Chapter 2: Filtering, Sorting & Aggregates

Once you can read a table, the next step is to shape the result: filter the right rows, combine conditions, and summarize data with aggregates. This chapter covers logical operators, pattern matching, grouping, and the string, date, and math functions interviewers expect you to know. These are the building blocks of almost every reporting query.

In this chapter:

  • →AND, OR, NOT and operator precedence with parentheses
  • →LIKE, IN, BETWEEN, and IS NULL filtering
  • →Aggregate functions and the difference between COUNT forms
  • →GROUP BY, HAVING, ROLLUP, and CUBE
  • →Finding duplicate rows
  • →String, date, rounding, and NULL-handling functions

    • Key learning: Filtering decides which rows are considered, grouping decides how rows are summarized, and HAVING filters the groups that result. Knowing when each clause runs and how NULL values flow through aggregates and functions prevents the most common beginner query errors.

    Q13. How do AND, OR, and NOT work in a WHERE clause, and what is operator precedence?

    Answer: AND requires every combined condition to be true. OR requires at least one combined condition to be true. NOT reverses a condition, so NOT (Salary > 50000) is true only when the salary is 50000 or less, or when the comparison is unknown due to NULL handling.

    When a WHERE clause mixes these operators, SQL Server applies them in a fixed order called precedence: NOT first, then AND, then OR. That means Department = 'Sales' OR Department = 'HR' AND Salary > 50000 is read as Sales, or HR with a high salary. Parentheses override precedence and make intent obvious, so use them whenever AND and OR appear together.

    SELECT EmployeeID, FirstName, LastName, Department, Salary
FROM Employees
WHERE (Department = 'Sales' OR Department = 'Marketing')
  AND Salary > 50000
  AND NOT Department = 'HR';

    Key learning: NOT runs first, then AND, then OR, so use parentheses to make the intended grouping explicit.

    Q14. How do LIKE patterns and wildcards work for text matching?

    Answer: LIKE tests whether a text value matches a pattern. The percent sign matches any sequence of zero or more characters, so 'Sm%' matches Smith, Small, and Sm. The underscore matches exactly one character, so 'Sm_th' matches Smith and Smyth but not Smth. Brackets match one character from a set or range, so '[ABC]%' matches names starting with A, B, or C, and '[^A]%' matches names that do not start with A.

    Use brackets or the ESCAPE clause to search for a literal percent sign or underscore. Keep in mind that a pattern starting with a percent sign usually cannot use an index seek efficiently, because SQL Server must scan values to find matches anywhere in the string. Whether LIKE is case sensitive depends on the collation of the column.

    SELECT CustomerID, CustomerName, City
FROM Customers
WHERE CustomerName LIKE 'Sm%';

SELECT ProductID, ProductName
FROM Products
WHERE ProductName LIKE '%[%]%';

    Key learning: LIKE matches text patterns where the percent sign matches any sequence of characters and the underscore matches exactly one character.

    Q15. How do IN, BETWEEN, and IS NULL work in a WHERE clause?

    Answer: IN tests whether a value appears in a list or in a subquery result. Department IN ('Sales', 'HR', 'IT') is shorthand for Department = 'Sales' OR Department = 'HR' OR Department = 'IT', and it is easier to read when the list is long. BETWEEN tests whether a value falls inside an inclusive range, so Salary BETWEEN 50000 AND 80000 means Salary >= 50000 AND Salary <= 80000, with both ends included.

    IS NULL tests whether a value is missing, and IS NOT NULL tests whether a value is present. Never test for NULL with = NULL, because that comparison returns unknown and filters the row out. For date and time ranges, prefer an explicit >= start AND < next day test over BETWEEN with an end-of-day value, because BETWEEN can miss or double-count times at the boundary.

    SELECT EmployeeID, FirstName, LastName, Department, Salary
FROM Employees
WHERE Department IN ('Sales', 'HR', 'IT')
  AND Salary BETWEEN 50000 AND 80000
  AND ManagerID IS NOT NULL;

    Key learning: IN tests membership in a list, BETWEEN tests an inclusive range, and IS NULL tests for a missing value.

    Q16. What do the aggregate functions COUNT, SUM, AVG, MIN, and MAX do?

    Answer: Aggregate functions summarize a set of rows into a single value. COUNT counts rows or values. SUM adds numeric values. AVG returns the mean of numeric values. MIN returns the smallest value and MAX returns the largest value, and both work for numbers, dates, and text.

    All of these functions except COUNT(*) ignore NULL values. That means AVG uses only rows with a value, and SUM skips NULL amounts rather than returning NULL. Watch out for AVG on whole numbers: AVG of INT values can lose the fractional part, so cast to DECIMAL first when you need an exact average. Without GROUP BY, the whole filtered set becomes one group and the query returns one row.

    SELECT COUNT(*) AS OrderCount,
       SUM(TotalAmount) AS TotalSales,
       AVG(TotalAmount) AS AverageOrder,
       MIN(OrderDate) AS FirstOrder,
       MAX(OrderDate) AS LastOrder
FROM Orders;

    Key learning: Aggregates summarize a set of rows into one value and ignore NULL values except for COUNT(*) which counts every row.

    Q17. What is the difference between COUNT(*), COUNT(column), and COUNT(DISTINCT column)?

    Answer: COUNT(*) counts every row in the group, including rows where every column is NULL. COUNT(column) counts only rows where that column is not NULL, so it can return a smaller number than COUNT(*) when the column has missing values. COUNT(DISTINCT column) counts distinct non-NULL values, so repeated values are counted once and NULL values are not counted at all.

    A common interview follow-up is COUNT(DISTINCT *) which is not valid syntax. DISTINCT must name a column or expression. Choose COUNT(*) when you want the row count, COUNT(column) when you want how many rows have a value, and COUNT(DISTINCT column) when you want how many different values exist.

    SELECT COUNT(*) AS AllEmployees,
       COUNT(Email) AS EmployeesWithEmail,
       COUNT(DISTINCT Department) AS DistinctDepartments
FROM Employees;

    Key learning: COUNT(*) counts all rows, COUNT(column) counts non-NULL values, and COUNT(DISTINCT column) counts distinct non-NULL values.

    Q18. What does GROUP BY do, and how does it group rows for aggregation?

    Answer: GROUP BY collects rows that share the same values in the grouping columns into one group, and the query returns one row per group. Aggregate functions in the SELECT list are then calculated separately for each group, so you can ask for a count or average per department instead of one total for the whole table.

    Every column in the SELECT list must either appear in GROUP BY or be inside an aggregate function. A bare column that varies inside a group has no single value to show, so SQL Server rejects it. GROUP BY does not guarantee sorted output, so add ORDER BY when the order of groups matters. You cannot use a SELECT column alias in GROUP BY in the same query, so repeat the expression or group by the underlying column.

    SELECT Department,
       COUNT(*) AS EmployeeCount,
       AVG(Salary) AS AverageSalary
FROM Employees
GROUP BY Department
ORDER BY Department;

    Key learning: GROUP BY produces one row per distinct grouping key with aggregates calculated separately for each group.

    Q19. What is the difference between HAVING and WHERE?

    Answer: WHERE filters individual rows before grouping happens. It cannot use aggregate functions, because aggregates are not calculated until rows are grouped. Use WHERE to exclude rows that should never be counted, such as orders before a start date.

    HAVING filters groups after grouping happens. It can use aggregate functions, so it answers questions such as which departments have an average salary above a threshold or which customers placed more than ten orders. You can use WHERE and HAVING in the same query: WHERE narrows the rows first, GROUP BY forms the groups, and HAVING keeps only the groups that pass its test.

    SELECT Department,
       AVG(Salary) AS AverageSalary
FROM Employees
WHERE HireDate >= '2020-01-01'
GROUP BY Department
HAVING AVG(Salary) > 60000;

    Key learning: WHERE filters individual rows before grouping and HAVING filters groups after grouping.

    Q20. How does GROUP BY work with multiple columns, and what are the basics of ROLLUP and CUBE?

    Answer: With multiple columns, GROUP BY treats the combination of values as the grouping key. GROUP BY Country, City produces one row per city within each country, so two cities with the same name in different countries stay separate. The order of the columns does not change which groups are formed, but it does matter for ROLLUP.

    ROLLUP adds subtotal rows in a hierarchy from left to right, plus a grand total row. ROLLUP (Country, City) returns rows per city, subtotals per country, and one grand total. CUBE adds subtotals for every combination of the grouping columns, so CUBE (Country, City) also returns subtotals per city across all countries. Subtotal rows show NULL in the rolled-up columns, and the GROUPING function returns 1 for those subtotal NULL values so you can tell them apart from real NULL data.

    SELECT Country, City, COUNT(*) AS CustomerCount
FROM Customers
GROUP BY Country, City;

SELECT Country, City, COUNT(*) AS CustomerCount,
       GROUPING(Country) AS IsCountryTotal,
       GROUPING(City) AS IsCityTotal
FROM Customers
GROUP BY ROLLUP (Country, City);

    Key learning: Multiple GROUP BY columns group by the combination of values, ROLLUP adds hierarchical subtotals, and CUBE adds subtotals for every combination.

    Q21. How do you find duplicate rows in a table?

    Answer: First decide which columns define a duplicate: two rows are duplicates only when every column in that set matches. The fastest way to find them is GROUP BY on those columns with HAVING COUNT(*) > 1, which returns each duplicated combination and how many times it appears. That tells you the scale of the problem before you delete anything.

    To remove the extras, use ROW_NUMBER() OVER (PARTITION BY the duplicate columns ORDER BY the column that decides which row to keep) in a CTE, then delete the rows numbered 2 and above. ORDER BY decides the survivor, for example the earliest created row or the latest updated row, so choose it deliberately and always check the count in a SELECT first. Never delete duplicates without a backup or a transaction you can roll back, and fix the cause afterwards, usually with a UNIQUE constraint or a unique index.

    -- Find the duplicated combinations and how many times each appears
SELECT CustomerID, Email, COUNT(*) AS DuplicateCount
FROM Customers
GROUP BY CustomerID, Email
HAVING COUNT(*) > 1;

-- Keep the earliest row per duplicate set, delete the rest
WITH RankedCustomers AS (
    SELECT CustomerID,
           ROW_NUMBER() OVER (
               PARTITION BY Email
               ORDER BY CreatedDate ASC
           ) AS RowNum
    FROM Customers
)
DELETE FROM RankedCustomers
WHERE RowNum > 1;

    Key learning: GROUP BY with HAVING COUNT(*) > 1 finds duplicates, and ROW_NUMBER() in a CTE deletes the extras while ORDER BY decides which row survives.

    Q22. What do the string functions CONCAT, SUBSTRING, LEFT, RIGHT, UPPER, LOWER, TRIM, and LEN do?

    Answer: CONCAT joins two or more strings into one value and treats NULL as an empty string, which is different from the + operator, where a NULL operand makes the whole result NULL. SUBSTRING returns part of a string starting at a 1-based position for a given length. LEFT returns the first N characters and RIGHT returns the last N characters.

    UPPER converts text to upper case and LOWER converts text to lower case. TRIM removes leading and trailing spaces, while LTRIM and RTRIM remove spaces from one side only. LEN returns the number of characters, excluding trailing spaces, so LEN('abc ') returns 3. Use DATALENGTH when you need the stored byte length including trailing spaces.

    SELECT EmployeeID,
       CONCAT(FirstName, ' ', LastName) AS FullName,
       SUBSTRING(FirstName, 1, 3) AS FirstThreeLetters,
       LEFT(LastName, 2) AS LastNameStart,
       RIGHT(LastName, 2) AS LastNameEnd,
       UPPER(Department) AS DepartmentUpper,
       LOWER(Department) AS DepartmentLower,
       TRIM(FirstName) AS TrimmedFirstName,
       LEN(FirstName) AS FirstNameLength
FROM Employees;

    Key learning: String functions build, slice, change case, trim, and measure text, with CONCAT treating NULL as an empty string.

    Q23. What do the date functions GETDATE, SYSDATETIME, DATEADD, DATEDIFF, DATENAME, DATEPART, and EOMONTH do?

    Answer: GETDATE returns the current date and time as DATETIME, based on the server clock. SYSDATETIME returns the current date and time as DATETIME2 with higher precision and is the preferred choice for new code. Both return local server time, not UTC, so use GETUTCDATE or SYSUTCDATETIME when UTC is required.

    DATEADD adds a number of date parts to a date, such as DATEADD(MONTH, 1, OrderDate) for one month later. DATEDIFF returns the number of date part boundaries crossed between two dates, so DATEDIFF(DAY, start, end) counts midnights crossed, not full 24-hour periods. DATENAME returns the name of a date part as text, such as January, while DATEPART returns the same part as a number, such as 1 for January. EOMONTH returns the last day of the month containing a date, with an optional month offset.

    SELECT OrderID,
       OrderDate,
       GETDATE() AS CurrentDateTime,
       SYSDATETIME() AS CurrentDateTimePrecise,
       DATEADD(MONTH, 1, OrderDate) AS OneMonthLater,
       DATEDIFF(DAY, OrderDate, GETDATE()) AS DaysSinceOrder,
       DATENAME(MONTH, OrderDate) AS OrderMonthName,
       DATEPART(YEAR, OrderDate) AS OrderYear,
       EOMONTH(OrderDate) AS MonthEnd
FROM Orders;

    Key learning: Date functions return the current time, add or compare date parts, extract date components, and find the last day of a month.

    Q24. What do ROUND, CEILING, FLOOR, and ABS do, and what is the difference between COALESCE and ISNULL?

    Answer: ROUND rounds a number to a given number of decimal places, so ROUND(10.555, 2) returns 10.56. A third argument with a non-zero value truncates instead of rounding. CEILING returns the smallest whole number greater than or equal to the value, so CEILING(10.2) returns 11. FLOOR returns the largest whole number less than or equal to the value, so FLOOR(10.8) returns 10. ABS returns the absolute value, so ABS(-15) returns 15.

    COALESCE and ISNULL both replace NULL with another value, but they differ in important ways. COALESCE takes any number of arguments and returns the first non-NULL value, and it is standard SQL. ISNULL takes exactly two arguments, is specific to T-SQL, and returns the data type of its first argument. COALESCE follows data type precedence across all its arguments, while ISNULL can truncate the replacement value to the type of the checked expression.

    SELECT ROUND(10.555, 2) AS RoundedValue,
       CEILING(10.2) AS CeilingValue,
       FLOOR(10.8) AS FloorValue,
       ABS(-15) AS AbsoluteValue;

SELECT EmployeeID,
       COALESCE(Phone, Email, 'No contact') AS PreferredContact,
       ISNULL(Phone, 'No phone') AS PhoneOrDefault
FROM Employees;

    Key learning: ROUND, CEILING, FLOOR, and ABS shape numeric values, while COALESCE returns the first non-NULL value from any number of arguments and ISNULL does the same for two arguments only.
