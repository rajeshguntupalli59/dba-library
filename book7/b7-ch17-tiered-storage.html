Chapter 17: Tiered Storage: Moving Cold Data Cheaply

Organizations that audit their cloud database storage seriously almost always find the same thing: 60–80% of the data sitting on expensive SSD-backed block storage has not been touched in months. That data costs the same per gigabyte as the hot rows your application reads thousands of times per second. Moving cold data to cheaper storage tiers—S3, Azure Blob, GCS, or archival-class object storage—routinely reduces total database storage costs by 40–70%, and on multi-terabyte databases that translates directly to $8,000–$50,000 per year in avoided spend. This chapter walks through how to identify cold data, classify it systematically, move it to the right storage tier, and automate the entire lifecycle so it keeps paying dividends without manual intervention every quarter.

17.1 Understanding the Storage Cost Stack

Before moving anything, you need to understand what you are paying for and why the pricing spread across tiers is so dramatic.

AWS RDS storage pricing (us-east-1, 2024):

| Storage Type | Cost per GB-month |

|---|---|

| gp2 SSD | $0.115 |

| gp3 SSD | $0.092 |

| io1 / io2 SSD | $0.125–$0.138 |

| S3 Standard | $0.023 |

| S3 Standard-IA | $0.0125 |

| S3 Glacier Instant | $0.004 |

| S3 Glacier Deep Archive | $0.00099 |

The math is straightforward. A 1 TB volume on gp2 costs $115.00/month. That same 1 TB on S3 Glacier Deep Archive costs $0.99/month. The gap is 116x. Even moving to S3 Standard-IA costs 10x less than gp2.

Azure SQL / Blob pricing (East US, 2024):

|---|---|

| Azure SQL Premium (P-series) | $0.114 |

| Azure SQL General Purpose | $0.115 |

| Azure Blob Hot | $0.018 |

| Azure Blob Cool | $0.01 |

| Azure Blob Archive | $0.00099 |

Google Cloud (us-central1, 2024):

| Storage Type | Cost per GB-month |

|---|---|

| Cloud SQL SSD | $0.17 |

| Cloud SQL HDD | $0.09 |

| GCS Standard | $0.020 |

| GCS Nearline | $0.010 |

| GCS Coldline | $0.004 |

| GCS Archive | $0.0012 |

The pricing structure across all three clouds tells the same story: object storage is an order of magnitude cheaper than block storage attached to your database instances. The technical challenge is not the pricing—it is designing the data movement pipeline so that cold data moves gracefully and retrieval remains possible when needed.

Worked example: 10 TB audit log table on AWS RDS (gp3)

17.2 Diagnosing Cold Data: Finding What You Can Archive

You cannot archive what you cannot identify. The first step is building a clear picture of data age, access patterns, and business rules for retention.

-- Find the date range of data in each table that has a created_at column
-- This query generates dynamic SQL for inspection (T-SQL string concatenation)
SELECT
    'SELECT ''' + s.name + '.' + t.name
    + ''' AS tbl, MIN(' + c.name + ') AS oldest_row, '
    + 'MAX(' + c.name + ') AS newest_row, '
    + 'COUNT(*) AS total_rows '
    + 'FROM ' + s.name + '.' + t.name + ';' AS inspection_sql
FROM sys.columns c
JOIN sys.tables t ON c.object_id = t.object_id
JOIN sys.schemas s ON t.schema_id = s.schema_id
WHERE c.name IN ('created_at', 'created_date', 'inserted_at', 'event_time', 'timestamp')
    AND s.name NOT IN ('sys', 'information_schema')
ORDER BY s.name, t.name;
-- For SQL Server / Azure SQL: find table age distribution
-- using sys.dm_db_index_usage_stats
SELECT
    OBJECT_NAME(i.object_id) AS table_name,
    i.name AS index_name,
    ius.user_seeks,
    ius.user_scans,
    ius.user_lookups,
    ius.user_updates,
    ius.last_user_seek,
    ius.last_user_scan,
    ius.last_user_lookup,
    -- Total read activity
    (ius.user_seeks + ius.user_scans + ius.user_lookups) AS total_reads,
    CASE
        WHEN ius.last_user_seek < GETDATE() - 90
          OR ius.last_user_seek IS NULL
        THEN 'Archive candidate'
        WHEN ius.last_user_seek < GETDATE() - 30
        THEN 'Monitor'
        ELSE 'Active'
    END AS recommendation
FROM
    sys.indexes i
    LEFT JOIN sys.dm_db_index_usage_stats ius
        ON i.object_id = ius.object_id
        AND i.index_id = ius.index_id
        AND ius.database_id = DB_ID()
WHERE
    OBJECTPROPERTY(i.object_id, 'IsUserTable') = 1
ORDER BY
    total_reads ASC,
    table_name;

Beyond table-level statistics, you need CloudWatch or Azure Monitor metrics to confirm that the storage IOPS consumption is actually coming from a small subset of tables. A table that shows up as large in the file-space diagnostics but consumes zero IOPS is a clean archival candidate. A large table with high IOPS is not—even if most rows are old.

17.3 Classifying and Partitioning Data for Tiered Movement

The most reliable pattern for tiered storage is range partitioning by time. Once you know which tables have archivable data, you restructure them so that cold partitions can be detached and exported cleanly without touching active data.

Creating a partitioned table in SQL Server for future tiering:

-- Convert an existing unpartitioned table to quarterly range partitioning
-- This example handles an audit_events table with 3 years of history

-- Step 1: Create the partition function (quarterly boundaries)
CREATE PARTITION FUNCTION pf_audit_quarterly (DATETIME2)
AS RANGE RIGHT FOR VALUES (
    '2022-01-01', '2022-04-01', '2022-07-01', '2022-10-01',
    '2023-01-01', '2023-04-01', '2023-07-01', '2023-10-01',
    '2024-01-01', '2024-04-01', '2024-07-01', '2024-10-01',
    '2025-01-01', '2025-04-01', '2025-07-01', '2025-10-01'
);

-- Step 2: Create the partition scheme
CREATE PARTITION SCHEME ps_audit_quarterly
AS PARTITION pf_audit_quarterly ALL TO ([PRIMARY]);

-- Step 3: Create the partitioned table
CREATE TABLE dbo.audit_events_partitioned (
    id          BIGINT IDENTITY(1,1),
    user_id     BIGINT       NOT NULL,
    event_type  VARCHAR(100) NOT NULL,
    event_data  NVARCHAR(MAX),
    ip_address  VARCHAR(45),
    created_at  DATETIME2    NOT NULL DEFAULT SYSDATETIME(),
    CONSTRAINT PK_audit_events PRIMARY KEY (id, created_at)
) ON ps_audit_quarterly (created_at);

-- Step 4: Migrate data from the old table, then rename
-- INSERT INTO dbo.audit_events_partitioned (...) SELECT ... FROM dbo.audit_events;

Once partitions exist, the archival workflow is clean: detach a partition, export it to S3/GCS/Blob as Parquet or CSV, verify the export, then drop the partition. The table keeps serving queries with no downtime.

flowchart LR
    A[Switch out partition] --> B["Export to S3/GCS/Blob
as Parquet/CSV"]
    B --> C[Verify checksum + row count]
    C -->|Verified| D[Drop partition from live DB]
    C -->|Failed| E[Keep partition — do not drop]
    D --> F[Record in archive metadata catalog]

*The detach → export → verify → drop pipeline: a partition is only dropped from the live database after its export is independently verified.*

17.4 Automated Tiering with S3 Lifecycle Policies and AWS Glue

Manual archival runs once. Automation runs forever. The goal is a pipeline that identifies cold partitions on a schedule, exports them, validates the export, and transitions the objects through S3 storage classes automatically as they age further.

S3 lifecycle policy to transition archived database exports through storage tiers:

#!/bin/bash
# Apply a lifecycle policy to the database archive bucket
# Transitions: Standard → Standard-IA (30d) → Glacier Instant (90d) → Deep Archive (365d)

BUCKET="your-archive-bucket"

cat > /tmp/lifecycle-policy.json << 'EOF'
{
  "Rules": [
    {
      "ID": "DatabaseArchiveTiering",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "database-archive/"
      },
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "STANDARD_IA"
        },
        {
          "Days": 90,
          "StorageClass": "GLACIER_IR"
        },
        {
          "Days": 365,
          "StorageClass": "DEEP_ARCHIVE"
        }
      ],
      "NoncurrentVersionTransitions": [
        {
          "NoncurrentDays": 7,
          "StorageClass": "STANDARD_IA"
        }
      ],
      "NoncurrentVersionExpiration": {
        "NoncurrentDays": 90
      }
    },
    {
      "ID": "DeleteExpiredArchives",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "database-archive/audit_events/"
      },
      "Expiration": {
        "Days": 2555
      }
    }
  ]
}
EOF

aws s3api put-bucket-lifecycle-configuration \
  --bucket $BUCKET \
  --lifecycle-configuration file:///tmp/lifecycle-policy.json

echo "Lifecycle policy applied to s3://$BUCKET"

# Verify the policy was applied
aws s3api get-bucket-lifecycle-configuration \
  --bucket $BUCKET \
  --output json | jq '.Rules[] | {ID: .ID, Status: .Status, Transitions: .Transitions}'

Python automation script for scheduled tiering — runs nightly via Lambda or cron:

#!/usr/bin/env python3
"""
db_tiering_scheduler.py

Runs nightly (scheduled via AWS EventBridge or cron).
Identifies SQL Server partitions older than the configured threshold,
exports them to S3 in Parquet format, validates row counts,
and switches the local partition out after confirmation.

Requirements:
  pip install pyodbc boto3 pandas pyarrow sqlalchemy
"""

import os
import sys
import json
import logging
import hashlib
from datetime import datetime, timedelta
from typing import Optional

import boto3
import pandas as pd
import pyodbc
import pyarrow as pa
import pyarrow.parquet as pq
from sqlalchemy import create_engine, text

# ── Configuration ────────────────────────────────────────────────────────────
DB_HOST          = os.environ.get("DB_HOST", "prod-sqlserver-01.xxxx.us-east-1.rds.amazonaws.com")
DB_PORT          = int(os.environ.get("DB_PORT", 1433))
DB_NAME          = os.environ.get("DB_NAME", "production")
DB_USER          = os.environ.get("DB_USER", "archive_user")
DB_PASSWORD      = os.environ.get("DB_PASSWORD")   # From AWS Secrets Manager in prod

ARCHIVE_BUCKET   = os.environ.get("ARCHIVE_BUCKET", "your-archive-bucket")
ARCHIVE_PREFIX   = os.environ.get("ARCHIVE_PREFIX", "database-archive")
AWS_REGION       = os.environ.get("AWS_REGION", "us-east-1")

# Archive partitions older than this many months
COLD_THRESHOLD_MONTHS = int(os.environ.get("COLD_THRESHOLD_MONTHS", 6))

# Tables to include in tiering (parent table name → timestamp column)
TIERING_CONFIG = {
    "audit_events_partitioned":      "created_at",
    "transaction_logs_partitioned":  "transaction_date",
    "clickstream_partitioned":       "event_time",
}

METADATA_TABLE = "archive_metadata"

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[logging.StreamHandler(sys.stdout)]
)
log = logging.getLogger(__name__)


# ── Database helpers ─────────────────────────────────────────────────────────

def get_connection():
    conn_str = (
        "DRIVER={ODBC Driver 18 for SQL Server};"
        f"SERVER={DB_HOST},{DB_PORT};DATABASE={DB_NAME};"
        f"UID={DB_USER};PWD={DB_PASSWORD};"
        "Encrypt=yes;TrustServerCertificate=yes;"
        "Connection Timeout=30;"
    )
    return pyodbc.connect(conn_str, autocommit=False)


def pf_name_for(conn, table_name: str) -> str:
    """Return the partition function name backing a partitioned table."""
    cur = conn.cursor()
    cur.execute("""
        SELECT pf.name
        FROM sys.tables t
        JOIN sys.indexes i ON i.object_id = t.object_id AND i.index_id IN (0, 1)
        JOIN sys.partition_schemes ps ON ps.data_space_id = i.data_space_id
        JOIN sys.partition_functions pf ON pf.function_id = ps.function_id
        WHERE t.name = ?
    """, table_name)
    row = cur.fetchone()
    cur.close()
    if not row:
        raise ValueError(f"Table {table_name} is not partitioned")
    return row[0]


def get_cold_partitions(conn, parent_table: str, threshold_months: int) -> list[dict]:
    """
    Return partitions whose boundary value is older than the cold threshold.
    Only returns partitions that have not been archived yet.
    """
    cutoff = datetime.utcnow() - timedelta(days=threshold_months * 30)

    query = """
        SELECT
            p.partition_number,
            CAST(rv.value AS DATETIME2) AS boundary_value,
            SUM(a.total_pages) * 8.0 / 1024 / 1024 AS size_gb
        FROM sys.tables t
        JOIN sys.indexes i        ON i.object_id = t.object_id AND i.index_id IN (0, 1)
        JOIN sys.partitions p     ON p.object_id = t.object_id AND p.index_id = i.index_id
        JOIN sys.allocation_units a ON a.container_id = p.partition_id
        JOIN sys.partition_schemes ps ON ps.data_space_id = i.data_space_id
        JOIN sys.partition_functions pf ON pf.function_id = ps.function_id
        LEFT JOIN sys.partition_range_values rv
               ON rv.function_id = pf.function_id
              AND rv.boundary_id = p.partition_number - 1
        WHERE t.name = ?
          AND p.partition_number > 1
          AND NOT EXISTS (
                SELECT 1 FROM dbo.archive_metadata am
                WHERE am.original_table = ?
                  AND am.partition_name = CAST(p.partition_number AS VARCHAR(10))
                  AND am.verified = 1
          )
        GROUP BY p.partition_number, rv.value
        ORDER BY p.partition_number ASC;
    """

    cur = conn.cursor()
    cur.execute(query, (parent_table, parent_table))
    cols = [c[0] for c in cur.description]
    candidates = [dict(zip(cols, row)) for row in cur.fetchall()]
    cur.close()

    # Filter by boundary value: partitions whose data ends before the cutoff
    cold = [part for part in candidates
            if part["boundary_value"] is not None
            and part["boundary_value"] < cutoff]
    for part in cold:
        part["partition_name"] = f"{parent_table}_p{part['partition_number']}"
        part["bytes"] = int(part["size_gb"] * 1024 ** 3)
        part["human_size"] = f"{part['size_gb']:.2f} GB"
    return cold


def export_partition_to_s3(
    conn,
    part: dict,
    parent_table: str,
    bucket: str,
    prefix: str,
    region: str
) -> tuple[str, int, str]:
    """
    Export partition to S3 as Parquet.
    Returns (s3_path, row_count, checksum).
    part carries partition_number, partition_name, plus pf_name/ts_column
    resolved by the caller from the tiering config.
    """
    partition_name = part["partition_name"]
    pf_name = part["pf_name"]
    ts_column = part["ts_column"]
    s3 = boto3.client("s3", region_name=region)

    log.info("Reading partition: %s (partition %d)", partition_name, part["partition_number"])
    cur = conn.cursor()
    # $PARTITION restricts the read to the single partition being archived
    cur.execute(
        f"SELECT * FROM {parent_table} WHERE $PARTITION.{pf_name}({ts_column}) = ?",
        part["partition_number"],
    )
    cols = [c[0] for c in cur.description]
    rows = cur.fetchall()
    cur.close()

    if not rows:
        log.warning("Partition %s is empty — skipping", partition_name)
        return None, 0, None

    row_count = len(rows)
    df = pd.DataFrame.from_records(rows, columns=cols)

    # Convert to Parquet in memory
    table = pa.Table.from_pandas(df, preserve_index=False)
    parquet_buffer = pa.BufferOutputStream()
    pq.write_table(
        table,
        parquet_buffer,
        compression="snappy",
        row_group_size=100_000
    )
    parquet_bytes = parquet_buffer.getvalue().to_pybytes()

    # Compute checksum for verification
    checksum = hashlib.sha256(parquet_bytes).hexdigest()

    # Build S3 path
    timestamp = datetime.utcnow().strftime("%Y%m%dT%H%M%SZ")
    s3_key = f"{prefix}/{parent_table}/{partition_name}/{partition_name}_{timestamp}.parquet"
    s3_path = f"s3://{bucket}/{s3_key}"

    log.info("Uploading %d rows (%d bytes) to %s", row_count, len(parquet_bytes), s3_path)
    s3.put_object(
        Bucket=bucket,
        Key=s3_key,
        Body=parquet_bytes,
        ContentType="application/octet-stream",
        Metadata={
            "partition_name": partition_name,
            "parent_table": parent_table,
            "row_count": str(row_count),
            "exported_at": timestamp,
            "sha256": checksum,
        }
    )

    return s3_path, row_count, checksum


def verify_export(bucket: str, s3_path: str, expected_rows: int, expected_checksum: str) -> bool:
    """
    Re-download the Parquet file from S3 and verify row count and checksum.
    """
    s3 = boto3.client("s3")
    # Parse bucket/key from s3:// URI
    path_without_prefix = s3_path[len("s3://"):]
    bucket_name, _, key = path_without_prefix.partition("/")

    log.info("Verifying export at %s", s3_path)
    response = s3.get_object(Bucket=bucket_name, Key=key)
    data = response["Body"].read()

    actual_checksum = hashlib.sha256(data).hexdigest()
    if actual_checksum != expected_checksum:
        log.error("Checksum mismatch! Expected %s, got %s", expected_checksum, actual_checksum)
        return False

    buffer = pa.BufferReader(data)
    parquet_table = pq.read_table(buffer)
    actual_rows = parquet_table.num_rows

    if actual_rows != expected_rows:
        log.error("Row count mismatch! Expected %d, got %d", expected_rows, actual_rows)
        return False

    log.info("Verification passed: %d rows, checksum OK", actual_rows)
    return True


def record_archival(conn, parent_table: str, partition_name: str,
                    s3_path: str, row_count: int, checksum: str, verified: bool):
    """
    Insert a record into the archive_metadata tracking table.
    """
    cur = conn.cursor()
    cur.execute("""
        MERGE dbo.archive_metadata AS target
        USING (SELECT ? AS original_table, ? AS partition_name) AS src
           ON target.partition_name = src.partition_name
        WHEN MATCHED THEN
            UPDATE SET archive_path = ?, row_count = ?, checksum = ?,
                       archived_at = SYSDATETIME(), verified = ?
        WHEN NOT MATCHED THEN
            INSERT (original_table, partition_name, archive_path, row_count,
                    checksum, archived_at, archived_by, verified)
            VALUES (?, ?, ?, ?, ?, SYSDATETIME(), SUSER_SNAME(), ?);
    """, (parent_table, partition_name,
          s3_path, row_count, checksum, verified,
          parent_table, partition_name, s3_path, row_count, checksum, verified))
    cur.close()
    conn.commit()


def detach_and_drop_partition(conn, parent_table: str, part: dict, pf_name: str):
    """
    Switch the cold partition out to a staging table, drop the staging
    table, then merge the partition boundary away.
    """
    partition_number = part["partition_number"]
    staging = f"{parent_table}_archive_stage"

    cur = conn.cursor()
    try:
        # Switch out is metadata-only: instant, no data movement
        log.info("Switching partition %d out of %s", partition_number, parent_table)
        cur.execute(
            f"ALTER TABLE dbo.{parent_table} SWITCH PARTITION ? TO dbo.{staging}"
            .replace("?", str(partition_number))
        )
        conn.commit()

        log.info("Dropping staging table %s", staging)
        cur.execute(f"DROP TABLE dbo.{staging}")
        conn.commit()

        # Merge the boundary so the partition function no longer has the hole
        boundary = part["boundary_value"]
        log.info("Merging partition boundary %s", boundary)
        cur.execute(
            f"ALTER PARTITION FUNCTION {pf_name}() MERGE RANGE (?)", boundary
        )
        conn.commit()
    finally:
        cur.close()


# ── Main pipeline ────────────────────────────────────────────────────────────

def run_tiering_pipeline():
    log.info("Starting tiering pipeline — threshold: %d months", COLD_THRESHOLD_MONTHS)
    conn = get_connection()

    total_bytes_freed = 0
    partitions_archived = 0
    errors = []

    for parent_table, ts_column in TIERING_CONFIG.items():
        log.info("Processing table: %s", parent_table)

        cold_partitions = get_cold_partitions(conn, parent_table, COLD_THRESHOLD_MONTHS)
        log.info("Found %d cold partitions for %s", len(cold_partitions), parent_table)
        pf_name = pf_name_for(conn, parent_table)

        for part in cold_partitions:
            part["pf_name"] = pf_name
            part["ts_column"] = ts_column
            partition_name = part["partition_name"]
            bytes_size     = part["bytes"]
            human_size     = part["human_size"]

            log.info("Archiving %s (%s)", partition_name, human_size)

            try:
                # Export
                s3_path, row_count, checksum = export_partition_to_s3(
                    conn, part, parent_table,
                    ARCHIVE_BUCKET, ARCHIVE_PREFIX, AWS_REGION
                )
                if s3_path is None:
                    log.warning("Skipping empty partition: %s", partition_name)
                    continue

                # Record as unverified
                record_archival(conn, parent_table, partition_name,
                                s3_path, row_count, checksum, verified=False)

                # Verify
                verified = verify_export(ARCHIVE_BUCKET, s3_path, row_count, checksum)

                if not verified:
                    log.error("Verification failed for %s — partition NOT dropped", partition_name)
                    errors.append(f"Verification failed: {partition_name}")
                    continue

                # Mark verified in metadata
                record_archival(conn, parent_table, partition_name,
                                s3_path, row_count, checksum, verified=True)

                # Switch out from RDS
                detach_and_drop_partition(conn, parent_table, part, pf_name)

                total_bytes_freed  += bytes_size
                partitions_archived += 1
                log.info("Successfully archived and dropped %s", partition_name)

            except Exception as exc:
                log.exception("Error processing partition %s: %s", partition_name, exc)
                errors.append(f"{partition_name}: {exc}")
                conn.rollback()

    conn.close()

    gb_freed = total_bytes_freed / (1024 ** 3)
    log.info("Pipeline complete. Partitions archived: %d | Space freed: %.2f GB | Errors: %d",
             partitions_archived, gb_freed, len(errors))

    if errors:
        log.error("Errors encountered:\n%s", "\n".join(errors))
        sys.exit(1)


if __name__ == "__main__":
    run_tiering_pipeline()

17.6 Azure SQL and Google Cloud SQL Tiering Patterns

AWS RDS has the most mature native tooling for partition-level export via aws_s3, but Azure SQL and Google Cloud SQL require slightly different approaches. Both can achieve equivalent outcomes with extra plumbing.

Azure SQL: exporting cold data with BACPAC and Blob Storage

For Azure SQL databases without partitioning, the most practical cold-data workflow combines Azure Data Factory (ADF) for orchestrated export with Azure Blob lifecycle management for automatic tier transitions.

#!/usr/bin/env python3
"""
azure_cold_export.py

Uses the Azure SQL Bulk Copy API (BCP) wrapper via pyodbc and Azure Blob SDK
to export cold table partitions to Azure Data Lake Storage Gen2 as Parquet.

Equivalent to the AWS aws_s3 export for Azure SQL environments.
"""

import os
import io
import logging
import pyodbc
import pandas as pd
import pyarrow as pa
import pyarrow.parquet as pq
from azure.identity import DefaultAzureCredential
from azure.storage.blob import BlobServiceClient, ContentSettings
from datetime import datetime

log = logging.getLogger(__name__)
logging.basicConfig(level=logging.INFO)

AZURE_SQL_CONN_STR = os.environ.get("AZURE_SQL_CONN_STR")
# e.g. "Driver={ODBC Driver 18 for SQL Server};Server=tcp:yourserver.database.windows.net,1433;
#        Database=production;Authentication=ActiveDirectoryMsi;"

STORAGE_ACCOUNT_URL = os.environ.get("STORAGE_ACCOUNT_URL",
                                      "https://yourstorageaccount.dfs.core.windows.net")
CONTAINER_NAME      = os.environ.get("CONTAINER_NAME", "database-archive")


def export_sql_server_table_to_adls(
    table_name: str,
    date_column: str,
    cutoff_year: int,
    cutoff_quarter: int
):
    """
    Export one quarter of data from an Azure SQL table to ADLS Gen2 Parquet.
    """
    credential   = DefaultAzureCredential()
    blob_service = BlobServiceClient(STORAGE_ACCOUNT_URL, credential=credential)
    container    = blob_service.get_container_client(CONTAINER_NAME)

    conn   = pyodbc.connect(AZURE_SQL_CONN_STR)
    cursor = conn.cursor()

    # Build date bounds for the quarter
    quarter_start_month = (cutoff_quarter - 1) * 3 + 1
    quarter_end_month   = quarter_start_month + 3
    if quarter_end_month > 12:
        end_year  = cutoff_year + 1
        end_month = 1
    else:
        end_year  = cutoff_year
        end_month = quarter_end_month

    start_date = f"{cutoff_year}-{quarter_start_month:02d}-01"
    end_date   = f"{end_year}-{end_month:02d}-01"

    query = f"""
        SELECT *
        FROM   {table_name} WITH (NOLOCK)
        WHERE  {date_column} >= '{start_date}'
          AND  {date_column} <  '{end_date}'
    """

    log.info("Fetching data: %s Q%d from %s", cutoff_year, cutoff_quarter, table_name)
    df = pd.read_sql(query, conn)
    conn.close()

    if df.empty:
        log.warning("No rows found for %s %d Q%d", table_name, cutoff_year, cutoff_quarter)
        return None, 0

    row_count = len(df)
    log.info("Fetched %d rows", row_count)

    # Write Parquet to buffer
    arrow_table = pa.Table.from_pandas(df, preserve_index=False)
    buffer      = io.BytesIO()
    pq.write_table(arrow_table, buffer, compression="snappy")
    buffer.seek(0)

    blob_path = (f"audit_events/{cutoff_year}/Q{cutoff_quarter}/"
                 f"{table_name}_{cutoff_year}_Q{cutoff_quarter}.parquet")

    log.info("Uploading to %s/%s", CONTAINER_NAME, blob_path)
    blob_client = container.get_blob_client(blob_path)
    blob_client.upload_blob(
        buffer,
        overwrite=True,
        content_settings=ContentSettings(content_type="application/octet-stream"),
        metadata={
            "table_name":   table_name,
            "year":         str(cutoff_year),
            "quarter":      str(cutoff_quarter),
            "row_count":    str(row_count),
            "exported_at":  datetime.utcnow().isoformat(),
        }
    )

    s3_equivalent_path = f"abfss://{CONTAINER_NAME}@{STORAGE_ACCOUNT_URL.split('//')[1]}/{blob_path}"
    log.info("Export complete: %s", s3_equivalent_path)
    return s3_equivalent_path, row_count


if __name__ == "__main__":
    export_sql_server_table_to_adls(
        table_name    = "audit_events",
        date_column   = "created_at",
        cutoff_year   = 2022,
        cutoff_quarter= 1
    )

#!/usr/bin/env python3
"""
Apply GCS lifecycle rules to the archive bucket.
Transitions: Standard → Nearline (30d) → Coldline (90d) → Archive (365d)

from google.cloud import storage

def apply_lifecycle_rules(bucket_name: str):

    bucket = client.get_bucket(bucket_name)

    rules = [
        storage.lifecycle.TransitionRule(
            storage.lifecycle.TransitionRule.NEARLINE,
            age=30,
            matches_prefix=["database-archive/"]
        ),
        storage.lifecycle.TransitionRule(
            storage.lifecycle.TransitionRule.COLDLINE,
            age=90,
            matches_prefix=["database-archive/"]
        ),
        storage.lifecycle.TransitionRule(
            storage.lifecycle.TransitionRule.ARCHIVE,
            age=365,
            matches_prefix=["database-archive/"]
        ),
        storage.lifecycle.DeleteRule(
            age=2555,
            matches_prefix=["database-archive/"]
        ),
    ]

    bucket.lifecycle_rules = rules
    bucket.patch()
    print(f"Lifecycle rules applied to gs://{bucket_name}")

17.7 Building a Metadata Catalog for Archived Data

Every byte moved to object storage must be tracked. Without a metadata catalog, archived data becomes inaccessible not because it cannot be queried, but because no one can find it. The metadata table introduced in Section 17.3 needs to evolve into a proper catalog that your application, compliance team, and operations staff can query.

Equivalent SQL Server / Azure SQL catalog schema:

-- Archive metadata catalog for SQL Server / Azure SQL environments

CREATE TABLE archive_metadata (
    id                   BIGINT IDENTITY(1,1) PRIMARY KEY,
    original_table       NVARCHAR(255) NOT NULL,
    partition_name       NVARCHAR(255) NOT NULL,
    archive_path         NVARCHAR(MAX) NOT NULL,
    storage_class        NVARCHAR(50)  NOT NULL DEFAULT 'Hot',
    row_count            BIGINT        NOT NULL,
    uncompressed_bytes   BIGINT        NULL,
    compressed_bytes     BIGINT        NULL,
    checksum             NVARCHAR(64)  NULL,
    date_range_start     DATETIME2     NULL,
    date_range_end       DATETIME2     NULL,
    schema_version       INT           NOT NULL DEFAULT 1,
    archived_at          DATETIME2     NOT NULL DEFAULT SYSUTCDATETIME(),
    archived_by          NVARCHAR(100) NULL,
    verified             BIT           NOT NULL DEFAULT 0,
    verified_at          DATETIME2     NULL,
    retrieval_count      INT           NOT NULL DEFAULT 0,
    last_retrieved_at    DATETIME2     NULL,
    retention_policy     NVARCHAR(50)  NOT NULL DEFAULT '7_years',
    delete_after         DATETIME2     NULL,
    notes                NVARCHAR(MAX) NULL,
    tags                 NVARCHAR(MAX) NULL     -- JSON string
);

CREATE UNIQUE INDEX UX_archive_metadata_partition
    ON archive_metadata (partition_name);

CREATE INDEX IX_archive_metadata_table
    ON archive_metadata (original_table);

CREATE INDEX IX_archive_metadata_dates
    ON archive_metadata (date_range_start, date_range_end);

-- Cost estimation view for Azure Blob tiers
CREATE VIEW archive_cost_estimate AS
SELECT
    original_table,
    storage_class,
    COUNT(*)                                              AS partition_count,
    SUM(row_count)                                        AS total_rows,
    CAST(SUM(compressed_bytes) / POWER(1024.0, 3) AS DECIMAL(18,2)) AS total_gb,
    CASE storage_class
        WHEN 'Hot'     THEN SUM(compressed_bytes) / POWER(1024.0, 3) * 0.018
        WHEN 'Cool'    THEN SUM(compressed_bytes) / POWER(1024.0, 3) * 0.01
        WHEN 'Archive' THEN SUM(compressed_bytes) / POWER(1024.0, 3) * 0.00099
        ELSE NULL
    END                                                   AS estimated_monthly_cost_usd
FROM
    archive_metadata
WHERE
    verified = 1
GROUP BY
    original_table, storage_class;
GO

Tracking retrieval events — closing the feedback loop:

When someone queries the archive through Athena, Synapse, or BigQuery, that access should be logged back to the metadata catalog. This matters for two reasons: it proves the archive is reachable when compliance auditors ask, and it identifies data that is accessed frequently enough that re-hydration to a warmer storage tier would save money on per-retrieval fees.

-- SQL Server equivalent
CREATE OR ALTER PROCEDURE dbo.log_archive_retrieval
    @partition_name  NVARCHAR(255),
    @query_engine    NVARCHAR(50),
    @rows_scanned    BIGINT,
    @bytes_scanned   BIGINT,
    @cost_usd        DECIMAL(10,6)
AS
BEGIN
    SET NOCOUNT ON;

    UPDATE archive_metadata
    SET
        retrieval_count   = retrieval_count + 1,
        last_retrieved_at = SYSUTCDATETIME()
    WHERE
        partition_name = @partition_name;

    INSERT INTO archive_retrieval_log (
        partition_name,
        query_engine,
        rows_scanned,
        bytes_scanned,
        cost_usd,
        retrieved_at,
        retrieved_by
    ) VALUES (
        @partition_name,
        @query_engine,
        @rows_scanned,
        @bytes_scanned,
        @cost_usd,
        SYSUTCDATETIME(),
        SYSTEM_USER
    );
END;
GO

17.8 Handling Schema Evolution in Long-Term Archives

A problem that almost every team hits six to twelve months after deploying an archival pipeline is schema drift. The live table gains a new column, the schema_version in the archive catalog should increment, and the Parquet files already written do not have that column. Without planning for this, you end up with heterogeneous archives that break Athena and BigQuery external tables.

The safest approach is a three-part policy:

1. Always write schema version metadata into both the Parquet file metadata and the archive catalog row. The Python export script in Section 17.4 stores schema_version in the archive_metadata table; make that version number come from a controlled schema registry, not from the live table at export time.

2. Use schema-on-read with explicit null handling when querying archives. Athena, BigQuery, and Synapse can all handle missing columns in older Parquet files if you declare the column as nullable and the query does not filter on it.

3. Run a backfill job when additive schema changes occur — not to rewrite old Parquet files, but to emit a companion schema manifest file in the same S3 prefix that describes the columns present in each file generation.

Schema version manifest file — written alongside each Parquet export:

def write_schema_manifest(
    s3_client,
    bucket: str,
    parquet_key: str,
    df: "pd.DataFrame",
    schema_version: int
):
    """
    Write a companion schema manifest JSON next to the Parquet file.
    The manifest records column names, types, and the schema version
    so future readers can handle missing columns gracefully.
    """
    import json

    manifest = {
        "schema_version": schema_version,
        "parquet_key":    parquet_key,
        "exported_at":    datetime.utcnow().isoformat(),
        "columns": [
            {"name": col, "dtype": str(df[col].dtype)}
            for col in df.columns
        ],
        "row_count":       len(df),
    }

    manifest_key = parquet_key.replace(".parquet", ".schema.json")
    s3_client.put_object(
        Bucket=bucket,
        Key=manifest_key,
        Body=json.dumps(manifest, indent=2).encode(),
        ContentType="application/json"
    )
    return manifest_key

Athena query that handles nullable columns from mixed schema versions:

-- Query that works across archive files written before and after

SELECT

    event_type,
    user_id,

FROM

    AND user_id = 12345

    created_at DESC;

17.9 Retrieval and Re-Hydration Workflows

Most archived data is queried in place through serverless engines and never needs to come back to the live database. But occasionally—regulatory reviews, data corrections, application features that need to resurface old records—you need to re-hydrate data into the live SQL Server instance. Doing this well means reading from S3/GCS/ADLS and writing back in bulk without overwhelming the primary instance.

For SQL Server re-hydration, the equivalent pattern uses BULK INSERT or the bcp utility pointed at a blob URL, which Azure SQL supports natively via the BULK INSERT ... FROM 'https://...' syntax available in Azure SQL Managed Instance and Azure Synapse dedicated pools.

-- Azure SQL Managed Instance: bulk insert from ADLS Gen2
BULK INSERT dbo.audit_events_rehydration_staging
FROM 'https://yourstorageaccount.blob.core.windows.net/database-archive/audit_events/2022/Q1/audit_events_2022_Q1.parquet'
WITH (
    DATA_SOURCE     = 'db_cold_archive',
    FORMAT          = 'PARQUET',
    TABLOCK
);

17.10 Calculating and Reporting Tiering ROI

FinOps is only as strong as its measurement layer. Every archival pipeline needs a reporting view that connects bytes moved to dollars saved, so that leadership can see the value and engineers can tune the thresholds.

SQL Server equivalent:

CREATE VIEW dbo.tiering_roi_report AS
WITH archive_costs AS (
    SELECT
        original_table,
        COUNT(*)                                                   AS partitions_archived,
        SUM(row_count)                                             AS total_rows_archived,
        SUM(compressed_bytes) / POWER(1024.0, 3)                  AS archive_gb,
        SUM(compressed_bytes) / POWER(1024.0, 3) * 0.004          AS archive_monthly_cost_usd,
        SUM(compressed_bytes) * 4.0 / POWER(1024.0, 3) * 0.092   AS rds_gp3_equivalent_cost_usd,
        MIN(date_range_start)                                      AS oldest_archived_date,
        MAX(date_range_end)                                        AS newest_archived_date,
        MIN(archived_at)                                           AS first_archived_at
    FROM
        archive_metadata
    WHERE
        verified = 1
    GROUP BY
        original_table
)
SELECT
    original_table,
    partitions_archived,
    total_rows_archived,
    ROUND(CAST(archive_gb AS DECIMAL(18,2)), 2)                    AS archive_gb,
    ROUND(CAST(archive_monthly_cost_usd AS DECIMAL(18,2)), 2)      AS archive_cost_per_month,
    ROUND(CAST(rds_gp3_equivalent_cost_usd AS DECIMAL(18,2)), 2)   AS avoided_rds_cost_per_month,
    ROUND(CAST(rds_gp3_equivalent_cost_usd
               - archive_monthly_cost_usd AS DECIMAL(18,2)), 2)    AS monthly_savings_usd,
    ROUND(CAST((rds_gp3_equivalent_cost_usd
               - archive_monthly_cost_usd) * 12.0 AS DECIMAL(18,2)), 2)
                                                                   AS annualized_savings_usd,
    ROUND(CAST(100.0 * (rds_gp3_equivalent_cost_usd
               - archive_monthly_cost_usd)
               / NULLIF(rds_gp3_equivalent_cost_usd, 0) AS DECIMAL(5,1)), 1)
                                                                   AS savings_pct,
    oldest_archived_date,
    newest_archived_date,
    first_archived_at
FROM
    archive_costs;
GO

Running this view monthly and feeding it into a Grafana dashboard or a Slack report gives your team a persistent, compounding record of the value the tiering pipeline has delivered. Teams that skip this step often find the pipeline deprioritized the moment an engineer who built it moves on—there is no visible evidence of what it is doing.

17.11 Common Pitfalls and How to Avoid Them

Even well-designed tiering pipelines fail in predictable ways. The following are the failure modes that appear most often in production environments.

Forgetting retrieval costs when choosing storage classes

S3 Glacier Deep Archive costs $0.00099/GB-month at rest, but retrieval costs $0.02/GB plus a minimum 12-hour restore time. If your compliance team retrieves a 500 GB partition twice a year, that is $10 in retrieval fees each time—still cheap, but not free. For data that is accessed even once per quarter, Glacier Instant at $0.004/GB delivers millisecond retrieval and no restore delay. Match the storage class to the realistic access frequency, not just the cheapest option at rest.

Archiving without verifying

The export step in Section 17.4 writes verified=false to the metadata table and only flips it after the checksum and row count are confirmed. Teams under time pressure skip the verification step. Six months later, when a regulator asks for a specific archive, the file exists but is corrupted or incomplete. Never drop a partition before setting verified=true.

Partitioning by month when your queries span quarters

If Athena or BigQuery scans all partitions to answer a query spanning multiple months, the savings from partition pruning disappear. Design partition boundaries to match the most common query patterns. For audit logs queried by quarter for compliance, quarterly partitions are better than monthly ones.

Lock contention during partition detach

The ALTER TABLE ... SWITCH PARTITION command in SQL Server is metadata-only and completes instantly, but it requires a schema-modification lock on the table. Run the switch during a low-traffic window as shown in the detach_and_drop_partition function in Section 17.4, and always verify the export before dropping the staging table — once the staging table is dropped, the data exists only in S3.

Schema drift breaking external tables

Covered in Section 17.8, but worth reiterating: every time you ALTER a live table, test that the corresponding Athena, Synapse, or BigQuery external table still resolves. Add this as a step in your database migration CI pipeline—a simple SELECT 1 FROM archive_table LIMIT 1 run in CI catches the problem before it reaches production.

Not accounting for minimum storage duration fees

S3 Standard-IA has a 30-day minimum storage duration. Glacier Instant has a 90-day minimum. Deep Archive has a 180-day minimum. If you archive a partition to Deep Archive and then need to delete it 60 days later (say, because a GDPR erasure request covers that partition), you still pay for the full 180 days. Design your retention and deletion policies to account for these minimums, and track the archived_at timestamp in the metadata catalog so your deletion job knows when the minimum period has elapsed.

Key Takeaways

  • → **The storage tier price gap is 50–100x between block storage and archival object storage**, making cold data archival one of the highest-ROI cost reduction actions available on any cloud database platform. Even partial migration of large historical tables produces meaningful annual savings.
  • → **Range partitioning by time is the foundation of every reliable tiering pipeline.** Without partitions, cold data cannot be detached and exported cleanly. Invest in partitioning before building any other part of the archival workflow, and use quarterly or monthly partition boundaries that align with your query patterns.
  • → **Verification before deletion is non-negotiable.** Every export must be validated by checksum and row count before the source partition is dropped. A metadata catalog with a `verified` boolean flag and a retrieval log gives your operations and compliance teams proof that the archive is intact and accessible.
  • → **Archived data must remain queryable.** Athena, Synapse Serverless SQL, and BigQuery external tables over Parquet files deliver serverless, on-demand access to archived data at a fraction of the cost of keeping it in the live database. Register archives in the Glue Data Catalog or equivalent immediately after export so the data is findable.
  • → **Automate the full lifecycle and measure it visibly.** A tiering pipeline that runs once delivers one-time savings. A pipeline scheduled via EventBridge, Cloud Scheduler, or cron—with lifecycle policies automatically transitioning objects through storage classes and an ROI reporting view feeding a dashboard—delivers compounding savings that grow as the database ages and accumulates more cold data.
