Chapter 23: Tagging Strategy for Database Cost Allocation

Organizations that implement a disciplined database tagging strategy typically recover 15–30% of their cloud database spend within the first quarter—not by rightsizing instances or switching storage classes, but simply by discovering who owns what, which workloads are generating the bills, and where untagged or mistagged resources have been silently accumulating charges for months. A 500-instance RDS estate with inconsistent tagging can hide $40,000–$80,000 per month in costs that no team claims ownership of, no budget is allocated for, and no engineer is motivated to optimize. This chapter builds a complete tagging strategy from schema design through enforcement automation, covering AWS RDS, Azure SQL, and Google Cloud SQL, with cost allocation queries, policy enforcement scripts, and a scheduled audit pipeline that keeps your tag compliance above 95%.

---

23.1 Designing a Tag Schema That Finance and Engineering Both Respect

The most common tagging failure is not technical—it is organizational. Engineers apply tags that make sense for operations (env=prod, db=sqlserver) while Finance needs tags that map to budget lines (cost-center=CC-4421, project=Q3-Migration). The two systems never reconcile, showback reports are disputed, and the entire exercise collapses into a spreadsheet maintained by one person who eventually leaves.

A workable schema serves both audiences with a small, mandatory set of tags and an extended set of optional enrichment tags.

Mandatory Tag Set (enforce via policy)

| Tag Key | Example Values | Owner | Purpose |

|---|---|---|---|

| env | prod, staging, dev, sandbox | Engineering | Environment classification |

| team | payments, analytics, platform | Engineering | Team ownership |

| cost-center | CC-4421, CC-0012 | Finance | Budget line alignment |

| project | checkout-v2, data-warehouse | PM / Engineering | Project-level chargeback |

| application | order-service, reporting-api | Engineering | Application owner |

| managed-by | terraform, cloudformation, manual | Platform | IaC drift detection |

Extended Tag Set (recommended, not enforced)

| Tag Key | Example Values | Purpose |

|---|---|---|

| data-classification | pii, financial, internal | Compliance tagging |

| backup-policy | daily-7d, weekly-30d | Backup tier identification |

| dr-tier | tier1, tier2, tier3 | Recovery priority |

| schedule | business-hours, always-on | Scheduling automation (Chapter 24) |

| rightsizing-exempt | true, false | Block automated rightsizing |

AWS RDS Tagging Limits

AWS RDS supports up to 50 tags per resource. Tag keys are case-sensitive: Environment and environment are two different tags. Establish a naming convention enforced by policy—lowercase, hyphenated, no spaces. A tag key collision between teams (Env vs env vs ENV) is one of the most common reasons cost allocation reports produce duplicates that Finance refuses to trust.

Azure SQL Tagging

Azure SQL resources (servers, databases, elastic pools) support up to 50 tags. Tags applied at the resource group level do not automatically inherit to individual database resources—a common misconception that leaves individual Azure SQL databases untagged even when the resource group appears compliant.

Google Cloud SQL Labeling

GCP uses "labels" rather than "tags." Labels support up to 64 key-value pairs. GCP labels flow automatically into the BigQuery billing export, making them the primary mechanism for cost allocation queries in the gcp_billing_export dataset.

23.2 Discovering What Is Untagged Right Now

Before building enforcement pipelines, you need a baseline. The following queries and scripts identify every database resource across all three clouds that is missing one or more mandatory tags.

AWS: Find Untagged or Partially Tagged RDS Instances

#!/bin/bash
# audit_rds_tags.sh
# Scans all RDS instances across all regions and reports tag compliance
# Schedule: daily via EventBridge + Lambda or cron on a bastion host
# Output: CSV suitable for ingestion into cost dashboards

MANDATORY_TAGS=("env" "team" "cost-center" "project" "application")
REGIONS=$(aws ec2 describe-regions --query "Regions[].RegionName" --output text)

echo "region,db_instance,instance_class,monthly_est_usd,missing_tags"

for REGION in $REGIONS; do
  INSTANCES=$(aws rds describe-db-instances \
    --region "$REGION" \
    --query "DBInstances[*].[DBInstanceIdentifier,DBInstanceClass,DBInstanceArn]" \
    --output text 2>/dev/null)

  while IFS=$'\t' read -r DB_ID DB_CLASS DB_ARN; do
    [ -z "$DB_ID" ] && continue

    # Fetch existing tags for this instance
    EXISTING_TAGS=$(aws rds list-tags-for-resource \
      --resource-name "$DB_ARN" \
      --region "$REGION" \
      --query "TagList[].Key" \
      --output text 2>/dev/null | tr '\t' '\n' | tr '[:upper:]' '[:lower:]')

    MISSING=""
    for TAG in "${MANDATORY_TAGS[@]}"; do
      if ! echo "$EXISTING_TAGS" | grep -qx "$TAG"; then
        MISSING="$MISSING $TAG"
      fi
    done

    MISSING=$(echo "$MISSING" | xargs)  # trim whitespace

    if [ -n "$MISSING" ]; then
      # Rough monthly cost estimate based on instance class
      # Replace with aws ce get-cost-and-usage for exact figures
      MONTHLY_EST="unknown"
      echo "$REGION,$DB_ID,$DB_CLASS,$MONTHLY_EST,\"$MISSING\""
    fi
  done <<< "$INSTANCES"
done

Run this script on a schedule and pipe the output to an S3 bucket. The CSV becomes the input for your weekly tag compliance report. A 200-instance estate typically surfaces 40–80 instances with missing mandatory tags on the first run.

Azure: Identify Untagged Azure SQL Resources

#!/bin/bash
# audit_azure_sql_tags.sh
# Requires: az cli authenticated with Reader role on target subscriptions

MANDATORY_TAGS=("env" "team" "cost-center" "project" "application")
SUBSCRIPTIONS=$(az account list --query "[].id" --output tsv)

echo "subscription,resource_group,server,database,missing_tags"

for SUB in $SUBSCRIPTIONS; do
  az account set --subscription "$SUB" 2>/dev/null

  # Scan SQL servers
  SERVERS=$(az sql server list \
    --query "[*].[name,resourceGroup]" \
    --output tsv 2>/dev/null)

  while IFS=$'\t' read -r SERVER RG; do
    [ -z "$SERVER" ] && continue

    # Get databases under this server
    DATABASES=$(az sql db list \
      --server "$SERVER" \
      --resource-group "$RG" \
      --query "[?name!='master'].[name]" \
      --output tsv 2>/dev/null)

    while IFS=$'\t' read -r DB_NAME; do
      [ -z "$DB_NAME" ] && continue

      DB_TAGS=$(az sql db show \
        --name "$DB_NAME" \
        --server "$SERVER" \
        --resource-group "$RG" \
        --query "tags" \
        --output json 2>/dev/null)

      MISSING=""
      for TAG in "${MANDATORY_TAGS[@]}"; do
        if ! echo "$DB_TAGS" | python3 -c \
          "import sys,json; t=json.load(sys.stdin) or {}; \
           exit(0 if '$TAG' in {k.lower() for k in t.keys()} else 1)" 2>/dev/null; then
          MISSING="$MISSING $TAG"
        fi
      done

      MISSING=$(echo "$MISSING" | xargs)
      if [ -n "$MISSING" ]; then
        echo "$SUB,$RG,$SERVER,$DB_NAME,\"$MISSING\""
      fi

    done <<< "$DATABASES"
  done <<< "$SERVERS"
done

GCP: Find Cloud SQL Instances Missing Labels

#!/bin/bash
# audit_cloudsql_labels.sh
# Requires: gcloud authenticated with cloudsql.viewer on all projects

MANDATORY_LABELS=("env" "team" "cost-center" "project" "application")
PROJECTS=$(gcloud projects list --format="value(projectId)" 2>/dev/null)

echo "project,instance,tier,missing_labels"

for PROJECT in $PROJECTS; do
  INSTANCES=$(gcloud sql instances list \
    --project="$PROJECT" \
    --format="value(name,settings.tier)" 2>/dev/null)

  while IFS=$'\t' read -r INSTANCE TIER; do
    [ -z "$INSTANCE" ] && continue

    LABELS=$(gcloud sql instances describe "$INSTANCE" \
      --project="$PROJECT" \
      --format="json(settings.userLabels)" 2>/dev/null \
      | python3 -c \
        "import sys,json; d=json.load(sys.stdin); \
         labels=d.get('settings',{}).get('userLabels',{}); \
         print(' '.join(labels.keys()))")

    MISSING=""
    for LABEL in "${MANDATORY_LABELS[@]}"; do
      if ! echo "$LABELS" | grep -qw "$LABEL"; then
        MISSING="$MISSING $LABEL"
      fi
    done

    MISSING=$(echo "$MISSING" | xargs)
    if [ -n "$MISSING" ]; then
      echo "$PROJECT,$INSTANCE,$TIER,\"$MISSING\""
    fi
  done <<< "$INSTANCES"
done

23.3 Cost Allocation Queries: Turning Tags Into Budget Intelligence

Once resources are tagged, the second problem surfaces: the tagging is there, but no one is actually querying it. Finance is still allocating costs manually. The following queries demonstrate how to extract per-team and per-project database costs directly from each cloud's billing data.

AWS Cost Explorer: Per-Team RDS Cost Breakdown

#!/usr/bin/env python3
"""
rds_cost_by_team.py
Queries AWS Cost Explorer for RDS costs grouped by the 'team' tag.
Outputs a CSV and optionally posts a Slack summary.

Schedule: Weekly via EventBridge + Lambda or cron.
Requirements: boto3, AWS credentials with ce:GetCostAndUsage permission.
"""

import boto3
import csv
import io
import json
import os
from datetime import datetime, timedelta
from collections import defaultdict

def get_rds_cost_by_tag(tag_key: str = "team",
                         days_back: int = 30) -> list[dict]:
    """
    Returns RDS costs grouped by a tag key for the last N days.
    Includes both instance hours and storage costs.
    """
    ce = boto3.client("cost-explorer", region_name="us-east-1")

    end_date = datetime.today().strftime("%Y-%m-%d")
    start_date = (datetime.today() - timedelta(days=days_back)).strftime("%Y-%m-%d")

    response = ce.get_cost_and_usage(
        TimePeriod={"Start": start_date, "End": end_date},
        Granularity="MONTHLY",
        Filter={
            "And": [
                {
                    "Dimensions": {
                        "Key": "SERVICE",
                        "Values": ["Amazon Relational Database Service"]
                    }
                },
                {
                    # Exclude credits and refunds
                    "Not": {
                        "Dimensions": {
                            "Key": "RECORD_TYPE",
                            "Values": ["Credit", "Refund"]
                        }
                    }
                }
            ]
        },
        GroupBy=[
            {"Type": "TAG", "Key": tag_key},
            {"Type": "DIMENSION", "Key": "USAGE_TYPE"}
        ],
        Metrics=["UnblendedCost", "UsageQuantity"]
    )

    results = []
    for period in response["ResultsByTime"]:
        month = period["TimePeriod"]["Start"][:7]
        for group in period["Groups"]:
            tag_value = group["Keys"][0].replace(f"{tag_key}$", "")
            usage_type = group["Keys"][1]

            cost = float(group["Metrics"]["UnblendedCost"]["Amount"])
            quantity = float(group["Metrics"]["UsageQuantity"]["Amount"])

            if cost > 0.01:
                results.append({
                    "month": month,
                    tag_key: tag_value if tag_value else "UNTAGGED",
                    "usage_type": usage_type,
                    "cost_usd": round(cost, 2),
                    "usage_quantity": round(quantity, 2),
                    "unit": group["Metrics"]["UsageQuantity"]["Unit"]
                })

    return results


def summarize_by_team(results: list[dict], tag_key: str = "team") -> dict:
    """Aggregates detailed usage rows into per-team totals."""
    totals = defaultdict(float)
    for row in results:
        totals[row[tag_key]] += row["cost_usd"]
    return dict(sorted(totals.items(), key=lambda x: x[1], reverse=True))


def export_csv(results: list[dict], output_path: str) -> None:
    if not results:
        print("No results to export.")
        return
    with open(output_path, "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=results[0].keys())
        writer.writeheader()
        writer.writerows(results)
    print(f"Exported {len(results)} rows to {output_path}")


def post_slack_summary(totals: dict, webhook_url: str, period_label: str) -> None:
    """Posts a cost summary to Slack. Set SLACK_WEBHOOK_URL env variable."""
    import urllib.request

    lines = [f"*RDS Cost by Team — {period_label}*\n"]
    grand_total = sum(totals.values())
    for team, cost in totals.items():
        pct = (cost / grand_total * 100) if grand_total > 0 else 0
        lines.append(f"• `{team}`: ${cost:,.2f} ({pct:.1f}%)")
    lines.append(f"\n*Total: ${grand_total:,.2f}*")

    payload = json.dumps({"text": "\n".join(lines)}).encode()
    req = urllib.request.Request(
        webhook_url,
        data=payload,
        headers={"Content-Type": "application/json"}
    )
    urllib.request.urlopen(req)
    print("Slack summary posted.")


if __name__ == "__main__":
    results = get_rds_cost_by_tag(tag_key="team", days_back=30)
    totals = summarize_by_team(results, tag_key="team")

    print("\nRDS Cost by Team (last 30 days):")
    print("-" * 45)
    grand_total = sum(totals.values())
    for team, cost in totals.items():
        pct = (cost / grand_total * 100) if grand_total > 0 else 0
        print(f"  {team:<25} ${cost:>10,.2f}  ({pct:.1f}%)")
    print("-" * 45)
    print(f"  {'TOTAL':<25} ${grand_total:>10,.2f}")

    export_csv(results, "/tmp/rds_cost_by_team.csv")

    webhook = os.environ.get("SLACK_WEBHOOK_URL")
    if webhook:
        post_slack_summary(totals, webhook, "Last 30 Days")

GCP BigQuery: Cloud SQL Cost by Label

-- gcp_cloudsql_cost_by_label.sql
-- Queries the GCP billing export table in BigQuery
-- Replace 'your_project.billing_dataset.gcp_billing_export_v1_XXXXXX'
-- with your actual billing export table name.
-- Run in BigQuery console or schedule via Cloud Scheduler + BigQuery Data Transfer.

WITH

-- Flatten labels into a key-value structure per line item
labelled_costs AS (
  SELECT
    invoice.month                                           AS billing_month,
    project.id                                              AS gcp_project,
    service.description                                     AS service,
    sku.description                                         AS sku,

    -- Extract specific labels; NULLIF handles missing labels gracefully
    MAX(IF(label.key = 'team',         label.value, NULL))  AS team,
    MAX(IF(label.key = 'env',          label.value, NULL))  AS env,
    MAX(IF(label.key = 'cost-center',  label.value, NULL))  AS cost_center,
    MAX(IF(label.key = 'project',      label.value, NULL))  AS app_project,
    MAX(IF(label.key = 'application',  label.value, NULL))  AS application,

    SUM(cost)                                               AS total_cost_usd,
    SUM(cost_at_list)                                       AS list_cost_usd,

    -- Savings from committed use discounts
    SUM(cost_at_list) - SUM(cost)                          AS discount_usd

  FROM `your_project.billing_dataset.gcp_billing_export_v1_XXXXXX`,
  UNNEST(labels) AS label

  WHERE
    service.description LIKE '%Cloud SQL%'
    AND DATE(_PARTITIONTIME) >= DATE_SUB(CURRENT_DATE(), INTERVAL 3 MONTH)

  GROUP BY
    billing_month,
    gcp_project,
    service,
    sku
),

-- Identify line items where mandatory labels are missing
compliance_check AS (
  SELECT
    billing_month,
    gcp_project,
    team,
    env,
    cost_center,
    app_project,
    application,
    total_cost_usd,
    discount_usd,

    -- Tag completeness score: 1 point per present mandatory label
    (CASE WHEN team        IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN env         IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN cost_center IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN app_project IS NOT NULL THEN 1 ELSE 0 END +
     CASE WHEN application IS NOT NULL THEN 1 ELSE 0 END
    )                                              AS label_score,

    -- 5 = fully labelled, <5 = partially or fully unlabelled
    CASE
      WHEN team IS NULL AND env IS NULL AND cost_center IS NULL
        THEN 'UNTAGGED'
      WHEN (CASE WHEN team        IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN env         IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN cost_center IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN app_project IS NOT NULL THEN 1 ELSE 0 END +
            CASE WHEN application IS NOT NULL THEN 1 ELSE 0 END) < 5
        THEN 'PARTIAL'
      ELSE 'COMPLIANT'
    END                                            AS label_status

  FROM labelled_costs
)

-- Final summary: cost by team and label compliance status
SELECT
  billing_month,
  COALESCE(team, 'UNTAGGED')          AS team,
  COALESCE(env, 'unknown')            AS env,
  label_status,
  COUNT(*)                            AS line_item_count,
  ROUND(SUM(total_cost_usd), 2)       AS total_cost_usd,
  ROUND(SUM(discount_usd), 2)         AS total_discount_usd,
  ROUND(AVG(label_score), 2)          AS avg_label_score

FROM compliance_check

GROUP BY
  billing_month,
  team,
  env,
  label_status

ORDER BY
  billing_month DESC,
  total_cost_usd DESC;

Schedule this query to run on the first of each month via Cloud Scheduler. Export results to a Looker Studio dashboard that Finance can access without needing BigQuery access themselves.

23.4 Enforcing Tags at Resource Creation: AWS, Azure, and GCP Policies

Auditing after the fact catches problems late. The more cost-effective approach is enforcement at creation time: block or warn when a database resource is created without the required tags. Each cloud provides a native policy mechanism.

AWS: Service Control Policy (SCP) to Block Untagged RDS Creation

SCPs operate at the AWS Organization level and cannot be overridden by individual account administrators. The following SCP blocks RDS instance creation and restoration unless all mandatory tags are present.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RequireMandatoryTagsOnRDSCreate",
      "Effect": "Deny",
      "Action": [
        "rds:CreateDBInstance",
        "rds:CreateDBCluster",
        "rds:RestoreDBInstanceFromDBSnapshot",
        "rds:RestoreDBClusterFromSnapshot",
        "rds:CreateDBInstanceReadReplica"
      ],
      "Resource": "*",
      "Condition": {
        "Null": {
          "aws:RequestTag/env":         "true",
          "aws:RequestTag/team":        "true",
          "aws:RequestTag/cost-center": "true",
          "aws:RequestTag/project":     "true"
        }
      }
    },
    {
      "Sid": "AllowTaggingOnCreate",
      "Effect": "Allow",
      "Action": "rds:AddTagsToResource",
      "Resource": "*"
    }
  ]
}

Apply this SCP to all non-root OUs. Leave the root OU unconditional to allow emergency break-glass actions. Communicate the rollout two weeks in advance—teams using CloudFormation or Terraform without tag blocks will see failed deployments.

AWS Config Rule: Detect Existing Noncompliant Resources

The SCP only catches new resources. For existing resources, use an AWS Config managed rule:

# Deploy the required-tags Config rule via CLI
# This checks all existing RDS instances for tag compliance on a schedule

aws configservice put-config-rule \
  --config-rule '{
    "ConfigRuleName": "rds-required-tags",
    "Description": "Checks that all RDS DB instances have the required mandatory tags",
    "Scope": {
      "ComplianceResourceTypes": [
        "AWS::RDS::DBInstance",
        "AWS::RDS::DBCluster"
      ]
    },
    "Source": {
      "Owner": "AWS",
      "SourceIdentifier": "REQUIRED_TAGS"
    },
    "InputParameters": "{\"tag1Key\":\"env\",\"tag2Key\":\"team\",\"tag3Key\":\"cost-center\",\"tag4Key\":\"project\",\"tag5Key\":\"application\"}"
  }'

Add an auto-remediation action using AWS Config Remediation + SSM Automation to notify the resource owner via SNS when a noncompliant resource is detected. A full block on existing resources creates operational disruption; notification-first remediation is more sustainable.

Azure: Policy Assignment to Require Tags on Azure SQL

Azure Policy can be assigned at the management group, subscription, or resource group level. The following ARM-format policy definition enforces the presence of mandatory tags on Azure SQL database resources.

{
  "properties": {
    "displayName": "Require mandatory tags on Azure SQL databases",
    "description": "Denies creation of Azure SQL databases without all mandatory FinOps tags.",
    "mode": "Indexed",
    "parameters": {
      "tagNames": {
        "type": "Array",
        "metadata": {
          "displayName": "Required Tag Names",
          "description": "List of tag keys that must be present on Azure SQL databases."
        },
        "defaultValue": ["env", "team", "cost-center", "project", "application"]
      }
    },
    "policyRule": {
      "if": {
        "allOf": [
          {
            "field": "type",
            "equals": "Microsoft.Sql/servers/databases"
          },
          {
            "count": {
              "value": "[parameters('tagNames')]",
              "name": "tagName",
              "where": {
                "field": "[concat('tags[', current('tagName'), ']')]",
                "exists": false
              }
            },
            "greater": 0
          }
        ]
      },
      "then": {
        "effect": "deny"
      }
    }
  }
}

Deploy this policy definition and then assign it to your management group:

# Save the policy to a file, then deploy via Azure CLI
az policy definition create \
  --name "require-sql-mandatory-tags" \
  --display-name "Require mandatory tags on Azure SQL databases" \
  --description "Denies Azure SQL database creation without mandatory FinOps tags" \
  --rules policy_rule.json \
  --mode Indexed

# Assign at the management group level
az policy assignment create \
  --name "enforce-sql-tags" \
  --policy "require-sql-mandatory-tags" \
  --scope "/providers/Microsoft.Management/managementGroups/YOUR_MG_ID" \
  --enforcement-mode Default

For brownfield environments where existing databases lack tags, set --enforcement-mode DoNotEnforce initially and switch to Default after a 30-day remediation window.

GCP: Organization Policy to Require Labels on Cloud SQL

GCP's Organization Policies operate differently from AWS SCPs and Azure Policy. The constraints/sql.restrictCloudSQLInstanceToConfiguredZone style constraints exist for specific behaviors, but label enforcement at the organization policy level requires a custom constraint (available in GCP Organization Policy Service v2).

# custom_constraint_cloudsql_labels.yaml
# Custom Organization Policy constraint requiring labels on Cloud SQL instances
# Requires: Organization Policy Service API enabled
# Deploy with: gcloud org-policies set-custom-constraint

name: organizations/YOUR_ORG_ID/customConstraints/custom.requireCloudSQLLabels
resourceTypes:
  - sqladmin.googleapis.com/Instance
methodTypes:
  - CREATE
  - UPDATE
condition: >
  resource.settings.userLabels.exists(k, k == "env") &&
  resource.settings.userLabels.exists(k, k == "team") &&
  resource.settings.userLabels.exists(k, k == "cost-center") &&
  resource.settings.userLabels.exists(k, k == "project") &&
  resource.settings.userLabels.exists(k, k == "application")
actionType: ALLOW
displayName: Require mandatory labels on Cloud SQL instances
description: >
  Cloud SQL instances must have all five mandatory FinOps labels
  (env, team, cost-center, project, application) before they can
  be created or updated.
# Deploy the custom constraint
gcloud org-policies set-custom-constraint custom_constraint_cloudsql_labels.yaml

# Create the policy that enforces the constraint at the org level
cat > enforce_cloudsql_labels_policy.yaml << 'EOF'
name: organizations/YOUR_ORG_ID/policies/custom.requireCloudSQLLabels
spec:
  rules:
    - enforce: true
EOF

gcloud org-policies set-policy enforce_cloudsql_labels_policy.yaml

23.5 Tagging Automation: Applying Tags Programmatically to Existing Resources

After the audit from 23.2 and policies from 23.4 are in place, you still have a backlog of untagged existing resources. Manually tagging hundreds of instances is error-prone and time-consuming. The following scripts automate bulk tagging based on existing metadata—instance name patterns, VPC placement, account structure, or a CSV input file.

AWS: Bulk Tag RDS Instances from a CSV Input

The input CSV format:

db_instance_identifier,region,env,team,cost-center,project,application
orders-prod-01,us-east-1,prod,payments,CC-4421,checkout-v2,order-service
analytics-rds,us-west-2,prod,analytics,CC-0012,data-warehouse,reporting-api
dev-scratch-db,eu-west-1,dev,platform,CC-0099,internal,scratch
#!/usr/bin/env python3
"""
bulk_tag_rds.py
Reads a CSV of RDS instances and applies tags to each one.
Performs a dry-run by default; pass --apply to execute changes.

Usage:
  python3 bulk_tag_rds.py --input tags.csv --dry-run
  python3 bulk_tag_rds.py --input tags.csv --apply
"""

import argparse
import boto3
import csv
import sys
from botocore.exceptions import ClientError

MANDATORY_KEYS = ["env", "team", "cost-center", "project", "application"]

def get_instance_arn(rds_client, db_instance_id: str) -> str | None:
    try:
        response = rds_client.describe_db_instances(
            DBInstanceIdentifier=db_instance_id
        )
        return response["DBInstances"][0]["DBInstanceArn"]
    except ClientError as e:
        if e.response["Error"]["Code"] == "DBInstanceNotFound":
            return None
        raise


def apply_tags(rds_client, arn: str, tags: dict, dry_run: bool) -> None:
    tag_list = [{"Key": k, "Value": v} for k, v in tags.items() if v]
    if dry_run:
        print(f"  [DRY RUN] Would apply tags to {arn}:")
        for tag in tag_list:
            print(f"    {tag['Key']} = {tag['Value']}")
    else:
        rds_client.add_tags_to_resource(
            ResourceName=arn,
            Tags=tag_list
        )
        print(f"  [APPLIED] Tags applied to {arn}")

23.6 Scheduled Tag Compliance Audit Pipeline

A one-time audit degrades quickly. Instances are created, cloned, and restored without tags every week. The audit must run on a schedule and produce a compliance score that is tracked over time. The following section builds a serverless audit pipeline on AWS (the pattern is replicable on Azure Functions and GCP Cloud Run).

Architecture Overview

The blue Schedule zone fires a weekly trigger into the orange Audit zone, where a Lambda function scans every RDS instance across all regions and computes per-instance tag scores. Results flow to the green Outputs zone: an S3 report in CSV and JSON, compliance history in DynamoDB, and a Slack alert when compliance drops below threshold. Run it weekly and tag drift never compounds silently.

EventBridge (weekly schedule)
    └─► Lambda: audit_tag_compliance
            ├─► Scans all RDS instances across all regions
            ├─► Calculates per-instance tag scores
            ├─► Writes compliance report → S3 (CSV + JSON)
            ├─► Updates DynamoDB compliance history table
            └─► Posts Slack alert if compliance < threshold

Lambda Function: Tag Compliance Auditor

#!/usr/bin/env python3
"""
lambda_tag_audit.py
AWS Lambda handler for weekly RDS tag compliance auditing.

Environment variables:
  MANDATORY_TAGS        Comma-separated list of required tag keys
  COMPLIANCE_THRESHOLD  Float 0–100; trigger alert if score drops below (default: 95)
  S3_BUCKET             S3 bucket name for report storage
  S3_PREFIX             S3 key prefix (default: 'tag-audit/')
  DYNAMODB_TABLE        DynamoDB table for compliance history (optional)
  SLACK_WEBHOOK_URL     Slack incoming webhook (optional)

IAM permissions required:
  rds:DescribeDBInstances (all regions)
  rds:ListTagsForResource
  s3:PutObject
  dynamodb:PutItem (if DYNAMODB_TABLE set)
"""

import boto3
import csv
import io
import json
import os
import urllib.request
from datetime import datetime, timezone
from collections import defaultdict
from botocore.exceptions import ClientError

MANDATORY_TAGS = [t.strip() for t in
                  os.environ.get("MANDATORY_TAGS",
                                 "env,team,cost-center,project,application").split(",")]
COMPLIANCE_THRESHOLD = float(os.environ.get("COMPLIANCE_THRESHOLD", "95"))
S3_BUCKET  = os.environ.get("S3_BUCKET", "")
S3_PREFIX  = os.environ.get("S3_PREFIX", "tag-audit/")
DDB_TABLE  = os.environ.get("DYNAMODB_TABLE", "")
SLACK_URL  = os.environ.get("SLACK_WEBHOOK_URL", "")


def get_all_regions() -> list[str]:
    ec2 = boto3.client("ec2", region_name="us-east-1")
    return [r["RegionName"] for r in ec2.describe_regions()["Regions"]]


def audit_region(region: str) -> list[dict]:
    rds = boto3.client("rds", region_name=region)
    records = []

    paginator = rds.get_paginator("describe_db_instances")
    for page in paginator.paginate():
        for inst in page["DBInstances"]:
            db_id  = inst["DBInstanceIdentifier"]
            db_arn = inst["DBInstanceArn"]
            db_cls = inst["DBInstanceClass"]
            engine = inst["Engine"]

            try:
                tag_response = rds.list_tags_for_resource(ResourceName=db_arn)
                existing_keys = {
                    t["Key"].lower() for t in tag_response["TagList"]
                }
            except ClientError:
                existing_keys = set()

            present  = [t for t in MANDATORY_TAGS if t in existing_keys]
            missing  = [t for t in MANDATORY_TAGS if t not in existing_keys]
            score    = len(present) / len(MANDATORY_TAGS) * 100

            records.append({
                "region":         region,
                "db_instance_id": db_id,
                "db_class":       db_cls,
                "engine":         engine,
                "tags_present":   ",".join(present),
                "tags_missing":   ",".join(missing),
                "tag_score":      round(score, 1),
                "status":         "COMPLIANT" if score == 100 else "NONCOMPLIANT"
            })
    return records


def calculate_summary(records: list[dict]) -> dict:
    total     = len(records)
    compliant = sum(1 for r in records if r["status"] == "COMPLIANT")
    score     = (compliant / total * 100) if total > 0 else 0

    by_region = defaultdict(lambda: {"total": 0, "compliant": 0})
    for r in records:
        by_region[r["region"]]["total"]     += 1
        by_region[r["region"]]["compliant"] += (1 if r["status"] == "COMPLIANT" else 0)

    missing_counts = defaultdict(int)
    for r in records:
        for tag in r["tags_missing"].split(","):
            if tag:
                missing_counts[tag] += 1

    return {
        "total_instances":      total,
        "compliant_instances":  compliant,
        "noncompliant_instances": total - compliant,
        "compliance_score_pct": round(score, 2),
        "by_region":            dict(by_region),
        "missing_tag_frequency": dict(sorted(
            missing_counts.items(), key=lambda x: x[1], reverse=True
        ))
    }


def write_to_s3(records: list[dict], summary: dict, run_ts: str) -> str:
    s3 = boto3.client("s3")
    date_prefix = run_ts[:10]  # YYYY-MM-DD

    # Write CSV
    csv_key = f"{S3_PREFIX}{date_prefix}/compliance_report.csv"
    buf = io.StringIO()
    if records:
        writer = csv.DictWriter(buf, fieldnames=records[0].keys())
        writer.writeheader()
        writer.writerows(records)
    s3.put_object(Bucket=S3_BUCKET, Key=csv_key,
                  Body=buf.getvalue().encode(),
                  ContentType="text/csv")

    # Write JSON summary
    json_key = f"{S3_PREFIX}{date_prefix}/summary.json"
    s3.put_object(Bucket=S3_BUCKET, Key=json_key,
                  Body=json.dumps(summary, indent=2).encode(),
                  ContentType="application/json")

    print(f"Reports written to s3://{S3_BUCKET}/{S3_PREFIX}{date_prefix}/")
    return f"s3://{S3_BUCKET}/{S3_PREFIX}{date_prefix}/"


def write_to_dynamodb(summary: dict, run_ts: str) -> None:
    if not DDB_TABLE:
        return
    ddb = boto3.resource("dynamodb")
    table = ddb.Table(DDB_TABLE)
    table.put_item(Item={
        "run_date":              run_ts[:10],
        "run_timestamp":         run_ts,
        "compliance_score_pct":  str(summary["compliance_score_pct"]),
        "total_instances":       summary["total_instances"],
        "compliant_instances":   summary["compliant_instances"],
        "noncompliant_instances":summary["noncompliant_instances"]
    })


def post_slack_alert(summary: dict, s3_path: str) -> None:
    if not SLACK_URL:
        return
    score = summary["compliance_score_pct"]
    status_emoji = "✅" if score >= COMPLIANCE_THRESHOLD else "🚨"
    top_missing = list(summary["missing_tag_frequency"].items())[:3]
    missing_str = ", ".join(f"`{k}` ({v})" for k, v in top_missing)

    text = (
        f"{status_emoji} *RDS Tag Compliance Report*\n"
        f"Compliance Score: *{score}%* "
        f"(threshold: {COMPLIANCE_THRESHOLD}%)\n"
        f"Instances: {summary['total_instances']} total, "
        f"{summary['noncompliant_instances']} noncompliant\n"
        f"Most missing tags: {missing_str}\n"
        f"Full report: `{s3_path}`"
    )

    payload = json.dumps({"text": text}).encode()
    req = urllib.request.Request(
        SLACK_URL, data=payload,
        headers={"Content-Type": "application/json"}
    )
    urllib.request.urlopen(req)


def lambda_handler(event, context):
    run_ts = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
    print(f"Tag compliance audit started at {run_ts}")

    all_records = []
    regions = get_all_regions()
    print(f"Auditing {len(regions)} regions...")

    for region in regions:
        try:
            region_records = audit_region(region)
            all_records.extend(region_records)
            print(f"  {region}: {len(region_records)} instances")
        except Exception as e:
            print(f"  [WARN] Could not audit {region}: {e}")

    summary  = calculate_summary(all_records)
    s3_path  = write_to_s3(all_records, summary, run_ts) if S3_BUCKET else "N/A"
    write_to_dynamodb(summary, run_ts)
    post_slack_alert(summary, s3_path)

    print(f"\nCompliance score: {summary['compliance_score_pct']}%")
    print(f"Noncompliant: {summary['noncompliant_instances']} instances")

    return {
        "statusCode": 200,
        "body": json.dumps(summary)
    }

23.7 Multi-Cloud Tag Normalization: When Teams Span AWS, Azure, and GCP

Organizations with workloads on multiple clouds frequently end up with fragmented tagging strategies: the AWS team uses cost-center, the Azure team uses CostCenter, and the GCP team uses cost_center. The billing export from each cloud goes to a central data warehouse, and none of the keys join cleanly.

Normalization must happen at the data warehouse layer—you cannot force tag key consistency retroactively across clouds without re-running tagging automation against every resource. The following SQL pattern implements a normalization view in your central analytics warehouse (syntax shown for BigQuery; adapt LOWER and REGEXP_REPLACE for Snowflake or Redshift as needed).

BigQuery: Unified Cross-Cloud Database Cost View

-- unified_db_cost_view.sql
-- Creates a unified view of database costs across AWS RDS, Azure SQL, and GCP Cloud SQL
-- by normalizing tag/label keys to a canonical schema.
-- Store as a BigQuery view: your_project.finops_dataset.v_unified_db_costs

CREATE OR REPLACE VIEW `your_project.finops_dataset.v_unified_db_costs` AS

WITH

-- ── AWS RDS costs from CUR (Cost and Usage Report) exported to S3 → BigQuery ──
aws_rds AS (
  SELECT
    FORMAT_DATE('%Y-%m', DATE(line_item_usage_start_date))  AS billing_month,
    'AWS'                                                    AS cloud,
    'RDS'                                                    AS db_service,
    line_item_resource_id                                    AS resource_id,
    line_item_usage_type                                     AS sku,

    -- Normalize tag keys: CUR tags use resource_tags_ prefix
    LOWER(COALESCE(
      resource_tags_user_team,
      resource_tags_user_Team,
      resource_tags_user_TEAM
    ))                                                        AS team,

    LOWER(COALESCE(
      resource_tags_user_env,
      resource_tags_user_Env,
      resource_tags_user_environment
    ))                                                        AS env,

    LOWER(COALESCE(
      resource_tags_user_cost_center,
      `resource_tags_user_cost-center`
    ))                                                        AS cost_center,

    LOWER(COALESCE(
      resource_tags_user_project,
      resource_tags_user_Project
    ))                                                        AS project,

    LOWER(COALESCE(
      resource_tags_user_application,
      resource_tags_user_Application
    ))                                                        AS application,

    SUM(line_item_unblended_cost)                            AS cost_usd

  FROM `your_project.aws_cur_dataset.aws_cur_*`
  WHERE
    line_item_product_code = 'AmazonRDS'
    AND line_item_line_item_type NOT IN ('Credit', 'Refund', 'Tax')
  GROUP BY
    billing_month, cloud, db_service, resource_id, sku,
    team, env, cost_center, project, application
),-- ── Azure SQL costs from Azure Cost Export exported to Blob → BigQuery ──
azure_sql AS (
  SELECT
    FORMAT_DATE('%Y-%m', DATE(UsageDateTime))                AS billing_month,
    'Azure'                                                   AS cloud,
    'Azure SQL'                                               AS db_service,
    InstanceId                                                AS resource_id,
    MeterName                                                 AS sku,

    -- Azure tag keys are stored as JSON strings; normalize with LOWER
    LOWER(COALESCE(
      JSON_VALUE(Tags, '$.team'),
      JSON_VALUE(Tags, '$.Team'),
      JSON_VALUE(Tags, '$.TEAM')
    ))                                                        AS team,

    LOWER(COALESCE(
      JSON_VALUE(Tags, '$.env'),
      JSON_VALUE(Tags, '$.Env'),
      JSON_VALUE(Tags, '$.environment'),
      JSON_VALUE(Tags, '$.Environment')
    ))                                                        AS env,

    LOWER(COALESCE(
      JSON_VALUE(Tags, '$.cost-center'),
      JSON_VALUE(Tags, '$.CostCenter'),
      JSON_VALUE(Tags, '$.costcenter'),
      JSON_VALUE(Tags, '$.cost_center')
    ))                                                        AS cost_center,

    LOWER(COALESCE(
      JSON_VALUE(Tags, '$.project'),
      JSON_VALUE(Tags, '$.Project')
    ))                                                        AS project,

    LOWER(COALESCE(
      JSON_VALUE(Tags, '$.application'),
      JSON_VALUE(Tags, '$.Application')
    ))                                                        AS application,

    SUM(PreTaxCost)                                           AS cost_usd

  FROM `your_project.azure_billing_dataset.azure_cost_export_*`
  WHERE
    -- Filter to SQL-family services
    (MeterCategory IN ('SQL Database', 'SQL Managed Instance',
                       'Azure SQL Database', 'SQL Server on Azure VM')
     OR ServiceName LIKE '%SQL%')
    AND ChargeType NOT IN ('Refund', 'Credit')
  GROUP BY
    billing_month, cloud, db_service, resource_id, sku,
    team, env, cost_center, project, application
),

-- ── GCP Cloud SQL costs from GCP Billing Export in BigQuery ──
gcp_cloudsql AS (
  SELECT
    invoice.month                                             AS billing_month,
    'GCP'                                                     AS cloud,
    'Cloud SQL'                                               AS db_service,
    -- GCP resource name is in the resource labels or the resource.name field
    resource.name                                             AS resource_id,
    sku.description                                           AS sku,

    -- GCP labels are already lowercase by convention; COALESCE handles missing ones
    MAX(IF(label.key = 'team',         label.value, NULL))   AS team,
    MAX(IF(label.key = 'env',          label.value, NULL))   AS env,
    MAX(IF(label.key = 'cost-center',  label.value, NULL))   AS cost_center,
    MAX(IF(label.key = 'project',      label.value, NULL))   AS project,
    MAX(IF(label.key = 'application',  label.value, NULL))   AS application,

    SUM(cost)                                                 AS cost_usd

  FROM `your_project.billing_dataset.gcp_billing_export_v1_XXXXXX`,
  UNNEST(labels) AS label

  WHERE
    service.description LIKE '%Cloud SQL%'
    AND cost_type NOT IN ('rounding_error')
  GROUP BY
    billing_month, cloud, db_service, resource_id, sku
),

-- ── Union all three sources ──
combined AS (
  SELECT * FROM aws_rds
  UNION ALL
  SELECT * FROM azure_sql
  UNION ALL
  SELECT * FROM gcp_cloudsql
)

-- ── Final output with normalization flag ──
SELECT
  billing_month,
  cloud,
  db_service,
  resource_id,
  sku,

  COALESCE(team,        'UNTAGGED')   AS team,
  COALESCE(env,         'unknown')    AS env,
  COALESCE(cost_center, 'UNTAGGED')   AS cost_center,
  COALESCE(project,     'UNTAGGED')   AS project,
  COALESCE(application, 'UNTAGGED')   AS application,

  -- Tag completeness score
  (CASE WHEN team        IS NOT NULL THEN 1 ELSE 0 END +
   CASE WHEN env         IS NOT NULL THEN 1 ELSE 0 END +
   CASE WHEN cost_center IS NOT NULL THEN 1 ELSE 0 END +
   CASE WHEN project     IS NOT NULL THEN 1 ELSE 0 END +
   CASE WHEN application IS NOT NULL THEN 1 ELSE 0 END
  )                                   AS tag_score,

  ROUND(SUM(cost_usd), 2)             AS cost_usd

FROM combined

GROUP BY
  billing_month,
  cloud,
  db_service,
  resource_id,
  sku,
  team,
  env,
  cost_center,
  project,
  application,
  tag_score

ORDER BY
  billing_month DESC,
  cost_usd DESC;

Once this view exists, Finance can query it from any BI tool—Looker, Tableau, Power BI, or Looker Studio—without understanding the differences between CUR column naming conventions and GCP billing export label schema. A single WHERE team = 'payments' filter returns every database dollar spent by that team across all three clouds in a given month.

23.8 Integrating Tag Compliance into IaC Pipelines

The most durable place to enforce tagging is the deployment pipeline. An instance that cannot pass a terraform plan validation step or a CloudFormation stack policy check without the correct tags never reaches production in a noncompliant state. The approaches in this section work in concert with the cloud-native policies from section 23.4—defense in depth rather than relying on a single enforcement layer.

Terraform: Variable Validation for Mandatory Tags

# modules/rds/variables.tf
# Shared Terraform module for RDS instances.
# All mandatory tags must be provided by the calling module.
# This prevents the plan from succeeding without complete tags.

variable "mandatory_tags" {
  description = "Mandatory FinOps tags required on all RDS resources."
  type = object({
    env          = string
    team         = string
    cost_center  = string
    project      = string
    application  = string
  })

  validation {
    condition     = contains(["prod", "staging", "dev", "sandbox"], var.mandatory_tags.env)
    error_message = "env must be one of: prod, staging, dev, sandbox."
  }

  validation {
    condition     = length(var.mandatory_tags.team) >= 2
    error_message = "team must be at least 2 characters."
  }

  validation {
    condition     = can(regex("^CC-[0-9]{4}$", var.mandatory_tags.cost_center))
    error_message = "cost_center must match format CC-XXXX (e.g., CC-4421)."
  }

  validation {
    condition     = length(var.mandatory_tags.project) >= 3
    error_message = "project must be at least 3 characters."
  }

  validation {
    condition     = length(var.mandatory_tags.application) >= 3
    error_message = "application must be at least 3 characters."
  }
}

variable "optional_tags" {
  description = "Optional enrichment tags. Merged with mandatory_tags at resource creation."
  type        = map(string)
  default     = {}
}

# Compose the full tag map used on every resource in this module
locals {
  all_tags = merge(
    {
      env         = var.mandatory_tags.env
      team        = var.mandatory_tags.team
      "cost-center" = var.mandatory_tags.cost_center   # normalize hyphen form
      project     = var.mandatory_tags.project
      application = var.mandatory_tags.application
      managed-by  = "terraform"
    },
    var.optional_tags
  )
}
# modules/rds/main.tf
# Example RDS instance resource using the validated tag block

resource "aws_db_instance" "this" {
  identifier        = var.db_identifier
  engine            = var.engine
  engine_version    = var.engine_version
  instance_class    = var.instance_class
  allocated_storage = var.allocated_storage
  db_name           = var.db_name
  username          = var.master_username
  password          = var.master_password

  # ... other required parameters ...

  tags = local.all_tags
}

resource "aws_db_subnet_group" "this" {
  name       = "${var.db_identifier}-subnet-group"
  subnet_ids = var.subnet_ids
  tags       = local.all_tags
}

A calling module that omits cost_center or provides an invalid value fails at terraform validate before any AWS API calls are made. This is the cheapest enforcement point.

Conftest / OPA Policy for Terraform Plan Output

For organizations using Open Policy Agent in their CI pipeline, the following Rego policy evaluates the Terraform plan JSON and fails the build if any aws_db_instance resource is missing mandatory tags.

# policies/rds_mandatory_tags.rego
# Evaluates terraform plan output (JSON) and enforces mandatory tag presence
# on all aws_db_instance and aws_db_cluster resources.
#
# Usage in CI (after terraform plan -out=plan.tfplan && terraform show -json plan.tfplan > plan.json):
#   conftest test plan.json --policy policies/

package rds_mandatory_tags

import future.keywords.in

mandatory_tags := {
  "env",
  "team",
  "cost-center",
  "project",
  "application",
}

rds_resource_types := {
  "aws_db_instance",
  "aws_db_cluster",
  "aws_rds_cluster",
}

# Collect all RDS resources being created or updated in the plan
rds_resources[name] := config {
  resource := input.resource_changes[_]
  resource.type in rds_resource_types
  resource.change.actions[_] in {"create", "update"}
  config := resource.change.after
  name := resource.address
}

# For each RDS resource, find which mandatory tags are missing
missing_tags[resource_addr] := absent {
  config := rds_resources[resource_addr]
  applied_tags := {lower(k) | config.tags[k]}
  absent := mandatory_tags - applied_tags
  count(absent) > 0
}

# Deny rule: fail if any resource has missing mandatory tags
deny[msg] {
  resource_addr := missing_tags[_]
  absent := missing_tags[resource_addr]
  msg := sprintf(
    "Resource %v is missing mandatory tags: %v",
    [resource_addr, concat(", ", absent)]
  )
}

Add this to your CI pipeline after the Terraform plan step:

# .github/workflows/terraform_tag_check.yml (excerpt)
- name: Convert Terraform plan to JSON
  run: terraform show -json tfplan > plan.json

- name: Run OPA tag compliance check
  uses: open-policy-agent/conftest-action@v3
  with:
    files: plan.json
    policy: policies/

A failed OPA check blocks the pull request merge. Engineers see the exact tag they missed and the exact resource address that violated the policy, which is far more actionable than a cryptic AWS AccessDenied error from the SCP.

23.9 Chargeback and Showback Workflows

Tagging alone does not produce chargeback. Chargeback requires a workflow: the tagged cost data flows to a report, the report is distributed to team leads or finance BPs, and there is an agreed mechanism for attributing those costs to a budget. The following describes a minimal chargeback workflow suitable for a 10–50 team organization.

Showback vs. Chargeback

*Showback* means: "Here is what your team consumed; no money actually moves." Showback is politically safe and builds team awareness of their database costs. Start here.

*Chargeback* means: "Here is what your team consumed; your budget is debited by this amount." Chargeback requires buy-in from finance leadership, a mapping from cloud cost centers to internal GL codes, and a process for handling disputes. It motivates optimization far more strongly than showback but requires more governance infrastructure.

Monthly Chargeback Report Generator

The following Python script generates per-team chargeback reports from the AWS Cost Explorer data and distributes them by email (or Slack). It reads the rds_cost_by_team.py output and formats it into a per-team summary that can be sent directly to each team's engineering lead.

#!/usr/bin/env python3
"""
generate_chargeback_reports.py
Generates and distributes monthly per-team RDS chargeback reports.

Reads cost data from the output of rds_cost_by_team.py (CSV) or
calls Cost Explorer directly. Emails each team lead using SES.

Requirements:
  boto3, jinja2
  pip install boto3 jinja2

Configuration:
  TEAM_CONTACTS_FILE  Path to JSON file mapping team names to email addresses
  FROM_EMAIL          Verified SES sender address
  REPORT_MONTH        YYYY-MM format; defaults to previous month
"""

import boto3
import csv
import json
import os
from collections import defaultdict
from datetime import datetime, date
from email.mime.multipart import MIMEMultipart
from email.mime.text import MIMEText
from jinja2 import Template

TEAM_CONTACTS_FILE = os.environ.get("TEAM_CONTACTS_FILE", "team_contacts.json")
FROM_EMAIL         = os.environ.get("FROM_EMAIL", "finops@yourcompany.com")
REPORT_MONTH       = os.environ.get("REPORT_MONTH", "")  # defaults to last month below


EMAIL_TEMPLATE = """
<!DOCTYPE html>
<html>
<body style="font-family: Arial, sans-serif; color: #333;">
<h2>📊 RDS Cost Chargeback Report — {{ month }}</h2>
<p>Hello {{ team_lead_name }},</p>
<p>Below is the database cost summary for the <strong>{{ team }}</strong> team for {{ month }}.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse; width: 100%;">
  <thead style="background-color: #f0f0f0;">
    <tr>
      <th>Usage Type</th>
      <th>Cost (USD)</th>
      <th>% of Team Total</th>
    </tr>
  </thead>
  <tbody>
    {% for row in usage_rows %}
    <tr>
      <td>{{ row.usage_type }}</td>
      <td>${{ "%.2f"|format(row.cost_usd) }}</td>
      <td>{{ "%.1f"|format(row.pct) }}%</td>
    </tr>
    {% endfor %}
  </tbody>
  <tfoot style="background-color: #f8f8f8; font-weight: bold;">
    <tr>
      <td>TOTAL</td>
      <td>${{ "%.2f"|format(team_total) }}</td>
      <td>100%</td>
    </tr>
  </tfoot>
</table>

<p style="margin-top: 16px;">
  <strong>Untagged resources cost:</strong>
  ${{ "%.2f"|format(untagged_cost) }} — these are not included in team totals
  and represent optimization opportunities.
</p>

<p>
  Questions? Contact the FinOps team at <a href="mailto:finops@yourcompany.com">finops@yourcompany.com</a>
  or review the full report in the
  <a href="{{ dashboard_url }}">FinOps Dashboard</a>.
</p>
</body>
</html>
"""


def get_report_month() -> str:
    if REPORT_MONTH:
        return REPORT_MONTH
    today = date.today()
    # Default to previous month
    if today.month == 1:
        return f"{today.year - 1}-12"
    return f"{today.year}-{today.month - 1:02d}"


def load_team_contacts(path: str) -> dict:
    """
    team_contacts.json format:
    {
      "payments": {"email": "lead@payments.co", "name": "Alice Chen"},
      "analytics": {"email": "lead@analytics.co", "name": "Bob Patel"},
      ...
    }
    """
    with open(path) as f:
        return json.load(f)


def load_cost_data_from_csv(csv_path: str, month: str) -> list[dict]:
    rows = []
    with open(csv_path, newline="") as f:
        for row in csv.DictReader(f):
            if row.get("month", "").startswith(month):
                rows.append(row)
    return rows


def aggregate_by_team(rows: list[dict]) -> dict:
    team_data = defaultdict(list)
    for row in rows:
        team_data[row["team"]].append({
            "usage_type": row["usage_type"],
            "cost_usd":   float(row["cost_usd"])
        })
    return team_data


def send_email_ses(to_addr: str, from_addr: str,
                   subject: str, html_body: str) -> None:
    ses = boto3.client("ses", region_name="us-east-1")
    msg = MIMEMultipart("alternative")
    msg["Subject"] = subject
    msg["From"]    = from_addr
    msg["To"]      = to_addr
    msg.attach(MIMEText(html_body, "html"))

    ses.send_raw_email(
        Source=from_addr,
        Destinations=[to_addr],
        RawMessage={"Data": msg.as_string()}
    )
    print(f"  Email sent to {to_addr}")


def generate_and_distribute(csv_path: str, dry_run: bool = True) -> None:
    month         = get_report_month()
    team_contacts = load_team_contacts(TEAM_CONTACTS_FILE)
    rows          = load_cost_data_from_csv(csv_path, month)
    team_data     = aggregate_by_team(rows)
    template      = Template(EMAIL_TEMPLATE)
    dashboard_url = os.environ.get("DASHBOARD_URL", "https://finops.yourcompany.com")

    untagged_cost = sum(
        r["cost_usd"] for r in team_data.get("UNTAGGED", [])
    )

    print(f"\nGenerating chargeback reports for {month}...")
    print(f"Teams with data: {sorted(team_data.keys())}\n")

    for team, contact in team_contacts.items():
        usage_rows = team_data.get(team, [])
        if not usage_rows:
            print(f"  [SKIP] No cost data for team '{team}' in {month}")
            continue

        team_total = sum(r["cost_usd"] for r in usage_rows)
        for r in usage_rows:
            r["pct"] = (r["cost_usd"] / team_total * 100) if team_total > 0 else 0
        usage_rows.sort(key=lambda r: r["cost_usd"], reverse=True)

        html = template.render(
            month=month,
            team=team,
            team_lead_name=contact["name"],
            usage_rows=usage_rows,
            team_total=team_total,
            untagged_cost=untagged_cost,
            dashboard_url=dashboard_url
        )

        subject = f"RDS Cost Chargeback — {team} — {month} — ${team_total:,.2f}"

        if dry_run:
            print(f"  [DRY RUN] Would email {contact['email']}: {subject}")
        else:
            send_email_ses(contact["email"], FROM_EMAIL, subject, html)


if __name__ == "__main__":
    import argparse
    parser = argparse.ArgumentParser()
    parser.add_argument("--csv",     required=True, help="Path to cost CSV from rds_cost_by_team.py")
    parser.add_argument("--apply",   action="store_true", help="Send emails (default: dry run)")
    args = parser.parse_args()
    generate_and_distribute(args.csv, dry_run=not args.apply)

Run this on the third business day of each month, after Cost Explorer data for the prior month has settled. Send the emails to engineering leads first, give them a week to raise disputes, then send the final version to Finance for budget reconciliation.

Key Takeaways

  • → **A tag schema must serve both Finance and Engineering simultaneously.** A small mandatory set (five to six keys covering environment, team, cost center, project, and application) paired with an optional enrichment set is more durable than either a sprawling mandated list or a purely operational tagging convention that Finance cannot use for budget allocation.
  • → **Untagged database spend is not a tagging problem—it is an ownership problem.** The first step after discovering untagged resources is assigning an owner, not applying a tag. Without ownership, the tag will be inaccurate or drift over time. Use the audit pipeline to surface the cost of untagged resources explicitly and make it visible to leadership; financial visibility is the most reliable forcing function for ownership.
  • → **Enforce at creation time, audit continuously, and remediate through pipeline gates.** Cloud-native policies (AWS SCPs, Azure Policy, GCP Organization Policy custom constraints) block noncompliant resources at the API level. IaC validation (Terraform variable validation, OPA/Conftest in CI) catches problems before API calls are made. The weekly audit Lambda catches drift between deployments. Each layer compensates for the gaps of the others.
  • → **Multi-cloud tag normalization belongs in the data warehouse, not in each cloud's tagging convention.** You cannot retroactively harmonize `CostCenter`, `cost-center`, and `cost_center` across three clouds, but you can normalize them in a unified billing view. A tag normalization lookup table that maps raw values to canonical values prevents per-team cost views from fragmenting due to minor capitalization or delimiter inconsistencies.
  • → **Showback precedes chargeback.** Begin by distributing read-only monthly reports that show teams what they consumed without moving budget. Once teams can see their costs clearly, they will identify optimization opportunities themselves. Introduce financial accountability through chargeback only after the tagging data quality is high enough that teams can trust—and if necessary, dispute—the numbers they are being charged.
