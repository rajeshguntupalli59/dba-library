Chapter 10: Idle Instance Detection and Automated Shutdown

Organizations running cloud databases at scale consistently find that 20–35% of their RDS, Azure SQL, and Cloud SQL instances are functionally idle at any given moment — consuming full compute and storage costs while serving zero meaningful workload. At an average of $200–$800/month per db.r6g.large or equivalent instance, a 50-instance fleet can hemorrhage $50,000–$150,000 annually on instances that nobody noticed were abandoned. This chapter builds a complete detection-to-shutdown pipeline: first identifying idle instances using CloudWatch, Azure Monitor, and GCP metrics, then validating idleness against connection counts and query throughput, and finally automating graceful shutdown with appropriate safeguards. Teams that implement this pipeline systematically report 15–30% reductions in their monthly database bills within the first 60 days.

---

10.1 Defining "Idle": Metrics That Actually Matter

The instinct to define an idle database as one with zero connections is wrong in practice. Client-side connection pools (ADO.NET / ODBC / JDBC) maintain persistent connections to the database engine even when no application queries are running. A single health-check query from a monitoring agent counts as a "connection" and will mask genuine idleness if you rely on connection count alone.

A production-grade idle definition combines four signals measured over a rolling 7-day window:

DatabaseConnections: The average number of active connections. For most workloads, a database averaging fewer than 2 connections over 7 days is a strong candidate.

ReadIOPS + WriteIOPS: Combined I/O operations per second. A truly idle database shows near-zero I/O. Thresholds below 1 IOPS average over 7 days are reliable.

CPUUtilization: CPU below 1% average over 7 days, excluding maintenance windows.

NetworkReceiveThroughput: Below 10 KB/s average, which eliminates instances receiving replication traffic or periodic ETL loads.

Using any single metric produces false positives. A batch ETL job that runs Sunday nights shows zero connections all week but is legitimate. Combining all four signals, with the 7-day rolling window, filters out these jobs reliably.

The financial logic is straightforward. An db.r6g.large in us-east-1 costs $0.26/hour on-demand, which is $187/month. That instance may have 100 GB of gp2 storage at $0.115/GB, adding $11.50/month — $198.50 total. Multiplied across 20 genuinely idle instances, you are spending $3,970/month. Automated shutdown eliminates that entirely. Even if you implement scheduled stop/start rather than full termination, stopping RDS instances for 16 hours per day on non-production instances saves 67% of the compute cost while keeping storage costs in place, dropping that $187 compute to roughly $62.

AWS: CloudWatch Metrics for Idle RDS Detection

# idle_detector_aws.py
# Scans all RDS instances in a region and scores them for idleness
# Run on a schedule (daily via Lambda or cron)
# Requires: boto3, IAM permissions for rds:DescribeDBInstances,
#           cloudwatch:GetMetricStatistics, ce:GetCostAndUsage

import boto3
import json
from datetime import datetime, timedelta, timezone
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class InstanceIdleScore:
    instance_id: str
    instance_class: str
    engine: str
    status: str
    region: str
    avg_connections: float = 0.0
    avg_cpu: float = 0.0
    avg_read_iops: float = 0.0
    avg_write_iops: float = 0.0
    avg_network_kb: float = 0.0
    idle_score: int = 0          # 0-4, higher = more idle
    monthly_cost_usd: float = 0.0
    tags: dict = field(default_factory=dict)
    recommendation: str = ""

# On-demand pricing for common RDS for SQL Server instance classes
# (us-east-1, Standard edition, license-included, single-AZ, USD/hour).
# NOTE: SQL Server cannot run on Graviton (t4g/m6g/r6g) classes — Intel/AMD only.
# Rates below are ILLUSTRATIVE. Update quarterly from the AWS RDS for SQL Server
# pricing page or fetch from the AWS Price List API.
RDS_HOURLY_PRICING = {
    "db.t3.micro":    0.12,
    "db.t3.small":    0.24,
    "db.t3.medium":   0.48,
    "db.t3.large":    0.96,
    "db.r6i.large":   1.60,
    "db.r6i.xlarge":  3.20,
    "db.r6i.2xlarge": 6.40,
    "db.r5.large":    1.45,
    "db.r5.xlarge":   2.90,
    "db.r5.2xlarge":  5.80,
    "db.m6i.large":   1.15,
    "db.m6i.xlarge":  2.30,
}

def get_metric_average(cw_client, instance_id, metric_name, namespace,
                        days=7, period_seconds=604800):
    """
    Fetches a single metric average over the past N days.
    period_seconds=604800 = 1 week (single data point average).
    """
    end_time = datetime.now(timezone.utc)
    start_time = end_time - timedelta(days=days)

    response = cw_client.get_metric_statistics(
        Namespace=namespace,
        MetricName=metric_name,
        Dimensions=[{"Name": "DBInstanceIdentifier", "Value": instance_id}],
        StartTime=start_time,
        EndTime=end_time,
        Period=period_seconds,
        Statistics=["Average"]
    )

    datapoints = response.get("Datapoints", [])
    if not datapoints:
        return 0.0
    return round(datapoints[0]["Average"], 4)

def score_instance(instance: InstanceIdleScore) -> InstanceIdleScore:
    """
    Assigns an idle score 0-4 based on four metric thresholds.
    Score 4 = idle across all dimensions.
    """
    score = 0
    if instance.avg_connections < 2.0:
        score += 1
    if instance.avg_cpu < 1.0:
        score += 1
    if (instance.avg_read_iops + instance.avg_write_iops) < 1.0:
        score += 1
    if instance.avg_network_kb < 10.0:
        score += 1

    instance.idle_score = score

    if score == 4:
        instance.recommendation = "STOP_OR_TERMINATE"
    elif score == 3:
        instance.recommendation = "INVESTIGATE_THEN_STOP"
    elif score == 2:
        instance.recommendation = "SCHEDULE_REVIEW"
    else:
        instance.recommendation = "ACTIVE_KEEP"

    return instance

def estimate_monthly_cost(instance_class: str, storage_gb: int = 0) -> float:
    hourly = RDS_HOURLY_PRICING.get(instance_class, 0.30)
    compute = hourly * 24 * 30
    storage = storage_gb * 0.115          # gp2 pricing
    return round(compute + storage, 2)

def scan_region(region: str) -> list[InstanceIdleScore]:
    rds = boto3.client("rds", region_name=region)
    cw  = boto3.client("cloudwatch", region_name=region)

    paginator = rds.get_paginator("describe_db_instances")
    results = []

    for page in paginator.paginate():
        for db in page["DBInstances"]:
            if db["DBInstanceStatus"] not in ("available", "stopped"):
                continue

            tags = {t["Key"]: t["Value"]
                    for t in db.get("TagList", [])}

            # Skip instances explicitly tagged to protect from auto-shutdown
            if tags.get("AutoShutdown") == "false":
                continue

            storage_gb = db.get("AllocatedStorage", 0)
            score_obj = InstanceIdleScore(
                instance_id=db["DBInstanceIdentifier"],
                instance_class=db["DBInstanceClass"],
                engine=db["Engine"],
                status=db["DBInstanceStatus"],
                region=region,
                tags=tags,
                monthly_cost_usd=estimate_monthly_cost(
                    db["DBInstanceClass"], storage_gb
                )
            )

            # Already stopped instances are trivially idle
            if db["DBInstanceStatus"] == "stopped":
                score_obj.idle_score = 4
                score_obj.recommendation = "ALREADY_STOPPED_VERIFY_DELETION"
                results.append(score_obj)
                continue

            iid = db["DBInstanceIdentifier"]
            score_obj.avg_connections = get_metric_average(
                cw, iid, "DatabaseConnections", "AWS/RDS")
            score_obj.avg_cpu = get_metric_average(
                cw, iid, "CPUUtilization", "AWS/RDS")
            score_obj.avg_read_iops = get_metric_average(
                cw, iid, "ReadIOPS", "AWS/RDS")
            score_obj.avg_write_iops = get_metric_average(
                cw, iid, "WriteIOPS", "AWS/RDS")

            net_bytes = get_metric_average(
                cw, iid, "NetworkReceiveThroughput", "AWS/RDS")
            score_obj.avg_network_kb = round(net_bytes / 1024, 2)

            results.append(score_instance(score_obj))

    return results

def main():
    regions = ["us-east-1", "us-west-2", "eu-west-1"]
    all_results = []

    for region in regions:
        print(f"Scanning {region}...")
        all_results.extend(scan_region(region))

    # Sort by idle score descending, then cost descending
    all_results.sort(key=lambda x: (x.idle_score, x.monthly_cost_usd),
                     reverse=True)

    total_idle_cost = sum(
        i.monthly_cost_usd for i in all_results
        if i.idle_score >= 3
    )

    print(f"\n{'='*70}")
    print(f"IDLE INSTANCE REPORT — {datetime.now().strftime('%Y-%m-%d')}")
    print(f"{'='*70}")
    print(f"Total instances scanned : {len(all_results)}")
    print(f"Idle candidates (score≥3): "
          f"{sum(1 for i in all_results if i.idle_score >= 3)}")
    print(f"Potential monthly savings: ${total_idle_cost:,.2f}")
    print(f"{'='*70}\n")

    for inst in all_results:
        if inst.idle_score >= 3:
            print(f"  {inst.instance_id:<40} "
                  f"Score:{inst.idle_score}/4  "
                  f"${inst.monthly_cost_usd:>8.2f}/mo  "
                  f"{inst.recommendation}")

    # Write JSON for downstream automation
    output = [vars(i) for i in all_results if i.idle_score >= 3]
    with open("/tmp/idle_instances.json", "w") as f:
        json.dump(output, f, indent=2)
    print(f"\nCandidates written to /tmp/idle_instances.json")

if __name__ == "__main__":
    main()

Azure SQL: Querying Metrics via Azure Monitor

#!/bin/bash
# azure_idle_detector.sh
# Detects idle Azure SQL databases using Azure Monitor metrics
# Requires: az login, Contributor or Monitoring Reader role

SUBSCRIPTION_ID="your-subscription-id"
LOOKBACK_DAYS=7
END_TIME=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
START_TIME=$(date -u -d "-${LOOKBACK_DAYS} days" +"%Y-%m-%dT%H:%M:%SZ")

OUTPUT_FILE="/tmp/azure_idle_sql.csv"
echo "server,database,sku,avg_cpu_pct,avg_connections,dtu_limit,est_monthly_usd,recommendation" \
  > "$OUTPUT_FILE"

# DTU pricing map (General Purpose, per database/month approximations)
declare -A DTU_COST
DTU_COST["Basic"]="4.90"
DTU_COST["S0"]="14.72"
DTU_COST["S1"]="29.43"
DTU_COST["S2"]="58.87"
DTU_COST["P1"]="465.00"
DTU_COST["GP_Gen5_2"]="368.00"
DTU_COST["GP_Gen5_4"]="736.00"
DTU_COST["BC_Gen5_2"]="1105.00"

az account set --subscription "$SUBSCRIPTION_ID"

# List all SQL servers
SERVERS=$(az sql server list --query "[].{name:name, rg:resourceGroup}" -o tsv)

while IFS=$'\t' read -r SERVER_NAME RESOURCE_GROUP; do
    echo "Checking server: $SERVER_NAME"

    # List all databases on this server (exclude master)
    DATABASES=$(az sql db list \
        --server "$SERVER_NAME" \
        --resource-group "$RESOURCE_GROUP" \
        --query "[?name!='master'].{name:name, sku:sku.name, tier:sku.tier}" \
        -o tsv)

    while IFS=$'\t' read -r DB_NAME SKU_NAME SKU_TIER; do
        RESOURCE_ID="/subscriptions/${SUBSCRIPTION_ID}/resourceGroups/${RESOURCE_GROUP}"
        RESOURCE_ID+="/providers/Microsoft.Sql/servers/${SERVER_NAME}"
        RESOURCE_ID+="/databases/${DB_NAME}"

        # Fetch average CPU percentage over the lookback window
        AVG_CPU=$(az monitor metrics list \
            --resource "$RESOURCE_ID" \
            --metric "cpu_percent" \
            --start-time "$START_TIME" \
            --end-time "$END_TIME" \
            --aggregation Average \
            --interval P1D \
            --query "value[0].timeseries[0].data[*].average" \
            -o tsv 2>/dev/null \
          | awk 'NF{sum+=$1; count++} END {
                if(count>0) printf "%.2f", sum/count; else print "0.00"
            }')

        # Fetch average connection count
        AVG_CONN=$(az monitor metrics list \
            --resource "$RESOURCE_ID" \
            --metric "connection_successful" \
            --start-time "$START_TIME" \
            --end-time "$END_TIME" \
            --aggregation Total \
            --interval P1D \
            --query "value[0].timeseries[0].data[*].total" \
            -o tsv 2>/dev/null \
          | awk 'NF{sum+=$1; count++} END {
                if(count>0) printf "%.0f", sum/count; else print "0"
            }')

        # Look up estimated cost
        COST="${DTU_COST[$SKU_NAME]:-unknown}"

        # Classify
        RECOMMENDATION="ACTIVE_KEEP"
        if (( $(echo "$AVG_CPU < 1.0" | bc -l) )) && \
           (( $(echo "$AVG_CONN < 50" | bc -l) )); then
            RECOMMENDATION="PAUSE_OR_DELETE"
        elif (( $(echo "$AVG_CPU < 5.0" | bc -l) )); then
            RECOMMENDATION="DOWNSIZE_SKU"
        fi

        echo "${SERVER_NAME},${DB_NAME},${SKU_NAME},${AVG_CPU}," \
             "${AVG_CONN},${SKU_NAME},${COST},${RECOMMENDATION}" \
          >> "$OUTPUT_FILE"

        if [[ "$RECOMMENDATION" == "PAUSE_OR_DELETE" ]]; then
            echo "  ⚠  IDLE: ${SERVER_NAME}/${DB_NAME} " \
                 "CPU=${AVG_CPU}% Conn=${AVG_CONN}/day SKU=${SKU_NAME} ~\$${COST}/mo"
        fi

    done <<< "$DATABASES"
done <<< "$SERVERS"

echo ""
echo "Report written to $OUTPUT_FILE"
echo "Idle databases by potential savings:"
awk -F',' 'NR>1 && $8=="PAUSE_OR_DELETE" {print $7, $1"/"$2}' "$OUTPUT_FILE" \
  | sort -rn \
  | awk '{printf "  $%s/mo  %s\n", $1, $2}'

GCP Cloud SQL: Detecting Idle Instances with gcloud and BigQuery

-- Query against the GCP Billing Export table in BigQuery
-- Replace `your_project.billing_dataset.gcp_billing_export_v1_XXXXXX`
-- This surfaces Cloud SQL instances with cost but no meaningful usage

WITH daily_costs AS (
  SELECT
    DATE(usage_start_time) AS usage_date,
    resource.name          AS instance_name,
    service.description    AS service,
    sku.description        AS sku_description,
    SUM(cost)              AS daily_cost_usd,
    SUM(usage.amount)      AS usage_amount,
    usage.unit             AS usage_unit
  FROM
    `your_project.billing_dataset.gcp_billing_export_v1_XXXXXX`
  WHERE
    service.description = 'Cloud SQL'
    AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
    AND cost > 0
  GROUP BY 1, 2, 3, 4, 6, 7
),

instance_summary AS (
  SELECT
    instance_name,
    SUM(CASE WHEN sku_description LIKE '%CPU%'
             THEN daily_cost_usd ELSE 0 END)     AS cpu_cost_30d,
    SUM(CASE WHEN sku_description LIKE '%Storage%'
             THEN daily_cost_usd ELSE 0 END)      AS storage_cost_30d,
    SUM(daily_cost_usd)                           AS total_cost_30d,
    COUNT(DISTINCT usage_date)                    AS days_with_charges
  FROM daily_costs
  GROUP BY 1
),

-- Join to Cloud SQL instance metrics exported via Cloud Monitoring
-- (assumes you have exported metrics to BigQuery via Monitoring Export)
metric_summary AS (
  SELECT
    resource.labels.database_id               AS instance_name,
    AVG(point.value.double_value)             AS avg_cpu_utilization
  FROM
    `your_project.monitoring_dataset.cloudsql_database`
  WHERE
    metric.type = 'cloudsql.googleapis.com/database/cpu/utilization'
    AND DATE(point.interval.end_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY)
  GROUP BY 1
)

SELECT
  i.instance_name,
  ROUND(i.total_cost_30d, 2)                  AS total_cost_30d_usd,
  ROUND(i.cpu_cost_30d, 2)                    AS cpu_cost_30d_usd,
  ROUND(i.storage_cost_30d, 2)                AS storage_cost_30d_usd,
  i.days_with_charges,
  ROUND(m.avg_cpu_utilization * 100, 2)       AS avg_cpu_pct_7d,
  CASE
    WHEN m.avg_cpu_utilization < 0.01
     AND i.cpu_cost_30d > 0
    THEN 'STOP_CANDIDATE'
    WHEN m.avg_cpu_utilization < 0.05
    THEN 'DOWNSIZE_CANDIDATE'
    ELSE 'ACTIVE'
  END                                          AS recommendation,
  ROUND(i.cpu_cost_30d * 12, 0)               AS projected_annual_cpu_waste_usd
FROM instance_summary i
LEFT JOIN metric_summary m
  ON i.instance_name = m.instance_name
WHERE i.total_cost_30d > 10        -- filter out trivial instances
ORDER BY projected_annual_cpu_waste_usd DESC;

10.3 Validating Candidates Before Taking Action

Automated detection surfaces candidates. Human or rule-based validation prevents the scenario where you shut down a database that runs a quarterly financial close process and hasn't run in 6 weeks because the last close was 6 weeks ago.

The validation layer adds three checks before any shutdown action is authorized.

Check 1: Recent Snapshot or Backup Activity

An instance with a backup taken in the last 24 hours, even if idle by metrics, may be part of an active pipeline. Query RDS automated backups to verify.

#!/bin/bash
# validate_backup_recency.sh
# For each idle candidate, check the most recent automated snapshot.
# If a snapshot was taken within 48 hours AND no other idle signals
# exist, flag for manual review instead of automated action.

CANDIDATES_FILE="/tmp/idle_instances.json"

if [[ ! -f "$CANDIDATES_FILE" ]]; then
    echo "Run idle_detector_aws.py first to generate candidates."
    exit 1
fi

# Parse instance IDs from the JSON output of idle_detector_aws.py
INSTANCE_IDS=$(python3 -c "
import json
with open('$CANDIDATES_FILE') as f:
    data = json.load(f)
print('\n'.join(i['instance_id'] for i in data))
")

NOW_EPOCH=$(date +%s)
FORTY_EIGHT_HOURS=172800

echo "Validating backup recency for idle candidates..."
echo "-----------------------------------------------"

while IFS= read -r INSTANCE_ID; do
    [[ -z "$INSTANCE_ID" ]] && continue

    # Get the most recent automated snapshot
    LATEST_SNAPSHOT=$(aws rds describe-db-snapshots \
        --db-instance-identifier "$INSTANCE_ID" \
        --snapshot-type automated \
        --query "sort_by(DBSnapshots, &SnapshotCreateTime)[-1].SnapshotCreateTime" \
        --output text 2>/dev/null)

    if [[ "$LATEST_SNAPSHOT" == "None" ]] || [[ -z "$LATEST_SNAPSHOT" ]]; then
        echo "  $INSTANCE_ID — NO SNAPSHOTS FOUND — safe to terminate"
        continue
    fi

    # Convert ISO timestamp to epoch
    SNAP_EPOCH=$(date -d "$LATEST_SNAPSHOT" +%s 2>/dev/null || \
                 date -jf "%Y-%m-%dT%H:%M:%S" \
                     "${LATEST_SNAPSHOT%%.*}" +%s 2>/dev/null)

    AGE_SECONDS=$(( NOW_EPOCH - SNAP_EPOCH ))
    AGE_HOURS=$(( AGE_SECONDS / 3600 ))

    if (( AGE_SECONDS < FORTY_EIGHT_HOURS )); then
        echo "  $INSTANCE_ID — RECENT BACKUP ($AGE_HOURS hrs ago) — flag for review"
    else
        echo "  $INSTANCE_ID — STALE BACKUP ($AGE_HOURShrs ago) — safe for automated action"
    fi

done <<< "$INSTANCE_IDS"

Check 2: Tag-Based Exemptions

Before acting on any candidate, re-verify tags at action time (not just at scan time). Tags can change between detection and enforcement. The following tag keys are the minimal exemption contract teams should agree on before deploying automation:

| Tag Key | Value | Meaning |

|---|---|---|

| AutoShutdown | false | Never shut this instance down automatically |

| Environment | production | Exclude from any automated stop/terminate |

| Schedule | quarterly | Runs quarterly; extend idle window to 90 days |

| Owner | team-name | Notify this team before action |

| LastKnownUse | ISO date | Human-annotated last intentional use date |

Any instance tagged Environment=production or AutoShutdown=false must be excluded at the action stage even if it scored 4/4 on idleness. The detection query already filters these, but the action script enforces the same check independently to create a defense-in-depth pattern.

Check 3: Cross-Reference with Application Deployment Records

If your organization uses a CMDB or deployment tagging convention (e.g., AWS Systems Manager Inventory, Azure Resource Graph, or GCP Asset Inventory), a cross-reference query can catch databases associated with active application deployments. The following Resource Graph query identifies Azure SQL databases where the parent logical server has an associated App Service or AKS cluster in the same resource group that was deployed or scaled in the past 30 days:

# Azure Resource Graph: find SQL databases linked to recently active apps
az graph query -q "
Resources
| where type == 'microsoft.sql/servers/databases'
| where name != 'master'
| project sqlDb=name, sqlServer=split(id, '/')[8],
          resourceGroup, subscriptionId
| join kind=leftouter (
    Resources
    | where type in (
        'microsoft.web/sites',
        'microsoft.containerservice/managedclusters'
      )
    | where properties.lastModifiedTimeUtc >= ago(30d)
    | project appName=name, resourceGroup, subscriptionId
  ) on resourceGroup, subscriptionId
| project sqlDb, sqlServer, resourceGroup,
          linkedApp=appName
| where isempty(linkedApp)
" --output table

SQL databases that appear here — no linked active app in the same resource group — are stronger termination candidates. Databases that have a linked app are handed off to the application team for confirmation before any action.

10.4 Automated Shutdown: Stop vs. Terminate vs. Snapshot-Then-Delete

The action vocabulary has three options, and choosing the wrong one is expensive in different ways:

Stop (RDS: stop-db-instance): Preserves the instance configuration, keeps automated backups, retains storage. Compute billing stops. Storage billing continues. AWS automatically restarts stopped instances after 7 days — a frustrating default that must be accounted for in your automation. Cost saving: roughly 60–70% of the monthly bill depending on storage fraction.

Terminate with final snapshot: Creates a final automated snapshot, then permanently deletes the instance. Compute and storage billing both stop. Snapshot storage is charged at $0.095/GB-month (RDS) until explicitly deleted. This is the right choice for instances confirmed as truly decommissioned.

Snapshot-then-delete (manual pattern): Take a manual snapshot first, tag it with metadata, then delete the instance. Gives you a recovery path without retaining the live instance. Manual snapshots persist until explicitly deleted, unlike automated snapshots that follow retention policies.

The decision tree for which action to take:

graph TD
    A[Idle candidate detected] --> B{idle_score == 4 AND\nalready stopped > 7 days?}
    B -->|Yes| C[Notify owner 7 days prior\n-> final snapshot -> terminate\n-> delete snapshot after 90 days]
    B -->|No| D{idle_score == 4 AND\nstatus == available?}
    D -->|Yes| E{Environment != production AND\nAutoShutdown != false?}
    E -->|Yes| F[Stop instance immediately\nre-check in 14 days]
    D -->|No| G{idle_score == 3?}
    G -->|Yes| H[Notify owner with evidence\nno action for 7 days]

*The idle-shutdown decision tree — confidence level (idle_score) determines how aggressive the automated action is.*

idle_score == 4 AND status == "stopped" (already stopped > 7 days)
    → Owner notified 7 days prior
    → Take final snapshot tagged with instance metadata
    → Terminate instance
    → Set snapshot lifecycle policy: delete after 90 days

idle_score == 4 AND status == "available" (running but idle)
    → Environment != production AND AutoShutdown != false
    → Stop instance immediately
    → Schedule re-check in 14 days
    → If still idle after 14 days: escalate to terminate workflow

idle_score == 3 (borderline idle)
    → Send owner notification with metrics evidence
    → No automated action for 7 days
    → If no response: treat as score-4 path

Implementing the Stop Action in AWS

# shutdown_orchestrator.py
# Reads /tmp/idle_instances.json and applies the stop/terminate decision tree.
# Designed to run as a Lambda function or from the command line.
# All actions are logged to CloudWatch Logs and a local audit trail.

import boto3
import json
import sys
import logging
from datetime import datetime, timezone
from typing import Optional

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s  %(levelname)-8s  %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S"
)
log = logging.getLogger(__name__)

AUDIT_LOG = "/tmp/shutdown_audit.jsonl"
DRY_RUN = "--dry-run" in sys.argv  # Pass --dry-run to preview actions safely

PROTECTED_ENVIRONMENTS = {"production", "prod", "prd"}
SNAPSHOT_RETENTION_DAYS = 90

def load_candidates(path: str) -> list[dict]:
    with open(path) as f:
        return json.load(f)

def append_audit(record: dict):
    with open(AUDIT_LOG, "a") as f:
        f.write(json.dumps(record) + "\n")

def verify_tags_at_action_time(rds_client, instance_id: str) -> dict:
    """Re-fetch tags at action time, not from the cached scan data."""
    try:
        arn_response = rds_client.describe_db_instances(
            DBInstanceIdentifier=instance_id
        )
        db = arn_response["DBInstances"][0]
        arn = db["DBInstanceArn"]
        tag_response = rds_client.list_tags_for_resource(ResourceName=arn)
        return {t["Key"]: t["Value"] for t in tag_response["TagList"]}
    except Exception as e:
        log.warning(f"Could not fetch tags for {instance_id}: {e}")
        return {}

def is_protected(tags: dict) -> bool:
    env = tags.get("Environment", "").lower()
    if env in PROTECTED_ENVIRONMENTS:
        return True
    if tags.get("AutoShutdown", "").lower() == "false":
        return True
    return False

def take_final_snapshot(rds_client, instance_id: str,
                         tags: dict) -> Optional[str]:
    timestamp = datetime.now(timezone.utc).strftime("%Y%m%d-%H%M%S")
    snapshot_id = f"finops-final-{instance_id}-{timestamp}"
    # Snapshot IDs max 255 chars; truncate instance_id if needed
    snapshot_id = snapshot_id[:254]

    if DRY_RUN:
        log.info(f"[DRY-RUN] Would create snapshot: {snapshot_id}")
        return snapshot_id

    try:
        rds_client.create_db_snapshot(
            DBSnapshotIdentifier=snapshot_id,
            DBInstanceIdentifier=instance_id,
            Tags=[
                {"Key": "CreatedBy",    "Value": "finops-idle-shutdown"},
                {"Key": "InstanceId",   "Value": instance_id},
                {"Key": "DeleteAfter",
                 "Value": (datetime.now(timezone.utc).strftime("%Y-%m-%d"))},
                {"Key": "OriginalEnv",  "Value": tags.get("Environment", "unknown")},
            ]
        )
        log.info(f"Snapshot initiated: {snapshot_id}")
        return snapshot_id
    except Exception as e:
        log.error(f"Snapshot failed for {instance_id}: {e}")
        return None

def stop_instance(rds_client, instance_id: str):
    if DRY_RUN:
        log.info(f"[DRY-RUN] Would stop: {instance_id}")
        return
    try:
        rds_client.stop_db_instance(DBInstanceIdentifier=instance_id)
        log.info(f"Stop issued: {instance_id}")
    except Exception as e:
        log.error(f"Stop failed for {instance_id}: {e}")

def terminate_instance(rds_client, instance_id: str,
                        take_snapshot: bool = True) -> bool:
    snapshot_id = None
    if take_snapshot:
        # Must wait for any in-progress snapshot to complete before delete
        # In production, this becomes a Step Functions workflow; here we
        # just request the snapshot and mark the termination as pending.
        log.info(f"Termination pending snapshot completion: {instance_id}")
        return False  # Caller should re-check after snapshot completes

    if DRY_RUN:
        log.info(f"[DRY-RUN] Would terminate: {instance_id}")
        return True

    try:
        rds_client.delete_db_instance(
            DBInstanceIdentifier=instance_id,
            SkipFinalSnapshot=True,
            DeleteAutomatedBackups=False  # Keep automated backups per policy
        )
        log.info(f"Terminate issued: {instance_id}")
        return True
    except Exception as e:
        log.error(f"Terminate failed for {instance_id}: {e}")
        return False

def process_candidate(candidate: dict):
    region = candidate.get("region", "us-east-1")
    instance_id = candidate["instance_id"]
    idle_score = candidate.get("idle_score", 0)
    status = candidate.get("status", "available")
    recommendation = candidate.get("recommendation", "")

    rds = boto3.client("rds", region_name=region)

    # Defense-in-depth tag check at action time
    live_tags = verify_tags_at_action_time(rds, instance_id)
    if is_protected(live_tags):
        log.info(f"SKIPPED (protected by tags): {instance_id}")
        append_audit({
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "instance_id": instance_id,
            "action": "SKIPPED",
            "reason": "protected_tags",
            "tags": live_tags
        })
        return

    action_taken = "NONE"
    notes = ""

    if recommendation == "ALREADY_STOPPED_VERIFY_DELETION":
        # Already stopped; take snapshot and plan deletion
        snapshot_id = take_final_snapshot(rds, instance_id, live_tags)
        action_taken = "SNAPSHOT_FOR_DELETION"
        notes = f"snapshot={snapshot_id}; manual termination required after verification"

    elif idle_score == 4 and status == "available":
        stop_instance(rds, instance_id)
        action_taken = "STOPPED"
        notes = "Will re-check in 14 days for termination eligibility"

    elif idle_score == 3:
        action_taken = "NOTIFICATION_QUEUED"
        notes = "Owner notification queued; no automated action for 7 days"

    log.info(f"{action_taken}: {instance_id} — {notes}")
    append_audit({
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "instance_id": instance_id,
        "region": region,
        "idle_score": idle_score,
        "status": status,
        "action": action_taken,
        "dry_run": DRY_RUN,
        "notes": notes,
        "monthly_cost_usd": candidate.get("monthly_cost_usd", 0),
        "tags": live_tags
    })

def main():
    candidates = load_candidates("/tmp/idle_instances.json")
    log.info(f"Processing {len(candidates)} idle candidates "
             f"({'DRY RUN' if DRY_RUN else 'LIVE'})")

    for candidate in candidates:
        process_candidate(candidate)

    log.info(f"Audit log written to {AUDIT_LOG}")

if __name__ == "__main__":
    main()

10.5 Implementing Scheduled Stop/Start for Non-Production Instances

For non-production instances that need to exist but only run during business hours, a scheduled stop/start pattern captures most of the savings without the risk of full termination. A database running 10 hours per day (business hours) instead of 24 incurs 42% of its original compute cost.

The two main mechanisms are AWS Instance Scheduler and native EventBridge Scheduler rules for RDS.

EventBridge Scheduler: Stop All Dev Instances at 19:00 UTC

Lambda Function: Stop/Start Instances by Tag

# lambda_rds_stop_tagged.py
# Invoked by EventBridge Scheduler with {"action": "stop"|"start",
#   "tag_key": "...", "tag_value": "..."}
# Deploy as a Lambda function with a 5-minute timeout.

import boto3
import logging

log = logging.getLogger()
log.setLevel(logging.INFO)

def handler(event, context):
    action     = event.get("action", "stop")       # "stop" or "start"
    tag_key    = event.get("tag_key", "Environment")
    tag_value  = event.get("tag_value", "dev")
    regions    = event.get("regions", ["us-east-1", "us-west-2"])

    total_actioned = 0

    for region in regions:
        rds = boto3.client("rds", region_name=region)
        paginator = rds.get_paginator("describe_db_instances")

        for page in paginator.paginate():
            for db in page["DBInstances"]:
                db_id  = db["DBInstanceIdentifier"]
                status = db["DBInstanceStatus"]
                tags   = {t["Key"]: t["Value"] for t in db.get("TagList", [])}

                # Tag filter
                if tags.get(tag_key) != tag_value:
                    continue

                # Safety: never act on production regardless of tag_value match
                if tags.get("Environment", "").lower() in \
                        {"production", "prod", "prd"}:
                    log.warning(f"Skipping production instance: {db_id}")
                    continue

                # AutoShutdown=false exemption
                if tags.get("AutoShutdown", "").lower() == "false":
                    log.info(f"Skipping AutoShutdown=false: {db_id}")
                    continue

                try:
                    if action == "stop" and status == "available":
                        rds.stop_db_instance(DBInstanceIdentifier=db_id)
                        log.info(f"Stopped: {db_id} ({region})")
                        total_actioned += 1
                    elif action == "start" and status == "stopped":
                        rds.start_db_instance(DBInstanceIdentifier=db_id)
                        log.info(f"Started: {db_id} ({region})")
                        total_actioned += 1
                    else:
                        log.info(f"No action needed: {db_id} status={status}")
                except Exception as e:
                    log.error(f"Failed to {action} {db_id}: {e}")

    log.info(f"Total instances {action}ped: {total_actioned}")
    return {"actioned": total_actioned}

Azure SQL: Serverless Auto-Pause

Azure SQL's Serverless tier handles this natively. For databases on the General Purpose or Hyperscale tiers that need periodic use without continuous running cost, migrating to Serverless with an auto-pause delay of 60 minutes achieves stop/start behavior automatically without any Lambda equivalent.

# and configure auto-pause after 60 minutes of inactivity

RESOURCE_GROUP="myResourceGroup"
SERVER="my-sql-server"
DATABASE="my-dev-database"

az sql db update \
  --resource-group "$RESOURCE_GROUP" \
  --server "$SERVER" \
  --name "$DATABASE" \
  --compute-model Serverless \
  --auto-pause-delay 60 \
  --min-capacity 0.5 \

echo "Database $DATABASE migrated to Serverless with 60-minute auto-pause."
echo "Billing pauses automatically during inactivity."

The minimum vCore setting of 0.5 means the database can scale down to half a vCore while active, reducing costs for low-utilization periods as well. Combined with auto-pause, a database used for 2 hours per day on a 4-vCore SKU effectively costs what a continuous 0.5-vCore database costs on average — a reduction of roughly 80–90% compared to a continuously running General Purpose instance.

# main.py — Cloud Function handler for Cloud SQL stop/start
# Deploy alongside requirements.txt containing: google-cloud-sql-connector, google-auth

import os
import json
import logging
import functions_framework
from googleapiclient import discovery
from google.auth import default

log = logging.getLogger()

PROJECT_ID = os.environ.get("PROJECT_ID", "")

@functions_framework.http
def handle_schedule(request):
    body = request.get_json(silent=True) or {}
    action      = body.get("action", "stop")          # "stop" or "start"
    label_key   = body.get("label_key", "environment")
    label_value = body.get("label_value", "dev")

    credentials, project = default()
    sqladmin = discovery.build("sqladmin", "v1beta4",
                               credentials=credentials)

    instances_response = sqladmin.instances().list(
        project=PROJECT_ID
    ).execute()

    instances = instances_response.get("items", [])
    actioned = 0

    for instance in instances:
        instance_name = instance["name"]
        labels = instance.get("settings", {}).get("userLabels", {})
        state  = instance.get("state", "")

        if labels.get(label_key) != label_value:
            continue

        # Safety exclusion
        if labels.get("environment", "").lower() in \
                {"production", "prod", "prd"}:
            log.warning(f"Skipping production: {instance_name}")
            continue

        try:
            if action == "stop" and state == "RUNNABLE":
                sqladmin.instances().patch(
                    project=PROJECT_ID,
                    instance=instance_name,
                    body={"settings": {"activationPolicy": "NEVER"}}
                ).execute()
                log.info(f"Stopped: {instance_name}")
                actioned += 1

            elif action == "start" and state != "RUNNABLE":
                sqladmin.instances().patch(
                    project=PROJECT_ID,
                    instance=instance_name,
                    body={"settings": {"activationPolicy": "ALWAYS"}}
                ).execute()
                log.info(f"Started: {instance_name}")
                actioned += 1

        except Exception as e:
            log.error(f"Failed to {action} {instance_name}: {e}")

    return json.dumps({"actioned": actioned}), 200, \
           {"Content-Type": "application/json"}

10.6 Measuring the Impact and Building an Ongoing Process

Shutting down instances once is table stakes. The real value comes from making idle detection a continuous process that prevents new idle instances from accumulating undetected.

Weekly Idle Instance Report

The following query, run against the CloudWatch metrics stored in your detection pipeline's output or a central inventory table, provides a weekly digest for finance and engineering leadership:

-- Run against a SQL Server table populated by idle_detector_aws.py
-- Create the table once:
--
-- CREATE TABLE dbo.rds_idle_scan_results (
--   scan_date        DATE NOT NULL,
--   instance_id      NVARCHAR(255) NOT NULL,
--   region           NVARCHAR(50),
--   instance_class   NVARCHAR(100),
--   engine           NVARCHAR(50),
--   idle_score       INT,
--   avg_connections  DECIMAL(8,4),
--   avg_cpu          DECIMAL(8,4),
--   avg_read_iops    DECIMAL(8,4),
--   avg_write_iops   DECIMAL(8,4),
--   monthly_cost_usd DECIMAL(10,2),
--   recommendation   NVARCHAR(MAX),
--   action_taken     NVARCHAR(50),
--   PRIMARY KEY (scan_date, instance_id)
-- );

-- Weekly trend: how many idle instances were detected and acted on?
SELECT
    DATEADD(week, DATEDIFF(week, 0, scan_date), 0) AS week_start,
    COUNT(*)                                        AS total_scanned,
    SUM(CASE WHEN idle_score >= 3 THEN 1 ELSE 0 END) AS idle_candidates,
    SUM(CASE WHEN idle_score = 4 THEN 1 ELSE 0 END)  AS high_confidence_idle,
    SUM(CASE WHEN idle_score >= 3
             THEN monthly_cost_usd ELSE 0 END)       AS idle_monthly_cost_usd,
    SUM(CASE WHEN action_taken IN ('STOPPED','TERMINATED')
             THEN 1 ELSE 0 END)                      AS actions_taken,
    SUM(CASE WHEN action_taken IN ('STOPPED','TERMINATED')
             THEN monthly_cost_usd ELSE 0 END)       AS savings_actioned_usd
FROM rds_idle_scan_results
WHERE scan_date >= DATEADD(day, -90, CAST(GETDATE() AS DATE))
GROUP BY DATEADD(week, DATEDIFF(week, 0, scan_date), 0)
ORDER BY week_start DESC;

Drift Detection: Instances That Reappeared After Shutdown

A stopped instance that restarts automatically (AWS's 7-day auto-restart, or a developer manually starting a stopped instance) will reappear in your next scan. The following query surfaces "drift" — instances that were actioned and came back:

-- T-SQL: find instances that were stopped/terminated and then
-- reappeared as available in a subsequent scan

WITH actioned AS (
    SELECT DISTINCT instance_id, MIN(scan_date) AS first_actioned_date
    FROM rds_idle_scan_results
    WHERE action_taken IN ('STOPPED', 'TERMINATED')
    GROUP BY instance_id
),
reappeared AS (
    SELECT r.instance_id, r.scan_date AS reappear_date,
           r.idle_score, r.monthly_cost_usd
    FROM rds_idle_scan_results r
    JOIN actioned a ON r.instance_id = a.instance_id
    WHERE r.scan_date > a.first_actioned_date
      AND r.action_taken NOT IN ('STOPPED', 'TERMINATED')
      AND r.idle_score < 3   -- reappeared and now looks active
)
SELECT
    instance_id,
    first_actioned_date,
    reappear_date,
    DATEDIFF(day, first_actioned_date, reappear_date) AS days_until_reappear,
    idle_score                                         AS current_idle_score,
    monthly_cost_usd
FROM reappeared
ORDER BY days_until_reappear ASC;

Instances that consistently reappear as active within a day or two of being stopped are likely hitting AWS's 7-day auto-restart (someone is keeping them alive by starting them periodically). These are escalation candidates: the automation correctly identifies them as idle, but a human keeps restarting them, suggesting the instance has a legitimate owner who simply hasn't responded to notifications. The appropriate response is a direct conversation with the tagged owner, not repeated automated shutdowns.

Setting Up CloudWatch Alarms to Prevent New Idle Accumulation

Rather than only running the detection scan on a schedule, you can configure real-time alarms that fire when an instance transitions into an idle state. This catches newly abandoned instances within hours rather than waiting for the next weekly scan.

#!/bin/bash
# create_idle_alarms.sh```bash
# create_idle_alarms.sh (continued)
# Creates CloudWatch alarms on all running RDS instances to detect
# sustained low CPU, which triggers a notification to the FinOps SNS topic.
# Run this after provisioning any new RDS instance, or weekly to catch
# new instances that don't yet have alarms.

FINOPS_SNS_TOPIC_ARN="arn:aws:sns:us-east-1:123456789012:finops-idle-alerts"
REGION="us-east-1"
CPU_THRESHOLD=1.0          # percent
EVALUATION_PERIODS=48      # 48 × 30-minute periods = 24 hours sustained
DATAPOINTS_TO_ALARM=40     # 40 of 48 periods must breach (allows brief spikes)

rds_paginator() {
    aws rds describe-db-instances \
        --region "$REGION" \
        --query "DBInstances[?DBInstanceStatus=='available'].[DBInstanceIdentifier]" \
        --output text
}

while IFS= read -r INSTANCE_ID; do
    [[ -z "$INSTANCE_ID" ]] && continue

    ALARM_NAME="FinOps-IdleCPU-${INSTANCE_ID}"

    aws cloudwatch put-metric-alarm \
        --region "$REGION" \
        --alarm-name "$ALARM_NAME" \
        --alarm-description "CPU below ${CPU_THRESHOLD}% for 24h — possible idle instance" \
        --metric-name CPUUtilization \
        --namespace AWS/RDS \
        --dimensions "Name=DBInstanceIdentifier,Value=${INSTANCE_ID}" \
        --statistic Average \
        --period 1800 \
        --evaluation-periods "$EVALUATION_PERIODS" \
        --datapoints-to-alarm "$DATAPOINTS_TO_ALARM" \
        --threshold "$CPU_THRESHOLD" \
        --comparison-operator LessThanThreshold \
        --treat-missing-data notBreaching \
        --alarm-actions "$FINOPS_SNS_TOPIC_ARN" \
        --ok-actions "$FINOPS_SNS_TOPIC_ARN"

    echo "Alarm created/updated: $ALARM_NAME"

done < <(rds_paginator)

echo ""
echo "All idle CPU alarms configured."
echo "Alerts will fire to: $FINOPS_SNS_TOPIC_ARN"

The --treat-missing-data notBreaching setting is important here: if an instance is already stopped, CloudWatch will see missing data for CPU metrics. Without this setting, missing data would trigger the alarm — generating false alerts for instances you already shut down. With notBreaching, stopped instances stay quiet until they return to a running state and produce new metric data.

Connecting Alarms to the Detection Pipeline

The SNS topic receiving idle alarms can trigger the detection Lambda directly, creating an event-driven path alongside the scheduled scan:

# sns_triggered_scan.py
# Lambda handler: triggered by SNS when a CloudWatch idle alarm fires.
# Runs a targeted scan on the specific instance mentioned in the alarm,
# then writes to the same /tmp/idle_instances.json format for the
# shutdown_orchestrator to consume.

import json
import boto3
import logging
from datetime import datetime, timezone

log = logging.getLogger()
log.setLevel(logging.INFO)

# Import from the detection module (package both files in the Lambda layer)
from idle_detector_aws import scan_single_instance, score_instance

def handler(event, context):
    for record in event.get("Records", []):
        sns_message = json.loads(record["Sns"]["Message"])
        alarm_name  = sns_message.get("AlarmName", "")
        alarm_state = sns_message.get("NewStateValue", "")

        # Only act on ALARM transitions (not OK)
        if alarm_state != "ALARM":
            log.info(f"Ignoring non-ALARM state: {alarm_state} for {alarm_name}")
            continue

        # Extract instance ID from alarm name convention: FinOps-IdleCPU-<instance_id>
        if not alarm_name.startswith("FinOps-IdleCPU-"):
            log.warning(f"Unexpected alarm name format: {alarm_name}")
            continue

        instance_id = alarm_name.replace("FinOps-IdleCPU-", "")
        region = sns_message.get("Region", "us-east-1")

        log.info(f"Idle alarm fired for {instance_id} in {region}")

        # Run the full metric scan for this single instance
        result = scan_single_instance(instance_id, region)
        if result is None:
            log.warning(f"Could not scan {instance_id} — may have been deleted already")
            return

        scored = score_instance(result)
        log.info(f"Score for {instance_id}: {scored.idle_score}/4 "
                 f"— {scored.recommendation}")

        # Write to DynamoDB for the shutdown orchestrator to pick up
        dynamodb = boto3.resource("dynamodb", region_name=region)
        table    = dynamodb.Table("finops-idle-candidates")

        table.put_item(Item={
            "instance_id":      scored.instance_id,
            "detected_at":      datetime.now(timezone.utc).isoformat(),
            "idle_score":       scored.idle_score,
            "avg_connections":  str(scored.avg_connections),
            "avg_cpu":          str(scored.avg_cpu),
            "avg_read_iops":    str(scored.avg_read_iops),
            "avg_write_iops":   str(scored.avg_write_iops),
            "monthly_cost_usd": str(scored.monthly_cost_usd),
            "recommendation":   scored.recommendation,
            "region":           region,
            "ttl":              int(datetime.now(timezone.utc).timestamp()) + 604800
        })

        log.info(f"Candidate written to DynamoDB: {instance_id}")

This event-driven extension means a newly abandoned instance — one that drops to near-zero CPU after a project wraps up — will appear in your idle candidate table within 24 hours, compared to up to 7 days waiting for the next scheduled scan.

10.7 Avoiding the Common Failure Modes

Failure Mode 1: Stopping Read Replicas Without Stopping the Primary

RDS read replicas cannot be stopped independently while their primary is running. Attempting to stop a replica while the primary is available returns an error. The shutdown orchestrator must check whether an instance is a read replica before issuing a stop command, and if so, handle the primary-replica pair together:

def is_read_replica(rds_client, instance_id: str) -> tuple[bool, str]:
    """
    Returns (True, primary_instance_id) if this is a read replica,
    (False, "") otherwise.
    """
    try:
        response = rds_client.describe_db_instances(
            DBInstanceIdentifier=instance_id
        )
        db = response["DBInstances"][0]
        source = db.get("ReadReplicaSourceDBInstanceIdentifier", "")
        if source:
            return True, source
        return False, ""
    except Exception as e:
        log.warning(f"Could not determine replica status for {instance_id}: {e}")
        return False, ""

When the orchestrator encounters a read replica with idle score 4, it should flag the primary for review rather than attempting to stop the replica alone. If both the primary and all its replicas score 4/4, the correct sequence is: stop replicas first (if the primary is also being stopped — though RDS does not allow stopping replicas independently), or more practically, stop the primary, at which point replicas automatically stop receiving replication and will show as stopped as well.

Failure Mode 2: Stopping Saves Compute and License, Not Storage

On RDS for SQL Server with license-included pricing, stopping an instance halts the compute plus the bundled license charge — the biggest line item. But storage, backup retention, and snapshot costs keep accruing. Teams that celebrate the stop action without accounting for residual storage costs overstate their savings:

def estimate_stop_savings(rds_client, instance_id: str,
                          hourly_rate: float) -> dict:
    """Stopping halts compute+license (bundled in LI) but storage keeps billing."""
    resp = rds_client.describe_db_instances(DBInstanceIdentifier=instance_id)
    db = resp["DBInstances"][0]
    allocated_gb = db["AllocatedStorage"]
    # gp3 storage ~$0.115/GB-month; backup retention billed beyond the free window
    storage_monthly = allocated_gb * 0.115
    compute_monthly = hourly_rate * 730
    return {
        "instance_id": instance_id,
        "monthly_compute_license_savings": round(compute_monthly, 2),
        "residual_storage_cost": round(storage_monthly, 2),
        "note": "Terminate (not stop) if the instance will never return; "
                "otherwise the storage tail compounds monthly.",
    }

def stop_sqlserver_instance(rds_client, instance_id: str):
    if DRY_RUN:
        log.info(f"[DRY-RUN] Would stop RDS SQL Server instance: {instance_id}")
        return
    try:
        rds_client.stop_db_instance(DBInstanceIdentifier=instance_id)
        log.info(f"RDS SQL Server instance stop issued: {instance_id}")
    except Exception as e:
        log.error(f"Failed to stop {instance_id}: {e}")

The scan_region function in Section 10.2 should record each instance’s ReadReplicaSourceDBInstanceIdentifier so the orchestrator treats read replicas as independent stop targets: every RDS for SQL Server instance — primary or replica — takes its own stop_db_instance call. Never stop a primary while its replicas are still running without a plan; stop replicas first, then the primary.

Failure Mode 3: Multi-AZ Failover During Shutdown

Stopping a Multi-AZ RDS instance triggers a brief failover as the instance transitions states. For instances tagged Environment=staging or Environment=qa, applications connected at shutdown time will see a brief connection drop. The mitigation is to notify application owners via the SNS topic before acting, with a configurable delay:

import time

def notify_and_wait(sns_client, topic_arn: str, instance_id: str,
                    action: str, delay_minutes: int = 15):
    """
    Sends a pre-action notification and waits the specified delay.
    In production, replace time.sleep with a Step Functions wait state.
    """
    message = (
        f"FinOps Automated Action Pending\n"
        f"Instance : {instance_id}\n"
        f"Action   : {action}\n"
        f"Delay    : {delay_minutes} minutes\n"
        f"To cancel: tag the instance AutoShutdown=false within "
        f"{delay_minutes} minutes."
    )
    sns_client.publish(
        TopicArn=topic_arn,
        Subject=f"[FinOps] Pending {action}: {instance_id}",
        Message=message
    )
    log.info(f"Notification sent. Waiting {delay_minutes} minutes before {action}.")
    time.sleep(delay_minutes * 60)

    # Re-check tags after the delay — owner may have opted out
    return  # Caller re-verifies tags before proceeding

In a production Step Functions workflow, the time.sleep is replaced by a Wait state, which is far more reliable than sleeping inside a Lambda function that may time out.

Failure Mode 4: Snapshots Not Completing Before Deletion Proceeds

When the shutdown orchestrator issues create_db_snapshot and then immediately calls delete_db_instance, the deletion will fail because a snapshot is in progress. The orchestrator must poll for snapshot completion. In a Step Functions workflow, this is a Wait + Choice state loop. In the simple Lambda version, a waiter handles it:

def wait_for_snapshot(rds_client, snapshot_id: str, timeout_minutes: int = 60):
    """
    Polls until the snapshot reaches 'available' status.
    Use a Step Functions Wait state in production instead of polling in Lambda.
    """
    waiter = rds_client.get_waiter("db_snapshot_available")
    log.info(f"Waiting for snapshot {snapshot_id} to complete...")
    try:
        waiter.wait(
            DBSnapshotIdentifier=snapshot_id,
            WaiterConfig={"Delay": 30, "MaxAttempts": timeout_minutes * 2}
        )
        log.info(f"Snapshot complete: {snapshot_id}")
        return True
    except Exception as e:
        log.error(f"Snapshot wait failed for {snapshot_id}: {e}")
        return False

Key Takeaways

  • → **Idle detection requires four signals, not one.** Connection count alone produces false positives due to connection poolers and monitoring agents. Combining DatabaseConnections, CPU utilization, combined IOPS, and network throughput over a 7-day rolling window gives reliable idle candidates with minimal false positives.
  • → **Validate before acting, and validate again at action time.** The detection scan and the shutdown action should both independently verify tag-based exemptions. A tag added between scan time and action time must be respected; defense-in-depth tag checking at both stages prevents unintended shutdowns of newly protected instances.
  • → **Stop and terminate are different tools for different situations.** Stopping preserves the instance for potential restart, saves compute costs, but continues storage billing and auto-restarts after 7 days on AWS. Termination with a final snapshot eliminates all ongoing costs but requires a deliberate recovery process. Match the action to the confidence level: stop for score-3 candidates, terminate only for confirmed decommissions.
  • → **Schedule stop/start for non-production instances rather than relying solely on idle detection.** A database that runs batch jobs unpredictably will evade idle detection during active weeks. Scheduled shutdown during off-hours (evenings, weekends) captures consistent savings without the risk of accidentally stopping a legitimately used instance. Azure SQL Serverless auto-pause handles this automatically without custom scheduling infrastructure.
  • → **Make idle detection continuous, not a one-time exercise.** CloudWatch alarms on CPU thresholds catch newly abandoned instances within 24 hours rather than waiting for a weekly scan. Drift detection queries surface instances that were stopped and restarted, enabling targeted conversations with owners who are manually overriding automation. The ongoing process prevents idle debt from accumulating again after the initial cleanup.
