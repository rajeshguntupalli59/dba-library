Chapter 33: Autonomous SQL Server Systems

SQL Server has long been positioned as an enterprise database that "just works" — but in autonomous systems engineering, "just works" is the floor, not the ceiling. This chapter builds the architecture layer that transforms SQL Server from a managed platform into a self-observing, self-healing, self-optimizing engine. The patterns here treat SQL Server not as a monolithic appliance but as a controllable system with programmable decision surfaces — query store metadata, Dynamic Management Views, Always On Availability Groups, and Azure SQL's autonomy APIs are all levers that can be pulled by code rather than hands. With a deeply integrated observability substrate and a mature HA framework, SQL Server gives you everything an autonomous system needs — and with the right automation layer on top, it reaches full self-management depth.

Treating SQL Server DMVs as a Real-Time Autonomy Sensor Network

Every autonomous system needs a sensor layer — a continuous stream of state signals that drives downstream decisions. SQL Server's Dynamic Management Views (DMVs) are the richest built-in sensor network of any commercial relational database. The challenge at the ADE level is not learning DMVs; it is building a collection pipeline that turns DMV snapshots into time-series signals with enough resolution and history to drive autonomous decision logic.

The core DMVs for autonomous operation form three functional clusters:

Execution health: sys.dm_exec_requests, sys.dm_exec_sessions, sys.dm_os_wait_stats, sys.dm_exec_query_stats

Resource pressure: sys.dm_os_ring_buffers, sys.dm_os_memory_clerks, sys.dm_io_virtual_file_stats, sys.dm_os_performance_counters

Plan and optimizer state: sys.dm_exec_cached_plans, sys.dm_exec_query_plan, sys.query_store_runtime_stats, sys.query_store_plan

The autonomous sensor layer collects these at differential intervals — wait stats at 15-second deltas, query store at 60-second intervals, memory clerks at 30-second intervals. Collecting point-in-time snapshots without computing deltas is one of the most common mistakes in SQL Server observability. sys.dm_os_wait_stats is cumulative since the last service restart; what the decision engine needs is the delta over the collection window.

-- Autonomous wait stats delta collector
-- Run this via a SQL Agent job or external Python scheduler at 15-second intervals

IF OBJECT_ID('tempdb..#wait_baseline', 'U') IS NULL

SELECT
    w.wait_type,
    w.waiting_tasks_count - b.waiting_tasks_count   AS delta_tasks,
    w.wait_time_ms        - b.wait_time_ms           AS delta_wait_ms,
    w.signal_wait_time_ms - b.signal_wait_time_ms    AS delta_signal_ms,

        WHEN (w.wait_time_ms - b.wait_time_ms) = 0 THEN 0
        ELSE CAST((w.signal_wait_time_ms - b.signal_wait_time_ms) AS FLOAT)
           / (w.wait_time_ms - b.wait_time_ms) * 100
    END AS cpu_pressure_pct,
    GETUTCDATE() AS collected_at
FROM sys.dm_os_wait_stats w
JOIN tempdb..#wait_baseline b ON w.wait_type = b.wait_type
WHERE w.wait_time_ms - b.wait_time_ms > 0
ORDER BY delta_wait_ms DESC;

Once delta-aware DMV collection is running, the signals feed into a time-series store — typically Prometheus with a custom SQL Server exporter or a purpose-built Python collector writing to InfluxDB or TimescaleDB. The decision engine then operates against a sliding window of 5–15 minutes of signal history rather than instantaneous reads. A single spike in PAGEIOLATCH_EX waits means nothing; a sustained 10-minute elevation above a learned baseline triggers an I/O investigation workflow.

The autonomous baseline itself deserves careful engineering. Rather than static thresholds, the system learns workload-relative bounds using a rolling percentile window:

import pandas as pd
import numpy as np
from datetime import datetime, timedelta
import pyodbc

class SQLServerWaitBaseline:
    """
    Maintains rolling percentile baselines for SQL Server wait categories.
    Baselines are hour-of-week aware to account for batch vs. OLTP patterns.
    """

    WAIT_CATEGORIES = {
        'CPU':     ['SOS_SCHEDULER_YIELD', 'CXPACKET', 'THREADPOOL'],
        'IO':      ['PAGEIOLATCH_EX', 'PAGEIOLATCH_SH', 'WRITELOG', 'IO_COMPLETION'],
        'LOCK':    ['LCK_M_X', 'LCK_M_S', 'LCK_M_U', 'LCK_M_IX'],
        'MEMORY':  ['RESOURCE_SEMAPHORE', 'RESOURCE_SEMAPHORE_QUERY_COMPILE',
                    'CMEMTHREAD'],
        'NETWORK': ['ASYNC_NETWORK_IO', 'NET_WAITFOR_PACKET'],
    }

    def __init__(self, conn_str: str, lookback_days: int = 14):
        self.conn_str = conn_str
        self.lookback_days = lookback_days

    def fetch_historical_waits(self) -> pd.DataFrame:
        """Pull wait delta history from the collector's persistent store."""
        query = """
            SELECT
                category,
                hour_of_week,
                delta_wait_ms,
                collected_at
            FROM dba.wait_stat_history
            WHERE collected_at >= DATEADD(DAY, -?, GETUTCDATE())
        """
        with pyodbc.connect(self.conn_str) as conn:
            return pd.read_sql(query, conn, params=[self.lookback_days])

    def compute_baselines(self) -> dict:
        df = self.fetch_historical_waits()
        df['hour_of_week'] = pd.to_datetime(df['collected_at']).dt.dayofweek * 24 \
                           + pd.to_datetime(df['collected_at']).dt.hour
        baselines = {}
        for category in self.WAIT_CATEGORIES:
            cat_df = df[df['category'] == category]
            baselines[category] = cat_df.groupby('hour_of_week')['delta_wait_ms'].agg(
                p50=lambda x: np.percentile(x, 50),
                p95=lambda x: np.percentile(x, 95),
                p99=lambda x: np.percentile(x, 99),
            ).to_dict('index')
        return baselines

    def is_anomalous(self, category: str, current_ms: float,
                     hour_of_week: int, threshold_pct: float = 95.0) -> bool:
        baselines = self.compute_baselines()
        if category not in baselines or hour_of_week not in baselines[category]:
            return False
        p95 = baselines[category][hour_of_week]['p95']
        return current_ms > p95

The output of this sensor network is not alerts — alerts are the human path. The output is structured decision events that flow to the autonomy controller described in later subparts.

Query Store as the Autonomous Query Governor

Query Store is SQL Server's most underutilized autonomous control surface. Most teams use it reactively — they open SSMS, look at the "Top Resource Consuming Queries" report, and manually force a plan. That is precisely the workflow that autonomous systems are designed to replace. At the ADE level, Query Store becomes a continuously monitored decision substrate where the system detects plan regressions, validates alternative plans, and forces or unforces them without a human in the loop.

The autonomous query governance loop has four stages:

1. Regression detection — identify queries where the latest execution plan performs materially worse than the best known plan for the same query hash.

2. Impact scoring — rank regressions by total elapsed time impact, not just per-execution cost.

3. Validation — before forcing a plan, verify the "best" plan is still valid given current statistics.

4. Remediation — force the plan or escalate to an index-change workflow if no valid plan exists.

-- Autonomous plan regression detector
-- Identifies queries where active plan is >2x worse than best known plan
-- weighted by execution frequency over the last 2 hours

WITH recent_stats AS (
    SELECT
        qsq.query_id,
        qsq.query_hash,
        qsp.plan_id,
        qsp.is_forced_plan,
        SUM(qsrs.count_executions)                    AS exec_count,
        AVG(qsrs.avg_duration)                        AS avg_duration_us,
        AVG(qsrs.avg_cpu_time)                        AS avg_cpu_us,
        AVG(qsrs.avg_logical_io_reads)                AS avg_logical_reads,
        SUM(qsrs.count_executions * qsrs.avg_duration) AS total_elapsed_us,
        MAX(qsrs.last_execution_time)                 AS last_exec
    FROM sys.query_store_query         qsq
    JOIN sys.query_store_plan          qsp  ON qsq.query_id  = qsp.query_id
    JOIN sys.query_store_runtime_stats qsrs ON qsp.plan_id   = qsrs.plan_id
    JOIN sys.query_store_runtime_stats_interval qsrsi
                                             ON qsrs.runtime_stats_interval_id
                                              = qsrsi.runtime_stats_interval_id
    WHERE qsrsi.start_time >= DATEADD(HOUR, -2, GETUTCDATE())
    GROUP BY qsq.query_id, qsq.query_hash, qsp.plan_id, qsp.is_forced_plan
),
best_plan AS (
    SELECT
        query_id,
        MIN(avg_duration_us) AS best_avg_duration_us,
        MIN(avg_logical_reads) AS best_avg_logical_reads
    FROM recent_stats
    GROUP BY query_id
),
active_plan AS (
    -- The plan with the most recent execution for each query
    SELECT rs.*
    FROM recent_stats rs
    WHERE rs.last_exec = (
        SELECT MAX(rs2.last_exec)
        FROM recent_stats rs2
        WHERE rs2.query_id = rs.query_id
    )
)
SELECT
    ap.query_id,
    ap.plan_id                              AS active_plan_id,
    ap.is_forced_plan,
    ap.avg_duration_us                      AS active_avg_duration_us,
    bp.best_avg_duration_us,
    CAST(ap.avg_duration_us AS FLOAT)
        / NULLIF(bp.best_avg_duration_us,0) AS regression_ratio,
    ap.exec_count,
    ap.total_elapsed_us / 1000.0            AS total_elapsed_ms,
    -- Find the best plan_id for forcing
    (SELECT TOP 1 rs3.plan_id
     FROM recent_stats rs3
     WHERE rs3.query_id = ap.query_id
       AND rs3.avg_duration_us = bp.best_avg_duration_us) AS best_plan_id,
    GETUTCDATE()                            AS detected_at
FROM active_plan ap
JOIN best_plan   bp ON ap.query_id = bp.query_id
WHERE CAST(ap.avg_duration_us AS FLOAT)
        / NULLIF(bp.best_avg_duration_us,0) > 2.0   -- regression threshold
  AND ap.exec_count > 10                             -- statistical significance
  AND bp.best_avg_duration_us > 1000                -- ignore sub-millisecond queries
  AND ap.is_forced_plan = 0                          -- not already managed
ORDER BY total_elapsed_ms DESC;

The Python controller that acts on this output handles the force/unforce decision with a guard rail: before forcing any plan, it verifies that statistics on referenced objects are not stale beyond a threshold. Forcing an old plan against severely outdated statistics produces a different kind of regression.

import pyodbc
import logging
from dataclasses import dataclass
from typing import Optional
from datetime import datetime

logger = logging.getLogger('autonomous_qg')

@dataclass
class PlanRegression:
    query_id: int
    active_plan_id: int
    best_plan_id: int
    regression_ratio: float
    total_elapsed_ms: float
    detected_at: datetime

class AutonomousQueryGovernor:
    """
    Detects Query Store plan regressions and autonomously forces the best
    known plan after validating statistics freshness.
    """

    STATS_STALENESS_HOURS = 24
    MAX_AUTO_FORCE_RATIO  = 10.0   # Don't auto-force if regression > 10x (likely different workload)
    MIN_ELAPSED_MS        = 5000   # Only act if total impact > 5 seconds in window

    def __init__(self, conn_str: str, dry_run: bool = False):
        self.conn_str = conn_str
        self.dry_run  = dry_run

    def _conn(self):
        return pyodbc.connect(self.conn_str, autocommit=True)

    def detect_regressions(self) -> list[PlanRegression]:
        regression_sql = open('regression_detection.sql').read()  # The query above
        with self._conn() as conn:
            cursor = conn.cursor()
            cursor.execute(regression_sql)
            return [
                PlanRegression(
                    query_id        = row.query_id,
                    active_plan_id  = row.active_plan_id,
                    best_plan_id    = row.best_plan_id,
                    regression_ratio= row.regression_ratio,
                    total_elapsed_ms= row.total_elapsed_ms,
                    detected_at     = row.detected_at
                )
                for row in cursor.fetchall()
            ]

    def validate_stats_freshness(self, query_id: int) -> bool:
        """
        Check that all tables referenced by the best plan have stats
        updated within the staleness threshold.
        """
        sql = """
            SELECT COUNT(*) AS stale_count
            FROM sys.query_store_query_text qt
            JOIN sys.query_store_query      q  ON qt.query_text_id = q.query_text_id
            -- parse referenced objects and check sys.stats / sys.stats_columns
            -- simplified: check overall DB stats freshness as a proxy
            CROSS APPLY (
                SELECT COUNT(*) AS stale
                FROM sys.stats s
                JOIN sys.objects o ON s.object_id = o.object_id
                WHERE o.type = 'U'
                  AND STATS_DATE(s.object_id, s.stats_id) < DATEADD(
                      HOUR, -?, GETUTCDATE())
                  AND s.auto_created = 1
            ) stale_check
            WHERE q.query_id = ?
              AND stale_check.stale > 0
        """
        with self._conn() as conn:
            cursor = conn.cursor()
            cursor.execute(sql, [self.STATS_STALENESS_HOURS, query_id])
            row = cursor.fetchone()
            return row.stale_count == 0

    def force_plan(self, query_id: int, plan_id: int) -> bool:
        sql = "EXEC sys.sp_query_store_force_plan @query_id=?, @plan_id=?"
        try:
            if not self.dry_run:
                with self._conn() as conn:
                    conn.cursor().execute(sql, [query_id, plan_id])
            logger.info(
                "PLAN_FORCED query_id=%d plan_id=%d dry_run=%s",
                query_id, plan_id, self.dry_run
            )
            return True
        except Exception as e:
            logger.error("PLAN_FORCE_FAILED query_id=%d error=%s", query_id, e)
            return False

    def run_cycle(self):
        regressions = self.detect_regressions()
        logger.info("CYCLE_START detected_regressions=%d", len(regressions))

        for reg in regressions:
            if reg.regression_ratio > self.MAX_AUTO_FORCE_RATIO:
                logger.warning(
                    "ESCALATE_HUMAN query_id=%d ratio=%.1f "
                    "(exceeds autonomous threshold)",
                    reg.query_id, reg.regression_ratio
                )
                continue

            if reg.total_elapsed_ms < self.MIN_ELAPSED_MS:
                logger.debug(
                    "SKIP_LOW_IMPACT query_id=%d elapsed_ms=%.0f",
                    reg.query_id, reg.total_elapsed_ms
                )
                continue

            if not self.validate_stats_freshness(reg.query_id):
                logger.warning(
                    "STATS_STALE query_id=%d — triggering stats update first",
                    reg.query_id
                )
                # Emit a stats update work item to the autonomy queue
                # rather than forcing the plan
                continue

            self.force_plan(reg.query_id, reg.best_plan_id)

The same loop runs in reverse: when a forced plan itself starts regressing (because data distribution shifted and the forced plan is no longer optimal), the system unforces it and lets the optimizer replan. This bidirectional governance is what separates autonomous query management from the one-directional manual interventions most teams perform.

Automatic plan correction — introduced in SQL Server 2017 as a Database Compatibility feature — provides a native version of this loop. Enabling it is a prerequisite, but it is not sufficient for full autonomy because its correction logic is binary (force or don't) and does not participate in a broader decision pipeline. The ADE builds on top of it, using sys.dm_db_tuning_recommendations as an additional signal source:

-- Surface the native engine's own tuning recommendations
-- Use these as pre-validated signals in the autonomous decision pipeline

SELECT
    name,
    type,
    reason,
    score,
    JSON_VALUE(details, '$.implementationDetails.script') AS recommended_action,
    JSON_VALUE(details, '$.planForceDetails.queryId')     AS affected_query_id,
    JSON_VALUE(details, '$.planForceDetails.regressedPlanId')
                                                          AS regressed_plan_id,
    JSON_VALUE(details, '$.planForceDetails.forcedPlanId')
                                                          AS recommended_plan_id,
    valid_since,
    last_refresh
FROM sys.dm_db_tuning_recommendations
WHERE state = JSON_VALUE(state, '$.currentValue')  -- active recommendations only
  AND score > 30                                    -- confidence threshold
ORDER BY score DESC;

Always On Availability Groups: Autonomous Failover and Replica Management

Always On Availability Groups are SQL Server's primary HA mechanism, but the default configuration places humans at the center of decisions that should be automated: when to fail over, when to promote a secondary, when to redirect read workloads, and when to suspend data movement to a lagging replica. The autonomous architecture eliminates those human decision points.

The autonomy surface for AG management has three layers. The first is the Windows Server Failover Cluster (WSFC) or Pacemaker layer, which handles the low-level quorum and node fencing decisions. The second is the SQL Server AG health detection layer — sys.dm_hadr_availability_group_states, sys.dm_hadr_database_replica_states, sys.dm_hadr_availability_replica_states. The third is the application-level routing layer, which manages connection routing independently of what the AG itself reports.

For environments running Always On across Azure VMs or on-premises with Pacemaker on Linux, the autonomous controller monitors redo queue depth as a leading indicator of failover risk. A secondary with a growing redo queue that is not catching up indicates either an I/O-bound secondary or a network partition that will worsen before it improves.

-- AG replica health monitor for autonomous controller
-- Collects redo queue, send queue, and synchronization state per replica

SELECT
    ag.name                                     AS ag_name,
    ar.replica_server_name,
    ar.availability_mode_desc,
    ar.failover_mode_desc,
    drs.database_name,
    drs.synchronization_state_desc,
    drs.synchronization_health_desc,
    drs.redo_queue_size                         AS redo_queue_kb,
    drs.redo_rate                               AS redo_rate_kb_per_sec,
    CASE
        WHEN drs.redo_rate > 0
        THEN drs.redo_queue_size / drs.redo_rate
        ELSE NULL
    END                                         AS estimated_catchup_secs,
    drs.log_send_queue_size                     AS send_queue_kb,
    drs.log_send_rate                           AS send_rate_kb_per_sec,
    drs.last_redone_time,
    drs.last_received_time,
    ars.role_desc,
    ars.connected_state_desc,
    ars.operational_state_desc,
    GETUTCDATE()                                AS sampled_at
FROM sys.availability_groups ag
JOIN sys.availability_replicas ar
    ON ag.group_id = ar.group_id
JOIN sys.dm_hadr_availability_replica_states ars
    ON ar.replica_id = ars.replica_id
JOIN sys.dm_hadr_database_replica_states drs
    ON ar.replica_id = drs.replica_id
ORDER BY ag.name, ar.replica_server_name, drs.database_name;

The Python autonomous AG controller acts on this data in two modes: watchdog mode (continuous monitoring with corrective actions short of failover) and failover arbitration mode (triggered only when the primary is confirmed unhealthy).

import pyodbc
import logging
import time
from dataclasses import dataclass, field
from typing import Optional
from datetime import datetime, timedelta
from enum import Enum

logger = logging.getLogger('autonomous_ag')

class ReplicaHealth(Enum):
    HEALTHY    = 'HEALTHY'
    DEGRADED   = 'DEGRADED'
    CRITICAL   = 'CRITICAL'
    UNREACHABLE= 'UNREACHABLE'

@dataclass
class ReplicaState:
    ag_name: str
    replica_server_name: str
    availability_mode: str
    failover_mode: str
    database_name: str
    sync_state: str
    sync_health: str
    redo_queue_kb: Optional[float]
    redo_rate_kb_per_sec: Optional[float]
    estimated_catchup_secs: Optional[float]
    send_queue_kb: Optional[float]
    role: str
    connected_state: str
    operational_state: str
    sampled_at: datetime

    @property
    def health(self) -> ReplicaHealth:
        if self.connected_state != 'CONNECTED' or self.operational_state != 'ONLINE':
            return ReplicaHealth.UNREACHABLE
        if self.sync_health == 'NOT_HEALTHY':
            return ReplicaHealth.CRITICAL
        if self.sync_health == 'PARTIALLY_HEALTHY':
            return ReplicaHealth.DEGRADED
        # Redo queue growing faster than it drains — degraded signal
        if (self.redo_queue_kb is not None
                and self.estimated_catchup_secs is not None
                and self.estimated_catchup_secs > 300):        # 5 minutes behind
            return ReplicaHealth.DEGRADED
        return ReplicaHealth.HEALTHY


class AutonomousAGController:
    """
    Watchdog and arbitration controller for SQL Server Always On AGs.
    Operates in watchdog mode continuously; escalates to failover arbitration
    only after quorum of health checks confirms primary failure.
    """

    REDO_QUEUE_WARN_KB    = 512 * 1024   # 512 MB redo lag triggers warning
    REDO_QUEUE_SUSPEND_KB = 2 * 1024 * 1024  # 2 GB lag triggers data movement review
    FAILOVER_CONFIRM_CYCLES = 3          # Primary must fail N consecutive cycles
    CYCLE_INTERVAL_SECS   = 15

    def __init__(self, primary_conn_str: str,
                 secondary_conn_strs: dict[str, str],
                 dry_run: bool = False):
        self.primary_conn_str     = primary_conn_str
        self.secondary_conn_strs  = secondary_conn_strs
        self.dry_run              = dry_run
        self._primary_fail_count  = 0
        self._last_failover_time: Optional[datetime] = None

    def _conn(self, conn_str: str):
        return pyodbc.connect(conn_str, timeout=5, autocommit=True)

    def collect_replica_states(self, conn_str: str) -> list[ReplicaState]:
        sql = open('ag_health_monitor.sql').read()   # The query above
        try:
            with self._conn(conn_str) as conn:
                cursor = conn.cursor()
                cursor.execute(sql)
                rows = cursor.fetchall()
                return [ReplicaState(
                    ag_name=r.ag_name,
                    replica_server_name=r.replica_server_name,
                    availability_mode=r.availability_mode_desc,
                    failover_mode=r.failover_mode_desc,
                    database_name=r.database_name,
                    sync_state=r.synchronization_state_desc,
                    sync_health=r.synchronization_health_desc,
                    redo_queue_kb=r.redo_queue_kb,
                    redo_rate_kb_per_sec=r.redo_rate_kb_per_sec,
                    estimated_catchup_secs=r.estimated_catchup_secs,
                    send_queue_kb=r.send_queue_kb,
                    role=r.role_desc,
                    connected_state=r.connected_state_desc,
                    operational_state=r.operational_state_desc,
                    sampled_at=r.sampled_at,
                ) for r in rows]
        except Exception as e:
            logger.error("REPLICA_COLLECT_FAILED conn=%s error=%s", conn_str, e)
            return []

    def check_primary_reachable(self) -> bool:
        try:
            with self._conn(self.primary_conn_str) as conn:
                conn.cursor().execute("SELECT 1")
            return True
        except Exception:
            return False

    def handle_lagging_replica(self, state: ReplicaState):
        """
        When a synchronous secondary lags beyond REDO_QUEUE_WARN_KB,
        evaluate whether to temporarily change it to asynchronous mode
        to protect primary throughput — a reversible, safe corrective action.
        """
        if state.redo_queue_kb is None:
            return

        if state.redo_queue_kb > self.REDO_QUEUE_WARN_KB:
            logger.warning(
                "REPLICA_LAG ag=%s replica=%s db=%s redo_queue_kb=%.0f "
                "catchup_secs=%s",
                state.ag_name, state.replica_server_name, state.database_name,
                state.redo_queue_kb,
                f"{state.estimated_catchup_secs:.0f}"
                    if state.estimated_catchup_secs else "unknown"
            )

        if (state.redo_queue_kb > self.REDO_QUEUE_SUSPEND_KB
                and state.availability_mode == 'SYNCHRONOUS_COMMIT'
                and not self.dry_run):
            # Switching to async protects primary commit latency while
            # the secondary catches up; schedule a reversion check
            logger.warning(
                "ASYNC_DOWNGRADE ag=%s replica=%s — redo queue critical",
                state.ag_name, state.replica_server_name
            )
            self._change_replica_mode(
                state.ag_name, state.replica_server_name, 'ASYNCHRONOUS_COMMIT'
            )

    def _change_replica_mode(self, ag_name: str, replica_name: str, mode: str):
        sql = f"""
            ALTER AVAILABILITY GROUP [{ag_name}]
            MODIFY REPLICA ON N'{replica_name}'
            WITH (AVAILABILITY_MODE = {mode})
        """
        try:
            with self._conn(self.primary_conn_str) as conn:
                conn.cursor().execute(sql)
            logger.info(
                "REPLICA_MODE_CHANGED ag=%s replica=%s mode=%s",
                ag_name, replica_name, mode
            )
        except Exception as e:
            logger.error(
                "REPLICA_MODE_CHANGE_FAILED ag=%s replica=%s error=%s",
                ag_name, replica_name, e
            )

    def initiate_failover(self, target_replica: str, ag_name: str):
        """
        Initiates a manual failover to a specific secondary.
        Only called after FAILOVER_CONFIRM_CYCLES of confirmed primary failure
        and only if the target has MANUAL or AUTOMATIC failover mode configured.
        """
        # Enforce a minimum interval between autonomous failovers
        if (self._last_failover_time is not None
                and datetime.utcnow() - self._last_failover_time
                    < timedelta(minutes=30)):
            logger.error(
                "FAILOVER_THROTTLED — last failover was less than 30 minutes ago"
            )
            return

        sql = f"ALTER AVAILABILITY GROUP [{ag_name}] FAILOVER"
        conn_str = self.secondary_conn_strs.get(target_replica)
        if not conn_str:
            logger.error("FAILOVER_NO_CONN_STR replica=%s", target_replica)
            return

        logger.critical(
            "FAILOVER_INITIATED ag=%s target=%s dry_run=%s",
            ag_name, target_replica, self.dry_run
        )
        if not self.dry_run:
            try:
                with self._conn(conn_str) as conn:
                    conn.cursor().execute(sql)
                self._last_failover_time = datetime.utcnow()
            except Exception as e:
                logger.error("FAILOVER_FAILED ag=%s error=%s", ag_name, e)

    def select_best_failover_target(
            self, states: list[ReplicaState]) -> Optional[tuple[str, str]]:
        """
        Among synchronous secondaries, pick the one with the smallest
        redo queue (closest to primary). Returns (replica_name, ag_name).
        """
        candidates = [
            s for s in states
            if s.role == 'SECONDARY'
            and s.availability_mode == 'SYNCHRONOUS_COMMIT'
            and s.health != ReplicaHealth.UNREACHABLE
        ]
        if not candidates:
            return None
        best = min(candidates,
                   key=lambda s: s.redo_queue_kb or float('inf'))
        return (best.replica_server_name, best.ag_name)

    def run_watchdog(self):
        """Main watchdog loop. Runs indefinitely."""
        logger.info("WATCHDOG_START primary=%s", self.primary_conn_str)
        while True:
            primary_up = self.check_primary_reachable()

            if not primary_up:
                self._primary_fail_count += 1
                logger.warning(
                    "PRIMARY_UNREACHABLE consecutive_failures=%d",
                    self._primary_fail_count
                )
                if self._primary_fail_count >= self.FAILOVER_CONFIRM_CYCLES:
                    # Collect state from a secondary to identify best target
                    for name, conn_str in self.secondary_conn_strs.items():
                        states = self.collect_replica_states(conn_str)
                        if states:
                            target = self.select_best_failover_target(states)
                            if target:
                                self.initiate_failover(*target)
                            break
            else:
                self._primary_fail_count = 0
                states = self.collect_replica_states(self.primary_conn_str)
                for state in states:
                    if state.role == 'SECONDARY':
                        self.handle_lagging_replica(state)

            time.sleep(self.CYCLE_INTERVAL_SECS)

One detail that trips up many implementations: the ALTER AVAILABILITY GROUP ... FAILOVER statement must be issued from the target secondary, not from the primary. The controller connects to the secondary's connection string for the failover command, which is why secondary_conn_strs is a required parameter rather than being derived from DMV data.

For environments using the Windows Server Failover Cluster layer, automatic failover for AUTOMATIC failover mode replicas is already handled by WSFC without any application-layer code. The Python controller above is designed for scenarios where WSFC automatic failover is not in play — Linux HA clusters, Azure environments using a load balancer listener without WSFC, or configurations where the DBA team wants application-layer override capability above the WSFC decision.

Intelligent Connection Routing and Read-Scale Autonomy

Availability Groups introduce multiple replicas that can serve read traffic, but the default routing behavior — round-robin across read-only routing lists — is static. An autonomous routing layer adjusts replica selection based on replica health, redo lag, and current replica load in real time.

SQL Server's built-in read-only routing is configured via PRIMARY_ROLE and SECONDARY_ROLE routing lists on availability replicas. The autonomous layer supplements this with a routing proxy that re-evaluates replica suitability at connection time.

SQL Server — configuring the read-only routing foundation:

-- Run on the primary

MODIFY REPLICA ON N'SQLNODE2'
WITH (
    SECONDARY_ROLE (
        ALLOW_CONNECTIONS = READ_ONLY,
        READ_ONLY_ROUTING_URL = N'TCP://sqlnode2.corp.local:1433'
    )
);

ALTER AVAILABILITY GROUP [ProductionAG]
MODIFY REPLICA ON N'SQLNODE3'
WITH (
    SECONDARY_ROLE (
        ALLOW_CONNECTIONS = READ_ONLY,
        READ_ONLY_ROUTING_URL = N'TCP://sqlnode3.corp.local:1433'
    )
);

-- Set routing list on primary: prefer SQLNODE2, fall back to SQLNODE3
ALTER AVAILABILITY GROUP [ProductionAG]
MODIFY REPLICA ON N'SQLNODE1'
WITH (
    PRIMARY_ROLE (
        READ_ONLY_ROUTING_LIST = (
            ('SQLNODE2', 'SQLNODE3')  -- load-balanced pair
        )
    )
);

The autonomous routing controller wraps the connection acquisition logic in Python, scoring each replica before assigning a connection:

from dataclasses import dataclass
from typing import Optional
import pyodbc
import threading
import time

@dataclass
class ReplicaScore:
    name: str
    conn_str: str
    redo_lag_kb: float
    active_sessions: int
    avg_wait_ms: float
    is_healthy: bool

    @property
    def score(self) -> float:
        """Lower score is better. Combines lag, load, and wait pressure."""
        if not self.is_healthy:
            return float('inf')
        # Normalize each component to a 0–100 scale before weighting
        lag_score     = min(self.redo_lag_kb / 10_000, 100)   # cap at 10 GB equiv
        load_score    = min(self.active_sessions / 200, 100)   # cap at 200 sessions
        wait_score    = min(self.avg_wait_ms / 500, 100)       # cap at 500ms avg wait
        return (lag_score * 0.4) + (load_score * 0.35) + (wait_score * 0.25)


class AutonomousReadRouter:
    """
    Scores AG read replicas and routes read connections to the best
    available secondary. Thread-safe; refreshes scores at a configurable interval.
    """

    SCORE_REFRESH_SECS = 10

    def __init__(self, replica_configs: dict[str, str]):
        """
        replica_configs: {replica_name: connection_string}
        """
        self.replica_configs = replica_configs
        self._scores: list[ReplicaScore] = []
        self._lock   = threading.Lock()
        self._refresh_thread = threading.Thread(
            target=self._background_refresh, daemon=True
        )
        self._refresh_thread.start()

    def _score_replica(self, name: str, conn_str: str) -> ReplicaScore:
        try:
            with pyodbc.connect(conn_str, timeout=3) as conn:
                cursor = conn.cursor()
                # Redo lag for this replica
                cursor.execute("""
                    SELECT
                        ISNULL(SUM(redo_queue_size), 0) AS redo_lag_kb
                    FROM sys.dm_hadr_database_replica_states
                    WHERE is_local = 1
                """)
                redo_lag_kb = cursor.fetchone().redo_lag_kb or 0.0

                # Active session count
                cursor.execute("""
                    SELECT COUNT(*) AS session_count
                    FROM sys.dm_exec_sessions
                    WHERE is_user_process = 1
                """)
                active_sessions = cursor.fetchone().session_count or 0

                # Average wait time from recent wait stats
                cursor.execute("""
                    SELECT
                        ISNULL(
                            SUM(wait_time_ms) * 1.0 /
                            NULLIF(SUM(waiting_tasks_count), 0),
                        0) AS avg_wait_ms
                    FROM sys.dm_os_wait_stats
                    WHERE wait_type NOT IN (
                        'SLEEP_TASK', 'WAITFOR', 'XE_TIMER_EVENT',
                        'BROKER_TO_FLUSH', 'REQUEST_FOR_DEADLOCK_MONITOR'
                    )
                """)
                avg_wait_ms = cursor.fetchone().avg_wait_ms or 0.0

                return ReplicaScore(
                    name=name, conn_str=conn_str,
                    redo_lag_kb=redo_lag_kb,
                    active_sessions=active_sessions,
                    avg_wait_ms=avg_wait_ms,
                    is_healthy=True
                )
        except Exception:
            return ReplicaScore(
                name=name, conn_str=conn_str,
                redo_lag_kb=float('inf'), active_sessions=0,
                avg_wait_ms=0.0, is_healthy=False
            )

    def _background_refresh(self):
        while True:
            scores = [
                self._score_replica(name, conn_str)
                for name, conn_str in self.replica_configs.items()
            ]
            with self._lock:
                self._scores = sorted(scores, key=lambda s: s.score)
            time.sleep(self.SCORE_REFRESH_SECS)

    def get_read_connection(self) -> Optional[pyodbc.Connection]:
        """Returns a connection to the best available read replica."""
        with self._lock:
            candidates = [s for s in self._scores if s.is_healthy]
        if not candidates:
            raise RuntimeError("No healthy read replicas available")
        best = candidates[0]
        return pyodbc.connect(best.conn_str)

The routing layer deliberately keeps the scoring logic transparent and overridable. When a replica enters a planned maintenance window — index rebuilds, DBCC CHECKDB, or backup operations — the autonomous maintenance scheduler (described in the next subpart) posts a REPLICA_MAINTENANCE event that temporarily sets that replica's health flag to False, pulling it out of the routing pool without requiring any network-level change.

Autonomous Index and Statistics Management

SQL Server's built-in maintenance plans and Ola Hallengren's maintenance solution are both schedule-driven rather than condition-driven. Autonomous index management replaces the schedule with a continuous assessment loop: collect fragmentation state, score rebuild vs. reorganize decisions by impact and available maintenance window, and execute within cost guardrails.

The core signal is sys.dm_db_index_physical_stats, but querying it directly in SAMPLED mode at scale has a non-trivial I/O cost. The autonomous collector uses a tiered scan strategy: small tables are scanned nightly in DETAILED mode; large tables use LIMITED mode daily with DETAILED mode deferred to weekly off-peak windows.

-- Autonomous index fragmentation assessment with tiered scan mode
-- Returns actionable rows with recommended operation and estimated cost

SELECT
    OBJECT_SCHEMA_NAME(ips.object_id)   AS schema_name,
    OBJECT_NAME(ips.object_id)          AS table_name,
    i.name                              AS index_name,
    ips.index_id,
    ips.index_type_desc,
    ips.avg_fragmentation_in_percent,
    ips.page_count,
    ips.record_count,
    ips.avg_page_space_used_in_percent,
    -- Decide operation based on fragmentation and page count
    CASE
        WHEN ips.page_count < 1000
            THEN 'SKIP'            -- too small to matter
        WHEN ips.avg_fragmentation_in_percent < 5
            THEN 'SKIP'
        WHEN ips.avg_fragmentation_in_percent BETWEEN 5 AND 30
            THEN 'REORGANIZE'
        ELSE 'REBUILD'
    END                                 AS recommended_op,
    -- Rough rebuild cost estimate: pages * avg_page_size_kb
    ips.page_count * 8 / 1024.0        AS estimated_mb,
    GETUTCDATE()                        AS assessed_at
FROM sys.dm_db_index_physical_stats(
    DB_ID(), NULL, NULL, NULL, 'SAMPLED'
) ips
JOIN sys.indexes i
    ON ips.object_id = i.object_id
    AND ips.index_id = i.index_id
WHERE i.index_id > 0          -- exclude heap scans
  AND ips.page_count > 100    -- minimum page threshold
ORDER BY ips.avg_fragmentation_in_percent DESC, ips.page_count DESC;

The Python autonomous index manager wraps the assessment with an execution budget: it tracks total I/O and lock time consumed during a maintenance window and stops before the window closes, persisting remaining work for the next cycle.

import pyodbc
import logging
import time
from dataclasses import dataclass
from typing import Iterator
from datetime import datetime, timedelta

logger = logging.getLogger('autonomous_index')

@dataclass
class IndexAction:
    schema_name: str
    table_name: str
    index_name: str
    index_id: int
    recommended_op: str      # 'REBUILD' | 'REORGANIZE' | 'SKIP'
    estimated_mb: float
    avg_fragmentation: float
    page_count: int

class AutonomousIndexManager:
    """
    Condition-driven index maintenance for SQL Server.
    Executes within a time and I/O budget, yielding gracefully if
    the maintenance window closes.
    """

    REBUILD_ONLINE_THRESHOLD_MB  = 50_000  # Tables > 50 GB: prefer ONLINE rebuild
    REORG_FRAG_MIN               = 5.0
    REBUILD_FRAG_MIN             = 30.0
    DEFAULT_WINDOW_MINUTES       = 120

    def __init__(self, conn_str: str, dry_run: bool = False,
                 window_minutes: int = DEFAULT_WINDOW_MINUTES):
        self.conn_str       = conn_str
        self.dry_run        = dry_run
        self.window_end     = datetime.utcnow() + timedelta(minutes=window_minutes)

    def _conn(self):
        return pyodbc.connect(self.conn_str, autocommit=True)

    def _within_window(self) -> bool:
        return datetime.utcnow() < self.window_end

    def assess(self) -> list[IndexAction]:
        sql = open('index_fragmentation_assessment.sql').read()
        with self._conn() as conn:
            cursor = conn.cursor()
            cursor.execute(sql)
            return [
                IndexAction(
                    schema_name=r.schema_name,
                    table_name=r.table_name,
                    index_name=r.index_name,
                    index_id=r.index_id,
                    recommended_op=r.recommended_op,
                    estimated_mb=r.estimated_mb,
                    avg_fragmentation=r.avg_fragmentation_in_percent,
                    page_count=r.page_count,
                )
                for r in cursor.fetchall()
                if r.recommended_op != 'SKIP'
            ]

    def _build_maintenance_sql(self, action: IndexAction) -> str:
        fq_table = f"[{action.schema_name}].[{action.table_name}]"
        index    = f"[{action.index_name}]"

        if action.recommended_op == 'REORGANIZE':
            return (
                f"ALTER INDEX {index} ON {fq_table} "
                f"REORGANIZE"
            )
        elif action.recommended_op == 'REBUILD':
            online = (action.estimated_mb > self.REBUILD_ONLINE_THRESHOLD_MB
                      and self._is_enterprise_edition())
            online_clause = "WITH (ONLINE = ON, MAXDOP = 4)" if online \
                            else "WITH (MAXDOP = 4)"
            return (
                f"ALTER INDEX {index} ON {fq_table} "
                f"REBUILD {online_clause}"
            )
        raise ValueError(f"Unknown op: {action.recommended_op}")

    def _is_enterprise_edition(self) -> bool:
        with self._conn() as conn:
            cursor = conn.cursor()
            cursor.execute(
                "SELECT SERVERPROPERTY('EngineEdition') AS edition"
            )
            return cursor.fetchone().edition == 3   # 3 = Enterprise

    def execute_maintenance(self, actions: list[IndexAction]):
        # Sort: reorganize first (lower locking cost), then rebuild by size asc
        sorted_actions = sorted(
            actions,
            key=lambda a: (0 if a.recommended_op == 'REORGANIZE' else 1,
                           a.estimated_mb)
        )

        completed = 0
        skipped   = 0

        for action in sorted_actions:
            if not self._within_window():
                logger.info(
                    "WINDOW_CLOSED completed=%d skipped=%d remaining=%d",
                    completed, skipped, len(sorted_actions) - completed - skipped
                )
                break

            sql = self._build_maintenance_sql(action)
            logger.info(
                "INDEX_MAINT op=%s table=%s.%s index=%s frag=%.1f%% est_mb=%.0f",
                action.recommended_op, action.schema_name,
                action.table_name, action.index_name,
                action.avg_fragmentation, action.estimated_mb
            )

            if not self.dry_run:
                try:
                    start = time.monotonic()
                    with self._conn() as conn:
                        conn.cursor().execute(sql)
                    elapsed = time.monotonic() - start
                    logger.info(
                        "INDEX_MAINT_DONE elapsed_secs=%.1f", elapsed
                    )
                    completed += 1
                except Exception as e:
                    logger.error(
                        "INDEX_MAINT_FAILED table=%s.%s index=%s error=%s",
                        action.schema_name, action.table_name,
                        action.index_name, e
                    )
                    skipped += 1
            else:
                completed += 1

        logger.info(
            "MAINTENANCE_CYCLE_END completed=%d skipped=%d",
            completed, skipped
        )

    def run_cycle(self):
        actions = self.assess()
        logger.info("ASSESSMENT_COMPLETE actionable_indexes=%d", len(actions))
        self.execute_maintenance(actions)

Statistics management follows the same pattern. The autonomous stats controller evaluates modification counters from sys.dm_db_stats_properties against a density-aware threshold — tables with highly skewed distributions need stats updated at a lower modification threshold than uniform distributions, because the optimizer's cardinality estimates degrade faster on skewed data.

-- Autonomous statistics staleness assessment
-- Uses modification counter relative to table size + density proxy

SELECT
    OBJECT_SCHEMA_NAME(s.object_id)     AS schema_name,
    OBJECT_NAME(s.object_id)            AS table_name,
    s.name                              AS stats_name,
    sp.last_updated,
    sp.rows,
    sp.rows_sampled,
    sp.modification_counter,
    -- Dynamic threshold: smaller tables need proportionally more sensitivity
    CASE
        WHEN sp.rows < 500             THEN 500
        WHEN sp.rows < 25000           THEN CAST(sp.rows * 0.20 AS INT)
        ELSE CAST(500 + sp.rows * 0.02 AS INT)   -- sub-linear heuristic for large tables;
                                                   -- tune against your own workload rather
                                                   -- than treating this as an engine default
    END                                 AS update_threshold,
    CASE
        WHEN sp.modification_counter >= CASE
            WHEN sp.rows < 500         THEN 500
            WHEN sp.rows < 25000       THEN CAST(sp.rows * 0.20 AS INT)
            ELSE CAST(500 + sp.rows * 0.02 AS INT)
        END
        THEN 'UPDATE_STATS'
        ELSE 'SKIP'
    END                                 AS recommended_op,
    DATEDIFF(HOUR, sp.last_updated, GETUTCDATE()) AS hours_since_update
FROM sys.stats s
CROSS APPLY sys.dm_db_stats_properties(s.object_id, s.stats_id) sp
JOIN sys.objects o ON s.object_id = o.object_id
WHERE o.type = 'U'                 -- user tables only
  AND sp.rows > 0
  AND (
      sp.last_updated < DATEADD(DAY, -1, GETUTCDATE())  -- always refresh daily at minimum
      OR sp.modification_counter >= CASE
          WHEN sp.rows < 500         THEN 500
          WHEN sp.rows < 25000       THEN CAST(sp.rows * 0.20 AS INT)
          ELSE CAST(500 + sp.rows * 0.02 AS INT)
      END
  )
ORDER BY sp.modification_counter DESC, hours_since_update DESC;

The statistics update execution mirrors the index maintenance pattern: sorted by modification count descending (highest urgency first), executed within the same maintenance window budget, and logged to the same audit table so the controller can demonstrate ROI over time.

Autonomous Memory and Resource Governor Management

SQL Server's Resource Governor is one of the most powerful — and most underused — autonomous control surfaces in the engine. At steady state, most installations run with the default pool and a single workload group. The autonomous architecture treats Resource Governor as a dynamic pressure valve: when the sensor network detects memory pressure, CPU saturation, or blocking chains, the controller adjusts pool limits and workload group classifications in real time.

The feedback loop works as follows: the wait stats sensor detects sustained RESOURCE_SEMAPHORE waits (query memory grant queuing), which signals that the memory grant pool is exhausted. The controller inspects sys.dm_exec_query_memory_grants to identify which workload groups are consuming grants, and either caps the offending groups or redistributes the MAX_MEMORY_PERCENT between pools.

-- Memory grant pressure diagnostic for autonomous controller
SELECT
    mg.session_id,
    mg.request_id,
    mg.grant_time,
    mg.requested_memory_kb,
    mg.granted_memory_kb,
    mg.used_memory_kb,
    mg.max_used_memory_kb,
    mg.queue_id,
    mg.wait_order,
    mg.wait_time_ms,
    mg.is_next_candidate,
    wg.name                             AS workload_group,
    rp.name                             AS resource_pool,
    rp.max_memory_percent,
    wg.max_request_grant_memory_kb,
    es.login_name,
    es.program_name,
    SUBSTRING(qt.text, (er.statement_start_offset/2)+1,
        ((CASE er.statement_end_offset
            WHEN -1 THEN DATALENGTH(qt.text)
            ELSE er.statement_end_offset END
          - er.statement_start_offset)/2)+1) AS statement_text
FROM sys.dm_exec_query_memory_grants mg
JOIN sys.dm_exec_sessions            es ON mg.session_id = es.session_id
JOIN sys.dm_exec_requests            er ON mg.session_id = er.session_id
                                       AND mg.request_id = er.request_id
JOIN sys.dm_resource_governor_workload_groups wg
    ON mg.group_id = wg.group_id
JOIN sys.dm_resource_governor_resource_pools rp
    ON wg.pool_id = rp.pool_id
CROSS APPLY sys.dm_exec_sql_text(er.sql_handle) qt
ORDER BY mg.granted_memory_kb DESC;

When the autonomous controller identifies a resource pool absorbing disproportionate memory, it issues a live reconfiguration:

class AutonomousResourceGovernor:
    """
    Dynamically adjusts SQL Server Resource Governor pool limits
    in response to memory and CPU pressure signals.
    """

    def __init__(self, conn_str: str, dry_run: bool = False):
        self.conn_str = conn_str
        self.dry_run  = dry_run

    def _conn(self):
        return pyodbc.connect(self.conn_str, autocommit=True)

    def get_pool_memory_usage(self) -> list[dict]:
        sql = """
            SELECT
                rp.name                         AS pool_name,
                rp.max_memory_percent,
                rp.min_memory_percent,
                rp_stats.target_memory_kb,
                rp_stats.used_memory_kb,
                CAST(rp_stats.used_memory_kb AS FLOAT)
                    / NULLIF(rp_stats.target_memory_kb, 0) * 100
                                                AS utilization_pct
            FROM sys.dm_resource_governor_resource_pools rp
            JOIN sys.dm_resource_governor_resource_pools_history_ex rp_stats
                ON rp.pool_id = rp_stats.pool_id
        """
        try:
            with self._conn() as conn:
                cursor = conn.cursor()
                cursor.execute(sql)
                cols = [col[0] for col in cursor.description]
                return [dict(zip(cols, row)) for row in cursor.fetchall()]
        except Exception as e:
            logger.error("POOL_USAGE_FAILED error=%s", e)
            return []

    def reduce_pool_memory(self, pool_name: str, new_max_pct: int):
        """Reduce a pool's maximum memory allocation."""
        # Enforce a floor to prevent starving the pool entirely
        new_max_pct = max(new_max_pct, 10)
        sql = f"""
            ALTER RESOURCE POOL [{pool_name}]
            WITH (MAX_MEMORY_PERCENT = {new_max_pct});
            ALTER RESOURCE GOVERNOR RECONFIGURE;
        """
        logger.info(
            "POOL_MEMORY_REDUCE pool=%s new_max_pct=%d dry_run=%s",
            pool_name, new_max_pct, self.dry_run
        )
        if not self.dry_run:
            try:
                with self._conn() as conn:
                    for stmt in sql.split(';'):
                        stmt = stmt.strip()
                        if stmt:
                            conn.cursor().execute(stmt)
            except Exception as e:
                logger.error(
                    "POOL_MEMORY_REDUCE_FAILED pool=%s error=%s",
                    pool_name, e
                )

    def rebalance_under_pressure(self):
        """
        When total memory grant wait time is elevated, reduce the max memory
        of the highest-consuming non-default pool by 10 percentage points,
        rechecking after two collection cycles before further reduction.
        """
        pools = self.get_pool_memory_usage()
        # Exclude the internal and default pools from adjustment
        adjustable = [
            p for p in pools
            if p['pool_name'] not in ('internal', 'default')
            and p['utilization_pct'] is not None
        ]
        if not adjustable:
            return

        # Target the pool with highest utilization above 85%
        offender = max(adjustable, key=lambda p: p['utilization_pct'])
        if offender['utilization_pct'] > 85:
            current_max = offender['max_memory_percent']
            self.reduce_pool_memory(
                offender['pool_name'],
                max(current_max - 10, 10)
            )

The reversion path is equally important: once RESOURCE_SEMAPHORE waits return to baseline, the controller incrementally restores pool limits toward their configured maximums. All changes are recorded in the dba.resource_governor_changes audit table with the triggering signal, the before/after configuration, and the timestamp of both the change and any reversion, creating an evidence trail that demonstrates the system's decision-making over time.

Azure SQL and the Cloud Autonomy Layer

When SQL Server workloads run on Azure SQL Database or Azure SQL Managed Instance, the autonomy surface shifts. The platform handles storage scaling, OS patching, and basic HA invisibly. The ADE's responsibility moves up the stack: tier selection, DTU/vCore right-sizing, elastic pool management, and integration with Azure's native intelligence features like automatic tuning and Query Performance Insight.

Azure SQL's automatic tuning can create, drop, and force indexes and plans without human intervention. The ADE layer does not replace this — it supervises it. The supervision pattern uses the Azure SQL REST API and the sys.dm_db_tuning_recommendations view in concert:

import requests
from datetime import datetime, timedelta
import pyodbc

class AzureSQLAutonomyLayer:
    """
    Supervises Azure SQL automatic tuning actions and escalates
    those that cross defined impact thresholds to a human review queue.
    """

    # Tuning actions with impact scores above this are reviewed before applying
    HUMAN_REVIEW_SCORE_THRESHOLD = 80
    # Automatically approve low-impact tuning recommendations
    AUTO_APPROVE_SCORE_MAX       = 40

    def __init__(self, conn_str: str,
                 subscription_id: str,
                 resource_group: str,
                 server_name: str,
                 database_name: str,
                 bearer_token: str):
        self.conn_str       = conn_str
        self.base_url = (
            f"https://management.azure.com/subscriptions/{subscription_id}"
            f"/resourceGroups/{resource_group}"
            f"/providers/Microsoft.Sql/servers/{server_name}"
            f"/databases/{database_name}"
        )
        self.headers = {
            "Authorization": f"Bearer {bearer_token}",
            "Content-Type":  "application/json"
        }

    def get_automatic_tuning_state(self) -> dict:
        url = f"{self.base_url}/automaticTuning?api-version=2021-11-01"
        response = requests.get(url, headers=self.headers, timeout=15)
        response.raise_for_status()
        return response.json()

    def set_tuning_option(self, option: str, desired_state: str):
        """
        option: 'createIndex' | 'dropIndex' | 'forceLastGoodPlan'
        desired_state: 'Auto' | 'Disabled' | 'Manual'
        """
        url  = f"{self.base_url}/automaticTuning?api-version=2021-11-01"
        body = {
            "properties": {
                "desiredState": "Custom",
                "options": {
                    option: {"desiredState": desired_state}
                }
            }
        }
        response = requests.patch(url, json=body,
                                  headers=self.headers, timeout=15)
        response.raise_for_status()
        logger.info(
            "AZURE_TUNING_SET option=%s state=%s", option, desired_state
        )

    def review_recommendations(self):
        """
        Pull tuning recommendations and route each by impact score:
        - Low impact (< AUTO_APPROVE_SCORE_MAX): approve automatically
        - High impact (> HUMAN_REVIEW_SCORE_THRESHOLD): queue for human review
        - Mid range: apply with enhanced monitoring for 24 hours
        """
        sql = """
            SELECT
                name, type, reason, score,
                JSON_VALUE(details, '$.implementationDetails.script')
                    AS action_script,
                valid_since, last_refresh
            FROM sys.dm_db_tuning_recommendations
            WHERE state = JSON_VALUE(state, '$.currentValue')
              AND score IS NOT NULL
            ORDER BY score DESC
        """
        with pyodbc.connect(self.conn_str) as conn:
            cursor = conn.cursor()
            cursor.execute(sql)
            rows = cursor.fetchall()

        for row in rows:
            score = row.score or 0
            if score > self.HUMAN_REVIEW_SCORE_THRESHOLD:
                logger.warning(
                    "TUNING_HUMAN_REVIEW name=%s type=%s score=%d",
                    row.name, row.type, score
                )
                # Post to ticketing system / Slack escalation channel
                self._escalate_to_human(row)
            elif score <= self.AUTO_APPROVE_SCORE_MAX:
                logger.info(
                    "TUNING_AUTO_APPROVE name=%s type=%s score=%d",
                    row.name, row.type, score
                )
                # Low-risk: the platform will apply; just log the acknowledgment
            else:
                logger.info(
                    "TUNING_MONITORED_APPLY name=%s type=%s score=%d "
                    "— enhanced monitoring window started",
                    row.name, row.type, score
                )

    def _escalate_to_human(self, recommendation):
        # Implementation depends on organization's ticketing / alerting stack
        logger.critical(
            "ESCALATE name=%s script=%s",
            recommendation.name,
            recommendation.action_script
        )

The elastic pool right-sizing loop addresses a common Azure SQL anti-pattern: workloads are placed in an elastic pool sized for peak capacity, but individual databases rarely peak simultaneously. The autonomous tier manager monitors per-database DTU/vCore consumption against pool capacity on a rolling hourly basis and emits resize recommendations when sustained under- or over-utilization is detected:

def evaluate_elastic_pool_sizing(
        pool_stats: list[dict],
        pool_max_edtus: int,
        observation_hours: int = 24
) -> str:
    """
    Given per-database eDTU consumption over the observation window,
    return a sizing recommendation: 'DOWNSIZE', 'UPSIZE', or 'OPTIMAL'.
    """
    import numpy as np

    total_consumed = [row['total_edtu'] for row in pool_stats]
    p95_consumed   = np.percentile(total_consumed, 95)
    p50_consumed   = np.percentile(total_consumed, 50)

    utilization_p95 = p95_consumed / pool_max_edtus

    if utilization_p95 > 0.85:
        return 'UPSIZE'
    if utilization_p95 < 0.30 and p50_consumed / pool_max_edtus < 0.20:
        return 'DOWNSIZE'
    return 'OPTIMAL'

The cloud autonomy layer also manages geo-redundancy configuration: when disaster recovery RPO requirements tighten (detectable through application-layer SLA contract metadata stored in a configuration database), the controller enables active geo-replication or adjusts the failover group policy through the ARM API rather than waiting for a manual change request to work through an operations queue.

Integrating SQL Server Autonomy Into a Unified Control Plane

The subparts above describe individual autonomous subsystems — wait stats collection, Query Store governance, AG management, index maintenance, Resource Governor tuning, and Azure SQL supervision. In production, these must compose into a single control plane rather than operating as independent scripts that might issue conflicting actions.

The unified SQL Server autonomy controller implements a priority hierarchy and mutual exclusion between action types:

from enum import IntEnum
import threading
import logging
from datetime import datetime, timedelta
from typing import Callable, Optional

logger = logging.getLogger('autonomy_controller')

class ActionPriority(IntEnum):
    CRITICAL   = 1   # Failover, primary-unreachable response
    HIGH       = 2   # Plan regression force, memory pressure relief
    MEDIUM     = 3   # Index rebuild, stats update, replica mode change
    LOW        = 4   # Elastic pool resize recommendation, audit logging

class AutonomyAction:
    def __init__(self, name: str, priority: ActionPriority,
                 fn: Callable, cooldown_minutes: int = 10):
        self.name             = name
        self.priority         = priority
        self.fn               = fn
        self.cooldown_minutes = cooldown_minutes
        self._last_executed: Optional[datetime] = None
        self._lock            = threading.Lock()

    def is_cooled_down(self) -> bool:
        if self._last_executed is None:
            return True
        return (datetime.utcnow() - self._last_executed
                > timedelta(minutes=self.cooldown_minutes))

    def execute(self):
        with self._lock:
            if not self.is_cooled_down():
                logger.debug(
                    "ACTION_SUPPRESSED name=%s (cooldown active)", self.name
                )
                return
            try:
                logger.info("ACTION_START name=%s priority=%s",
                            self.name, self.priority.name)
                self.fn()
                self._last_executed = datetime.utcnow()
                logger.info("ACTION_COMPLETE name=%s", self.name)
            except Exception as e:
                logger.error("ACTION_FAILED name=%s error=%s", self.name, e)


class SQLServerAutonomyController:
    """
    Unified control plane that composes all SQL Server autonomous subsystems
    and enforces priority ordering and mutual exclusion between action types.
    """

    def __init__(self):
        self._actions: list[AutonomyAction] = []
        self._critical_lock = threading.Lock()
        self._maintenance_active = False

    def register(self, action: AutonomyAction):
        self._actions.append(action)
        # Keep sorted by priority so highest-priority actions run first
        self._actions.sort(key=lambda a: a.priority)

    def run_evaluation_cycle(self, triggered_action_names: list[str]):
        """
        Run a single evaluation cycle for the named actions.
        CRITICAL actions acquire the critical lock, blocking all others
        until the critical action completes.
        """
        to_run = [
            a for a in self._actions
            if a.name in triggered_action_names
        ]

        critical = [a for a in to_run if a.priority == ActionPriority.CRITICAL]
        non_critical = [a for a in to_run if a.priority != ActionPriority.CRITICAL]

        if critical:
            with self._critical_lock:
                for action in critical:
                    action.execute()
            # After a critical action, suppress non-critical for safety
            logger.info(
                "POST_CRITICAL_SUPPRESS suppressed=%d actions",
                len(non_critical)
            )
            return

        # Non-critical actions run sequentially in priority order
        # Skip maintenance-class actions if a maintenance window is not active
        for action in non_critical:
            if action.priority == ActionPriority.MEDIUM:
                if not self._maintenance_active:
                    logger.debug(
                        "ACTION_DEFERRED name=%s (outside maintenance window)",
                        action.name
                    )
                    continue
            action.execute()

    def set_maintenance_window(self, active: bool):
        self._maintenance_active = active
        logger.info("MAINTENANCE_WINDOW active=%s", active)

The evaluation cycle is driven by the sensor network. Each sensor posts named events to an internal queue when it detects a threshold crossing; the controller dequeues these events and maps them to registered action names. This event-driven architecture means the controller does not run a fixed-interval polling loop for every subsystem — actions are triggered by signals, not by clocks, which reduces unnecessary load and makes the decision chain auditable: every action execution has a traceable triggering event in the log.

The final integration step is the audit and observability layer. Every action execution — whether it forces a Query Store plan, adjusts a Resource Governor pool, or initiates an AG failover — writes a structured record to the dba.autonomy_audit table:

-- SQL Server: autonomy audit table
CREATE TABLE dba.autonomy_audit (
    audit_id          BIGINT IDENTITY PRIMARY KEY,
    action_name       NVARCHAR(100)   NOT NULL,
    priority          NVARCHAR(20)    NOT NULL,
    triggering_signal NVARCHAR(500)   NOT NULL,
    action_sql        NVARCHAR(MAX),
    outcome           NVARCHAR(20)    NOT NULL,  -- 'SUCCESS' | 'FAILED' | 'SUPPRESSED'
    error_detail      NVARCHAR(MAX),
    dry_run           BIT             NOT NULL DEFAULT 0,
    executed_at       DATETIME2       NOT NULL DEFAULT SYSUTCDATETIME(),
    duration_ms       INT,
    rolled_back_at    DATETIME2,
    rollback_reason   NVARCHAR(500)
);

CREATE INDEX ix_autonomy_audit_executed_at
    ON dba.autonomy_audit (executed_at DESC)
    INCLUDE (action_name, outcome);

This audit table serves multiple purposes beyond debugging. It is the evidence layer for change management processes that require documentation of every database configuration change. It is the training data for future ML-based decision models that replace threshold-based rules with learned behavior. And it is the rollback reference: when a forced plan or Resource Governor adjustment needs to be reverted, the audit record contains the exact SQL to reverse it.

Key Takeaways

  • → DMVs are sensors, not reports. The autonomous SQL Server architecture treats Dynamic Management Views as a real-time sensor network, collecting differential deltas at sub-minute intervals and feeding them into time-series baselines rather than instantaneous thresholds. Workload-aware, hour-of-week percentile baselines replace static alert limits and dramatically reduce false-positive–driven action storms.
  • → Query Store closes the plan governance loop. Autonomous plan regression detection, validation, and forcing transforms Query Store from a passive diagnostic tool into an active decision surface. The bidirectional design — forcing regressions and unforcing stale forced plans — is what separates genuine autonomy from one-directional manual interventions accumulated over time.
  • → Always On automation requires application-layer arbitration above the cluster. WSFC and Pacemaker handle quorum-level failover, but the ADE layer adds replica lag scoring, proactive synchronous-to-asynchronous mode transitions under redo queue pressure, and intelligent failover target selection — actions the cluster layer cannot make without workload context.
  • → Index and statistics maintenance become condition-driven, not schedule-driven. Replacing fixed maintenance windows with continuous fragmentation and modification-counter assessment, executed within time-budgeted windows that yield gracefully before closing, ensures maintenance work is proportional to actual need rather than calendar position.
  • → A unified control plane with priority ordering and mutual exclusion is non-negotiable. Individual autonomous subsystems operating without coordination can issue conflicting actions — a Resource Governor change during an AG failover, or an index rebuild during peak memory pressure. The SQLServerAutonomyController enforces a strict priority hierarchy, suppresses non-critical actions in the wake of critical events, and writes every decision to an audit table that serves as both the change management record and the training corpus for future decision model improvements.
